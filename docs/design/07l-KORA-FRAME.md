## 0. Решения поверх брифа (записаны до проектирования)

| Вопрос | Решение | Почему |
| --- | --- | --- |
| Пульт: общая рамка с центром или отдельная карточка с зазором | **Стык без зазора** — единый контур центральной колонки, Пульт отделён только швом-хендлом (§2) | Плавающая карточка — то самое «неестественно, не вписывается»; паттерн-образец владельца (VS Code) садит панели заподлицо |
| Чем блоки отличаются, если нет плавающих карточек | Стратой фона (центр = base, панели = well) и честными caps-заголовками («ХОСТЫ И АГЕНТЫ», «ПУЛЬТ · ДАЙДЖЕСТ») | «Своими блоками» = своя вывеска и своя страта, не своя геометрия |
| Правая панель: два скролла (Блок 1 / Блок 2) или один | **Один скролл панели**, заголовок «СЕССИИ · контекст» — sticky | Меньше вложенных скроллов — прямой ответ на «не хватает прокруток»; контекст, который теряется при скролле, — один (Блок 2), его и липлим |
| Заголовок «ХОСТЫ И АГЕНТЫ» — sticky? | Нет, скроллится | Это вывеска, а не контекст; липнуть ей незачем — плодим стыки sticky |
| Крошки + заголовок + сводка | **Одна строка 40px**: крошки «Агенты /» + H1 «Кора · сессии хостов» + сводка-числа + [Фильтр] + [Проверить связь] (§1.3) | Освобождает вертикаль ради цели «рабочая область ≥70vh»; крошки канонически не переносятся (`03` §5) — строка одна |
| Высота Пульта по умолчанию | **Авто по контенту** (пол 160, потолок 280px), drag переводит в фиксированную 160–420 с персистом; сброс возвращает авто (§3.2) | Директива «высота по контенту» и ресайз не противоречат, если персист — только про явное решение пользователя |
| Отдельный status bar внизу, как в VS Code | **Не вводим** | Статус уже живёт в топбаре (live-пилюля) и сводке; второй статус-бар — IDE-клише и дубль канала (анти-клише, §10) |
| Новые хоткеи Коры (v7) | Не добавляем; эксперт-прогон собирает «чего не хватает» (§6.3) | Одиночные символьные хоткеи тянут за собой обязанности 2.1.4; решаем по данным прогона, не по вкусу |
| Анимация ресайза | **Никакой анимации размеров** — drag мгновенный, transition off на время drag | Упрощение из брифа; перелив контента при перетаскивании — главный раздражитель IDE-ресайза |

### 1.2 Геометрия и запрет прокрутки страницы

- `kora.html`: `html, body { height: 100%; overflow: hidden }` — **прокрутка
  страницы на Корее запрещена**. Любой контент, которому тесно, скроллится
  внутри своего блока (`overflow-y: auto`): свиток, правая панель, вкладка
  Пульта. Ни один блок не растягивает страницу.
- Сетка каркаса: строки `48px (топбар) · 40px (шапка) · 1fr (работа)`;
  в строке «работа» — колонки `1fr (центральная колонка) · var(--kora-right-w)`
  (правая панель, дефолт 320px). Правая панель занимает обе подстроки
  (рабочая зона + Пульт) — Пульт по ширине равен **центральной колонке**,
  а не всей странице (§2).
- Рабочая зона внутри центральной колонки — `1fr`, Пульт — `auto` (своя
  высота, §3.2).
- Поверхности: центральная колонка `--color-bg-base`; правая панель и Пульт
  `--color-bg-well`; швы — `--myelin-hairline` в покое, `--myelin-strong`
  у активного хендла. Внешних радиусов и теней у блоков **нет** — каркас
  заподлицо (тени остаются только у дровера, палитры, тостов).

### 1.3 Шапка 40px: крошки + H1 + сводка

Одна строка, слева направо: крошки «Агенты /» (`--text-sm`, muted, «Агенты» —
ссылка) → **H1 «Кора · сессии хостов»** (`--text-body`, semibold,
`tabindex="-1"` — цель фокуса при переходе, канон `03` §8) → сводка-числа
(linkbtn, mono `--text-data`, из фикстур — правило `07j` §2.2) → spacer →
[Фильтр: ▾ Все хосты] (`05` §2.5 + dropdown) → [Проверить связь] (ghost).

- Сводка деградирует без переноса строки (строка едина, крошки не переносятся —
  `03` §5): <1200px прячется «за 24 ч», <1100px — «молчит», <1000px — «на
  связи»; «N сессии идёт» живёт всегда; спрятанные числа — в tooltip сводки.
  Порядок сокрытия — вопрос №2 (§11).
- Пояснение «Кора — журнал сессий всех хостов…» при первом показе сохраняется
  (`07a` §5) — переезжает в tooltip H1 (строка-подсказка не влезает в 40px).

### 1.4 Бюджет вертикали (цель «рабочая область ≥70vh»)

| Состояние | Шапка+топбар | Пульт | Рабочая зона (вьюпорт 900px) |
| --- | --- | --- | --- |
| Пульт свёрнут | 88px | 40px | 772px ≈ **86vh** |
| Пульт авто (контент ≤280px) | 88px | ≤280px | ≥532px ≈ ≥59vh |
| Пульт фиксированный 240px | 88px | 240px | 572px ≈ 64vh |

Гарантия ≥70vh даётся свёрнутым и полуразвёрнутым Пультом на вьюпортах ≥800px
высотой; развёрнутый до 240–420px Пульт — осознанная жертва пользователя,
возвращаемая сворачиванием/сбросом. Компактная шапка 40px — плата за каркас,
введена этим срезом (против двух строк в `07j`).

### 1.5 Деградация каркаса (рефлоу и зум)

- <1024px: правая панель → дровер поверх (кнопка «Хосты и сессии» в шапке,
  канон `07j` §8); хендл ширины не рендерится.
- <768px: Пульт → bottom sheet (кнопки ≥44px), дерево — карточный вид; каркас
  и на мобильном без прокрутки страницы — центр скроллится.
- `max-height: 560px` (малый вьюпорт / системный зум): Пульт принудительно
  свёрнут при входе, персист-высота применяется после возврата высоты.
- Критерий 1.4.10 Reflow: при 320px CSS-ширины (зум 400%) страница не даёт
  двумерной прокрутки — работают те же дрогеры/bottom sheet. `overflow:
  hidden` не должен срезать контент ни на одном брейкпоинте — проверка
  обязательна на прогоне эксперта (§6.3).

## 2. Пульт-стык: «размером с центральный блок, единый интерфейс»

- **Ширина** — центральная колонка целиком (grid col 1); правая панель рядом,
  не над Пультом.
- **Стык без зазора**: рабочая зона и Пульт — один контур; разделение —
  шов-хендл высоты Пульта (§3.3) и смена страты (base → well). Никаких
  `--radius-lg`/`--shadow-float` у Пульта (supersede `07j` §4.1): плавающая
  карточка и была «неестественностью».
- **Своими блоками**: Пульт сохраняет собственный caps-заголовок в той же
  стилистике, что панели: «ПУЛЬТ · <вкладка>» (11px caps + tracking).
  Слева от вкладок — caps-лейбл, справа — бейдж «ждут владельца: N» и кнопка
  сворачивания (07j §4.2 — логика вкладок и умный дефолт без изменений).
- **Свёрнутый Пульт — полоса 40px** (supersede 48px из `07j` §4.1): caps
  «ПУЛЬТ», вкладки [Дайджест | Эфир] остаются на полосе, бейдж остаётся,
  кнопка «Развернуть». Полоса — тот же шов: hover по верхней кромке даёт
  row-resize.
- Фон полосы и развёрнутого Пульта — `--color-bg-well`; hover-тинт полосы —
  `--myelin-hairline` (канон тинтов).

## 3. Ресайз панелей

### 3.1 Хендлы (общая анатомия)

| Хендл | Где | Управляет | Диапазон | Дефолт | Персист |
| --- | --- | --- | --- | --- | --- |
| Правой панели | левый край панели, на всю высоту | ширина | 240–420px | 320px | `vesmaro.koraRightW` (px, число) |
| Пульта | верхняя кромка Пульта/полосы, на ширину колонки | высота | 160–420px фиксированный; авто-режим 160–280px | авто по контенту | `vesmaro.koraPultH` (px) или ключа нет = авто |

Анатомия: визуальная линия 1px (`--myelin-hairline`; hover/focus/drag —
`--myelin-strong` + уширение до 4px через псевдоэлемент, без сдвига контента);
**зона попадания ≥24px** поперёк шва (WCAG 2.5.8), прозрачная. Курсоры:
`col-resize` (панель), `row-resize` (Пульт). Tooltip: «Потяните, чтобы
изменить ширину» / «…высоту. Двойной клик — вернуть как было».

### 3.2 Механика

- Drag: pointer capture; во время drag `transition: none` на ширину/высоту
  обеих панелей и содержимого — **анимации размеров нет вовсе** (§0);
  `user-select: none` на каркасе, контент панелей не переливается (текст —
  ellipsis, свиток держит ≤72ch).
- Двойной клик по хендлу — сброс: панель → 320px; Пульт → авто-режим
  (ключ `vesmaro.koraPultH` удаляется).
- Персист — на завершение drag (`pointerup` / `keyup`), не на каждый кадр.
- Значения вне диапазона (руками в storage) — clamp до диапазона при чтении,
  мусор → дефолт (§5.2, безопасные геттеры).
- Drag Пульта ниже 120px — прилипание в «свёрнут» (гистерезис: разворот из
  «свёрнут» — drag вниз от полосы или кнопка, высота = последняя сохранённая,
  иначе авто).

### 3.3 Клавиатурный путь (WCAG 2.1.1)

Хендл — `role="separator"`, `tabindex="0"`, `aria-orientation` («vertical» —
панель, «horizontal» — Пульт), `aria-valuemin/max/now` (px),
`aria-valuetext` («336 пикселей» / «высота 240 пикселей» / «авто, 264
пикселя»). Клавиши: ←/→ (панель) или ↑/↓ (Пульт) — ±16px; Home — дефолт;
End — максимум. Изменение объявляется самим значением separator'а; после
завершения серии (blur) — polite-объявление не требуется (значение уже у
роли). Бриф называл 2.1.4 — корректное имя критерия клавиатурной
управляемости **2.1.1 Keyboard**; 2.1.4 Character Key Shortcuts соблюдён
автоматически: одиночных символьных хоткеев у хендлов нет, стрелки — не
символьные.

### 3.4 State-матрица хендлов

| Компонент | Матрица |
| --- | --- |
| Хендл (оба) | default (hairline + курсор-подсказка) / hover (myelin-strong, 4px, tooltip) / focus-visible (ринг `--color-focus` 2px/2px по контуру зоны) / active-drag (myelin-strong, transition off, pointer capture, user-select none) / disabled — не бывает; на <1024px хендл панели не рендерится (дровер) / reduced-motion — без изменений (анимаций нет) |
| Правая панель при ресайзе | 240 (мин) / 320 (дефолт) / 420 (макс) / дерево и списки — ellipsis без переноса / свиток центра держит 72ch / дровер-режим (<1024px) — хендла нет |
| Пульт | auto (по контенту, 160–280) / fixed N (160–420) / свёрнут (полоса 40px) / drag-разворот из полосы / drag-сворачивание (<120px → прилипание) / max-height:560px — свёрнут принудительно / Пульт скрыт (нет вьюпорта) — не бывает |
| Сброс | double-click по хендлу / Home с клавиатуры → дефолт (панель) или авто (Пульт); после сброса фокус остаётся на хендле |

## 4. Внутренние скроллы

| Блок | Что закреплено | Что скроллится |
| --- | --- | --- |
| Центр | заголовок сессии + пилюля состояния + тулбар («Следить за хвостом», поиск) | свиток (канон `07j` §3: Lora, ≤72ch, догрузка снизу) |
| Правая панель | sticky-заголовок «СЕССИИ · <контекст>» | единый поток: Блок 1 (дерево) → Блок 2 (сессии, «О сессии») → «Что мы видим с ваших машин» |
| Пульт | шапка вкладок (caps + вкладки + бейдж + сворачивание) | контент активной вкладки |

- **Правая панель — один скролл** (§0): меньше вложенных скроллов, дереву и
  списку хватает одной колонки; sticky-заголовок Блока 2 держит контекст
  («zcode на laptop-go-1») при прокрутке — recognition over recall.
  Фон sticky-заголовка = `--color-bg-well` + нижняя hairline, чтобы под ним
  не просвечивал список.
- `scroll-padding-top` на скролл-контейнере = высота sticky-заголовка:
  Tab-фокус на строке под липучкой не прячется (2.4.11).
- **Скроллбар по токенам, видимый всегда** (прямой запрос владельца): ширина
  8px, радиус full; track — `--color-bg-well`; thumb — `--color-border`
  (3.2:1 на well — видно в покое), hover/drag thumb — `--color-text-secondary`;
  `scrollbar-width: thin` + `-webkit-scrollbar` одним видом на всех скролл-
  блоках Коры. Свиток центра сохраняет «пергамент» `--color-scroll-bg` с тем
  же thumb-правилом.
- Регионы: центр — `region aria-label="Ход сессии"` (07j), правая панель —
  `region aria-label="Хосты и сессии"` (единый скролл — один регион; внутри
  сохраняются `nav aria-label="Хосты и агенты"` и `role="list"` Блока 2),
  Пульт — `region aria-label="Пульт"`.

## 5. Диагностика P0: «раздел Кора пропадает»

### 5.1 Гипотеза (от ТЛ, включена как есть)

В localStorage владельца остались ключи **старых срезов** — `vesmaro.koraDock`
(v4), `vesmaro.koraTree` в структуре v4 (`{open:[...]}`), `vesmaro.koraPanel`
со значениями вне `{digest, ether}`. Init Коры на них падает молча (TypeError
где-то в цепочке рендера) — страница остаётся с пустым центром; переход на
«Агенты → Исполнение» и обратно реинициализирует страницу, отсюда «появляется,
когда нажимаю на другой раздел». Симптомы согласуются: падение тихое, рендер
обрывается частично, повторный вход пересобирает DOM.

### 5.2 Контракт хранилища и миграция (требование а)

- Новый ключ **`vesmaro.storageVersion`** (целое; текущее значение **2**:
  схема v7-каркаса с ресайзом; 1 = срезы v4–v6 — ключ никогда не писался).
- Пространство миграции — **только ключи `vesmaro.kora*`** (включая
  `vesmaro.koraDock`, `koraTree`, `koraPanel`, `koraAbout`, `koraPultHint`,
  `koraRightW`, `koraPultH`). Ключи прочих доменов (`vesmaro.authSession`,
  сайдбар, тема) **не трогаются никогда**.
- Правило миграции — **сброс, не конвертация**: настройки вида дёшево
  пересоздаются, код конвертации трёх мёртвых схем — источник новых багов.

| Состояние хранилища при init | Действие |
| --- | --- |
| версии нет, ключей `vesmaro.kora*` нет (свежий пользователь) | записать `storageVersion = 2`; **без тоста** |
| версии нет, есть любой `vesmaro.kora*` (наследие v4–v6) | удалить все `vesmaro.kora*`, записать версию, **тост «Настройки вида Коры обновлены»** |
| версия < 2 (на будущее) | тот же сброс `vesmaro.kora*` + тост |
| версия = 2 | читаем как есть; безопасные геттеры: мусор/чужой тип/вне диапазона → clamp или дефолт, никогда не throw |
| storage недоступен (file://, приватный режим) | работаем без персиста — уже так у `store` в `kora.html`; init не зависит от успеха записи |

- Тост — канон `05` §3 (4s, hover-пауза): «Настройки вида Коры обновлены».
  Тост объявляется polite через `#kora-live` (07j §6.1).

### 5.3 Защищённый init (требование б)

- Init Коры разбит на фазы: (1) миграция/чтение состояния → (2) сборка DOM →
  (3) проводка событий → (4) запуск таймеров/лент. Каждая фаза — в try/catch;
  **пустых catch запрещено**: catch → либо восстановление (дефолт), либо
  честный экран ошибки, либо `console.warn` с деталью (стенд-диагностика).
- Падение любой фазы init → **не пустота**, а экран ошибки в слоте рабочей
  зоны (топбар и шапка остаются):

```
│ ⚠ Не удалось отрисовать журнал                                (H2, фокус)  │
│ Похоже, повреждены сохранённые настройки вида. Перезагрузка обычно         │
│ помогает.                                                                   │
│ [ Перезагрузить страницу ]   [ Сбросить вид ]                               │
│ Пока журнал недоступен: статистика — на Обзоре →                            │
```

- «Сбросить вид» — удаляет все `vesmaro.kora*` и перезагружает страницу
  (confirm не нужен: обратимо, настройки вида пересоздаются).
- «Перезагрузить страницу» — `location.reload()`. «на Обзоре →» — ссылка:
  ошибка не тупик (канон пустых состояний, `07a` §1.2).
- Ошибка объявляется через `role="alert"`, фокус — на H2 экрана.
- Ошибки **внутри таймеров/лент** (после успешного init) страницу не валят:
  catch → пометка stale «данные на HH:MM» в соответствующем блоке + console.
- Критерий успеха: «пустой центр» как исход невозможен — любое падение
  заканчивается экраном с действием.

### 5.4 Seed-страница и чек-лист воспроизведения (требование в)

Новая стенд-страница **`design/stand/kora-seed.html`** (служебная, вне
сайдбара, URL-only; шапка с caps «ДЕМО-СТЕНД», как `07j` §13). Кнопки пишут
схему в localStorage и редиректят на `kora.html`:

| # | Кнопка на seed-странице | Что пишет | Ожидаемый исход на Корее |
| --- | --- | --- | --- |
| 1 | «Наследие v4: полный набор» | `koraDock = {"collapsed":false,"tab":"transcript"}`, `koraTree = {"open":["h-lgo","h-vpn"]}`, `koraPanel = "transcript"`, версия не пишется | тост «Настройки вида Коры обновлены»; Кора рендерится с дефолтами; в storage — версия 2, старых ключей нет |
| 2 | «Битый JSON дерева» | `koraTree = "{\"open\":["` (обрыв) | init не падает: безопасный парс → дефолт + тост миграции (или экран ошибки с рабочим «Сбросить вид» — пустоты нет) |
| 3 | «Мусорные типы» | `koraPanel = 17`, `koraRightW = "abc"`, `koraPultH = null` (без версии) | сброс ключей + тост; после — clamp/дефолты, рендер нормальный |
| 4 | «Чистый вход» | всё стереть | без тоста, версия 2 записана — контроль, что миграция не срабатывает на свежих |
| 5 | «Хранилище недоступно» (инструктаж) | вручную: приватный режим/file:// | Кора рендерится без персиста, без ошибок |

Чек-лист приёмки P0 (прогонять на каждом сценарии): (а) центр не пуст;
(б) тост миграции показан ровно один раз и не возвращается при следующем
входе; (в) после сценария 1–3 ключи `vesmaro.koraDock`/старая схема не
возвращаются; (г) «Сбросить вид» на экране ошибки чистит только `vesmaro.kora*`
(`vesmaro.authSession` выживает — вход не слетает); (д) переход «Агенты →
Исполнение → Кора» больше не меняет состояние Коры (симптом владельца).

## 6. План эксперт-прогонов (§план): три персоны

Все прогоны — на каркасе v7 после реализации; протокол: задача → наблюдения →
сигналы провала. «Прочие недочёты пусть поищут пользователи» — фиксировано:
прогон не ограничивается чек-листом, наблюдатель собирает свободные замечания.

### 6.1 Новичок (повторно)

- Легенда: видит Кору второй раз; первый раз — срез v6 (прокручиваемая
  страница).
- Journey: сайдбар → Кора → «где что лежит» (30 секунд на опознание каркаса) →
  открыть сессию из дерева → прочитать ход → найти разбор в Пульте → вернуться
  к списку.
- Наблюдения: опознаёт ли строку 40px (крошки+сводка) как шапку; находит ли
  сессию в едином скролле правой панели; понимает ли «ПУЛЬТ» без подсказки;
  пугает ли отсутствие прокрутки страницы.
- Провал: ищет прокрутку страницы >10 с; называет правую панель «рекламой»;
  открывает Пульт случайно.

### 6.2 Вернувшийся («заходил неделю назад — что изменилось»)

- Легенда: последний вход = срез v6 или раньше; в storage — наследие (сценарий
  seed #1).
- Journey: зайти на Кору → заметить тост «Настройки вида Коры обновлены» →
  понять, что случилось (5 секунд) → найти свою сессию заново → оценить
  каркас против памяти («раньше скроллилось»).
- Наблюдения: тост понятен и не тревожит; потеря старых настроек вида не
  воспринимается как поломка; отличает «вид сброшен» от «данные пропали».
- Провал: читает тост как ошибку; ищет «куда делись мои раскрытые ветки» >30 с.

### 6.3 Эксперт-оператор («держу 4 хоста, живу в Коре»)

- Легенда: скорость, плотность, хоткеи; эталон сравнения — VS Code/zcode.
- Journey: расширить правую панель до 420 и сузить до 240 (мышью и с
  клавиатуры) → Пульт до 420 и до 160 → свернуть/развернуть Пульт из полосы →
  сброс двойным кликом и Home → j/k по списку сессий, Enter, Esc-лестница →
  «Следить за хвостом» на живой сессии при узком центре → зум 200% и 400%
  (рефлоу, §1.5) → плотность compact → свободный блужд-тест «что бесит».
- Наблюдения: точность хендлов (не соскальзывает ли захват на контент);
  не мерцает ли sticky-заголовок; читается ли сводка при 240px панели;
  suffice ли стрелки ±16px (или нужен мелкий шаг); чего не хватает в хоткеях
  (собрать список — решение после данных, §0).
- Провал: хендл перехватывает выделение текста; ресайз дёргает свиток;
  фокус теряется после drag; на зуме появляется двумерная прокрутка.

## 7. A11y — именованные критерии (WCAG 2.2 AA)

- **2.1.1 Keyboard**: хендлы — полный клавиатурный путь (§3.3); Esc снимает
  drag (мышиный и клавиатурный).
- **2.1.4 Character Key Shortcuts**: одиночных символьных хоткеев хендлы не
  вводят; канон-хоткеи не меняются.
- **2.4.7 / 2.4.11 Focus Visible / Not Obscured**: ринг хендла по контуру
  24px-зоны; `scroll-padding-top` под sticky-заголовками; ринг не срезается
  швами (offset 4px у прижатых к краю целей — канон `03` §8).
- **2.5.8 Target Size**: зона хендлов ≥24px поперёк шва; кнопки полосы
  Пульта ≥24 (мобильный 44).
- **1.4.3 / 1.4.11 Contrast**: thumb скроллбара `--color-border` ≥3:1 на well;
  hover-хендл `--myelin-strong` — визуальный сигнал дублируется курсором и
  tooltip'ом (шов в покое — декоративный, его опознание не завязано только на
  контраст).
- **1.4.4 / 1.4.10 Resize Text / Reflow**: зум 200% — все скроллы внутренние
  работают; 400%/320px — деградация §1.5 без двумерной прокрутки.
- **1.4.1 Use of Color**: все состояния Коры остаются «точка + текст» (07j);
  хендлы различаются не только цветом — курсор, tooltip, ширина шва.
- **4.1.2 Name, Role, Value**: `separator` с orientation/min/max/now/valuetext;
  регионы скролла с `aria-label` (§4); `aria-expanded` полосы Пульта.
- **4.1.3 Status Messages**: тост миграции и экран ошибки — polite/alert через
  разметку до скриптов (`#kora-live`, 07j §6.1).
- Reduced-motion: ресайз и без анимаций; сворачивание Пульта кнопкой —
  240ms → мгновенно (06 §7); focus-ринги сохраняются.

## 8. Motion — изменения против 07j §6.2

| Что | Как |
| --- | --- |
| Drag ресайза (оба хендла) | **без анимации** — transition off, изменения мгновенны |
| Сворачивание/разворот Пульта кнопкой | 240ms `--duration-normal` + `--ease-enter`/`--ease-exit` (полоса 40px ↔ авто/фикс); reduced — мгновенно |

| Всё прочее | 07j §6.2 без изменений (дерево, смена сессии, Эфир, вкладки) |

## 10. Самокритика (проход 2)

- **Снял бренд: остаётся ли это VS Code-клоном?** Заимствован паттерн (100vh,
  заподлицо, внутренние скроллы, сепараторы-ресайзы), не кожа. Опознаваемые
  знаки своего: миелиновые швы (hairline → myelin-strong, «нерв» вместо
  серого сплиттера), честные caps-вывески блоков вместо таб-стрипсов, страты
  base/well, RU-словарь («Пульт», «Эфир», «Дайджест», «Хосты и агенты»),
  умный дефолт Пульта из 07j, сводка-производная фикстур. Чего сознательно
  нет: минимап, таб-стрип над каждой панелью, отдельного status bar, иконок
  activity bar, тёмно-серой «bash-палитры».
- **Риск «хендлы не найти»**: новичок может не увидеть швы. Принято: хендлы —
  инструмент эксперта; новичку они не нужны, а tooltip + курсор дают
  открытие при первом касании. Эксперт-прогон проверяет обратное (не мешают
  ли).
- **Риск «единый скролл правой панели» утопит дерево под длинным списком
  сессий**: sticky-контекст Блока 2 + то, что счётчики дерева свёрнуты по
  умолчанию (07j §11); при прогоне новичка смотрим именно это.
- **Риск авто-высоты Пульта**: «по контенту» может прыгать при смене сессии.
  Митигация: авто пересчитывается только при смене вкладки/сессии с
  фиксацией на время анимации смены; прыжки внутри вкладки гасятся её
  внутренним скроллом (потолок 280px).
- **P0 честность**: миграция-сброс не лечит сам TypeError — он остаётся
  возможным; лечит его защищённый init (§5.3) плюс устранение причины
  (несовместимые ключи больше не читаются). Оба слоя обязательны; сценарий
  seed #2 специально держит падение в порядке, чтобы экран ошибки был
  проверен, а не описан.
- **Токен-дисциплина**: новых токенов не ввожу — скроллбар, швы и страты
  собираются из существующих имён `02`; `--kora-right-w` — layout-переменная
  компонента (значение по умолчанию 320px), не дизайн-токен.

## 11. Открытые вопросы владельцу (≤2, с рекомендациями)

1. **«Сбросить вид» — что чистит?** Только `vesmaro.kora*` (мой дефолт в §5.2)
   или все настройки стенда? Рекомендация: только kora*-пространство — вход,
   тема и сайдбар не должны страдать от починки вида Коры.
2. **Порядок сокрытия сводки** при сужении (<1200 → <1100 → <1000, §1.3):
   прятать числа по порядку «за 24 ч → молчит → на связи», оставляя «N сессии
   идёт», или переносить сводку во вторую строку? Рекомендация: прятать по
   порядку — строка едина, канон «крошки не переносятся», полный ряд остаётся
   в tooltip.
