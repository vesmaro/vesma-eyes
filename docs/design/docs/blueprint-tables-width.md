## 1. Проблема и диагноз (проверено кодом)

Владелец: «таблицы нечитаемы (колонки сжаты в столбики по букве)». Механика
дефекта, три сомножителя:

1. `th/td` статьи несут `[overflow-wrap:anywhere]` — перенос разрешён в любом
   месте, включая середину слова и посимвольно.
2. `table.w-full` внутри статьи-меры `--measure-scroll: 72ch` (~730px):
   таблица не может стать шире меры, минимальная ширина колонок по контенту
   подавлена п.1.
3. Существующая обёртка `overflow-x-auto` мертва: таблица «умещается» в любую
   ширину, скролл никогда не включается.

Итог: длинные идентификаторы (ключи yaml, `vesmaro.*`, пути) рвутся в
букво-столбики; справочник mesh.yaml нечитаем. Расширение колонки БЕЗ п.1 не
чинит ничего — букво-столбики переедут на новую ширину.

Интент: TextEngine становится table-aware (таблица имеет минимальную ширину по
контенту; переполнение — честный горизонтальный скролл с аффордансом), мера
чтения доков умеренно расширяется до стандартной для 5-колоночных справочников.

## 2. Direction: «вынос за колонку» vs «шире везде» (сравнение и вердикт)

| Критерий | (A) Вынос широких таблиц за пределы колонки | (B) Шире колонка везде |
| --- | --- | --- |
| Чинит букво-столбики | нет сам по себе — всё равно нужны min-width и скролл | нет сам по себе — та же причина |
| Читаемость прозы | сохраняет 72ch | мера растёт до ~80ch — верхняя граница канона 60–85ch |
| Сетка страницы | рваный правый край: таблица шире текста, край «прыгает» | ровный край на всей статье |
| Сложность | JS-замер или CSS-хаки с отрицательными полями внутри scroll-контейнера; два горизонтальных скролла | один токен меры + один контейнер |
| 768–1024 (узко) | не спасает: выноситься некуда — скролл неизбежен | не спасает: скролл неизбежен |
| Регрессия | точечная (таблицы) | типографика всех страниц (код-блоки, цитаты, rail-баланс) |

ВЕРДИКТ: ни A, ни B в чистом виде. Ядро — table-aware TextEngine (нужно при
ЛЮБОМ выборе: без него букво-столбики не умирают), плюс умеренное расширение
меры 72ch → 80ch (--measure-docs, контейнер reading max-w-5xl → max-w-6xl,
1152px) — это вариант B в дозированной форме: справочники чаще помещаются в
меру без скролла, проза остаётся в читаемом коридоре. Полный B (мера = вся
колонка 5xl/operational) отклонён: ломает reading-канон 2026-10-21 и меру
чтения ради случая, который всё равно требует скролла. Полный A отклонён:
рваная сетка, два скролл-контекста, хрупкая вёрстка — издержки без выигрыша
против скролла внутри меры.

## 3. Table-aware TextEngine: правила рендера

Пять правил (контракт воркеру, тема статьи И компактная):

1. Заголовок не разрывается: `th` без overflow-wrap:anywhere,
   `white-space: nowrap` — минимальная ширина колонки = ширина заголовка.
   Букво-столбик заголовка становится невозможен по построению.
2. Ячейка переносит по словам, НЕ посимвольно: `td` без anywhere
   (`overflow-wrap: break-word`); потолок ячейки ~32ch — токены длиннее
   (супер-длинные пути) рвутся только там и только по необходимости.
3. Таблица набирает ширину по контенту (`min-width: max-content`, потолок —
   мера статьи): оживает существующая обёртка `overflow-x-auto`.
4. Переполнение честно: скролл обёртки с аффордансом (тень/градиент на правом
   краю при наличии остатка), обёртка фокусируема (`tabindex=0`,
   aria-label/role=region — скроллируемый регион доступен с клавиатуры).
5. Широкие справочники: первая колонка sticky (left:0, фон ячейки) — имя
   строки видно при горизонтальном скролле; sticky только когда таблица
   реально переполняется.

Ожидаемое поведение mesh.yaml-справочника: 1440/1280 — таблица в мере 80ch
без скролла или с коротким скроллом; 1024 — скролл с аффордансом, sticky
первая колонка; 768 — скролл, sticky, заголовки в одну строку.

Состояния: T-FIT (в мере, без скролла) · T-SCROLL (переполнение, аффорданс +
фокус) · T-STICKY (первая колонка приклеена) · T-CODE (инлайн-код в ячейках —
перенос по словам, без anywhere).

## 4. Поле контента: числа

- Токен: `--measure-docs: 80ch` (~800px) в tokens.css; статья доков читает его
  вместо 72ch. `--measure-scroll` не трогается (MemoryScroll и другие
  потребители не меняются).
- Контейнер: reading-режим pageGrid `max-w-5xl` → `max-w-6xl` (1152px) — на
  lg+ статья 80ch помещается рядом с rail 16rem+gap. Ниже контейнера — честная
  деградация: фактическая ширина = min(80ch, доступная ширина минус rail).
- Фактические ширины статьи: 1440 → 800px; 1280 → 800px; 1024 → ~736px
  (rail съедает); 768 → полная ширина центрального поля (rail скрыт <lg).

## 5. Волны и гейты

### W1 — table-aware TextEngine (M)
Правила §3 в обе темы theme.tsx; любое потребление TextEngine (задачи, память)
получает фикс бесплатно — регрессионный прогон их снапшотов обязателен.
Гейт (acceptance владельца, дословно): таблица справочника mesh.yaml читаема
на 1440/1280/1024/768; букво-столбиков нет НИГДЕ (прогон по всем докам:
ни один заголовок не разорван посимвольно — авто-тест на рендер).
Плюс: клавиатурный доступ к скролл-региону, sticky-колонка не перекрывает
контент, reduced-motion не задет (анимаций нет).

Вопросы владельцу (W1):
1. Sticky первая колонка для всех широких таблиц или только справочников?
   Рекомендую: для всех переполняющихся — правило без исключений дешевле.
2. Потолок ячейки 32ch устраивает? Рекомендую: да; длинные токены рвутся
   только в ячейках и только после 32ch.

### W2 — мера 80ch + контейнер 6xl (S)
Токен --measure-docs, reading → max-w-6xl, регрессия типографики.
Гейт: мера прозы на всех докс-страницах в коридоре 60–85ch на 1440/1280/1024;
код-блоки/цитаты/врезки не сломаны (снапшоты); H1 докс-разделов остаются на
общей оси pageGrid (замер на 1440 — канон pageGrid); rail-скролл-спай
работает с новой геометрией.

Вопрос владельцу (W2):
1. Подтверждаете пересмотр свежего reading-канона 2026-10-21 (max-w-5xl/72ch)
   до 6xl/80ch? Рекомендую: да — прод-дефект таблиц важнее трёхдневного
   канона, а 80ch остаётся читаемой мерой, не «операционной шириной».

## 6. Стыки и риски

- TextEngine общий: фикс затрагивает задачи/память/гейтвей-борды — их
  снапшоты переписываются той же волной, отдельной не оставлять.
- Риск: nowrap-заголовки при 6+ колонках на 768 дают длинный скролл — это
  честно (аффорданс + sticky), не дефект.
- Риск: смена контейнера reading двигает все докс-страницы — визуальный
  прогон всей секции, не только таблиц.
