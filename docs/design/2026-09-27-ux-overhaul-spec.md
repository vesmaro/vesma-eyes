### 1.2 Три системные проблемы (сжатие аудита)

- **СП-1 «Неполнота как тупик»**: 501/скоро/пусто рендерится полноэкранным EmptyState вместо одной строки с действием; мёртвые пункты — живые ссылки на 501.
- **СП-2 «Мета раньше данных»**: конфигурация (SSH-карточка) и объяснение (Кора-onboarding) стоят выше рабочего состояния; карточки не замыкаются на работу.
- **СП-3 «Словарь разработчика»**: срезы/флаги/сырые ошибки адаптера и pip-команды видны владельцу как первичный текст.

Эти три правки решают 8 из 10 фактов (остаются 3 и 8 — точечные).

## 2. Правила переработки (4 принципа, проверяемые на каждой поверхности)

- **П1 «Неполнота — строка, не экран»**. 501/скоро/пусто по умолчанию — одна
  строка с объяснением и (по возможности) действием, а не отдельный экран:
  новый примитив `HonestLine` (§7.1). Мёртвые разделы снимаются с навигации
  и превращаются в **disabled-слоты** по существующему паттерну `soonKey`
  (`navItems.ts:133` — «Хранилища» уже так живёт). Сырые `error.message`
  адаптера **никогда** не попадают в UI напрямую — только под раскрытие
  «Технические подробности» (расширение `EmptyState`, §7.2).
- **П2 «Данные раньше мета»**. Порядок блоков на любой поверхности:
  рабочее (списки, состояния, действия) → пояснение/конфигурация свёрнутым
  блоком ниже. Онбординг появляется как первый экран **только при реально
  пустом** домене.
- **П3 «Карточка замыкается на работу»**. Каждая карточка/строка домена Агенты
  отвечает «чем занят сейчас» из **существующих** данных
  (`GET /api/assignments?executor_id=` — open read, `BoardAdapter.ts:881`);
  пустой ответ тоже состояние («Свободен · задач нет»), а не отсутствие блока.
- **П4 «Язык владельца, не разработчика»**. Бан внутреннего словаря в проде:
  ни срезов, ни флагов развёртывания, ни pip-команд, ни HTTP-кодов. Термин
  допустим только если он имя сущности продукта (харнес, исполнитель — можно;
  «срез 3», «контракт-моки», `provisioner.passwordAuth` — нельзя).

## 3. Поверхность 1: Обзор — рабочий кокпит

### 3.1 Композиция первого экрана (порядок чтения = JTBD J1)

Колодец (breathing iris) **остаётся сигнатурой** — одно дыхание, ничего больше
не движется (действующий контракт). Ниже колодца — кокпит-блоки в порядке
«кто занят → что ждёт меня → что в памяти → строка честности»:

```
┌ TopBar ─────────────────────────────────────────────────────────┐
│ [овал «колодца»: поиск/⌘K]          …               ○ режим     │
└──────────────────────────────────────────────────────────────────┘
   (колодец: iris 120, tagline — сигнатура, без изменений)

  КТО ЗАНЯТ                                    Все агенты →
  ┌────────────────────────────────────────────────────────────┐
  │ ● 2 из 3 исполнителей на связи · 1 задача в работе ·       │
  │   2 в очереди            [Исполнение →] [Задачи →]         │
  └────────────────────────────────────────────────────────────┘

  ЧТО ЖДЁТ МЕНЯ
  ┌ Входящие: 3 задачи → ┐  ┌ В очереди: 2 запуска → ┐

  ЧТО В ПАМЯТИ
  ┌ mnemos · 53 записи · ОК ┐  ┌ kora · 2542 записи · … ┐
  Пульс (5 свежих)                                    весь пульс →

  Честность (строка HonestLine, рендерится только если есть что сказать)
  Хранилища-реестр появятся позже · Сессии и трассировки появятся позже
```

- **«Кто занят»** (Ф2, живые данные): строка агрегата из
  `GET /api/executors` (presence из meta) + `GET /api/assignments`
  (в работе/в очереди). Ноль исполнителей → блок не рендерится (анти-дашификация
  действующая), вместо него HonestLine «Агентов пока нет — подключите первого»
  с действием на `/agents/harnesses`.
- **«Что ждёт меня»** (Ф2): две плитки — Входящие (счётчик inbox уже есть в
  сайдбаре, `navItems.ts:91`) и очередь исполнений (queued assignments).
  Пустые плитки не рендерятся.
- **«Что в памяти»** (без изменений по данным): хранилища-карточки
  (`StoreCard`, живые) + пульс top-5, как сегодня — переносится ниже
  рабочих блоков.
- **Строка честности** (Ф1): одна строка HonestLine в подвале кокпита —
  перечисляет снятые с навигации домены («Хранилища появятся позже…»).
  Не рендерится, если всё живое.
- **Что убирается**: quick-links-тройка памяти (search/records/tags) —
  память живёт в блоке «Что в памяти» и в палитре; agents-строка
  `autoLaunchesToday` как единственный представитель домена (заменяется
  блоком «Кто занят»; счётчик остаётся внутри него).

### 3.2 Что это даёт

J1 «утренний обзор» отвечает с первого экрана: занятость агентов, очередь,
входящие — ≤10 с, без захода в три раздела (критерий §10.1). Колодец
остаётся сигнатурой — смелость в одном месте, всё остальное тихое.

## 4. Поверхность 2: Агенты вокруг ростера

### 4.1 «Подключение» (`/agents/harnesses`) — реестр наверх, SSH свёрнуто

- Порядок: **реестр (ленты pending/active/revoked) → «Подключить»-кнопка →
  SSH-карточка свёрнутым блоком внизу**. ProvisionCard переезжает вниз и
  рендерится **свёрнутым** (`<details>`-паттерн шапки реестра), заголовок
  «Подключить нового агента».
- **Пустой реестр → гайд первым** (П2, обратный случай): если
  `items.length === 0`, экран = `ConnectGuide` (он уже существует,
  `ConnectGuide.tsx`) на весь контент, реестр-мета не показывается. Это
  единственный случай, где «мета» законно первая — домен реально пуст.
- «Подключение за ≤5 мин без документации» (J5, критерий §10.5): гайд
  самодостаточен, pip-хинт из пустого состояния удаляется (микрокопия §8,
  `agents.strip.emptyHint`).

### 4.2 Строка хоста — лицо домена (Ф3, координация UI-29)

Ростер-консолидация: строка хоста = **одна строка ответа** «что на этом
хосте»:

```
┌ lap-zcode ──────────────────────────────────────────────────────┐
│ харнесы 2 · агентов 3 · сейчас: T-128 (zcode) · сессий 14      │
│ ● на связи        [Открыть исполнение →] [Сессии хоста →]       │
└──────────────────────────────────────────────────────────────────┘
```

- Источники — существующие: executors (harness/host/presence),
  assignments (`?state=queued`), счётчик сессий Коры по хосту.
  Новых API нет; консолидация — клиентская.
- Строка хоста заменяет сегодня разрозненные: техкарточку исполнителя как
  единственный вход, отдельный реестр без хост-контекста.

### 4.3 Карточка исполнителя — работа сверху, служебное свёрнуто (Ф1)

Порядок в `ExecutorSheet` переворачивается (П2/П3):

1. **«Сейчас в работе»** — новый первый блок: список assignments
   исполнителя (`?executor_id=`, состояние/задача/ссылки на `/tasks/:id?tab=execution`
   по действующему механизму `return=`). Пусто → строка «Свободен — задач
   в работе нет» (состояние, не отсутствие блока).
2. Связь (ExecutorLinkCheck с новым названием §8).
3. Доступ (статус/одобрение) — как есть.
4. **Идентификация** (facts-таблица) — свёрнутый блок «Подробности» по
   умолчанию; внутри — все текущие facts без изменений.

### 4.4 «Проверить связь» → «Обновить пульс»

Механика не трогается (refetch реестра + вердикт присутствия — это честно
при честном названии): меняется только подпись и микрокопия вердикта
(§8). NN/g #2: слово «связь» обещало ping, которого нет; «пульс» обещает
ровно то, что происходит.

## 5. Поверхность 3: Кора — рабочая

- **Корень = реестр сессий сразу** (П2): список `kora.list.*` первым,
  без onboarding/coverage выше данных. Мета («Зачем Кора», «Что вижу /
  чего нет») — свёрнутый блок в подвале корня.
- **Фильтры хост/агент/статус в URL** (Ф3, координация Кора-срез-3):
  `?host&agent&state` — URL-first договор списков (действующий канон,
  образец §0). Реестр уже корнем (`navItems.ts:119–128`) — подтверждаем
  и достраиваем фильтры.
- **Честное пустое состояние**: сейчас «Подключите исполнителя…» показывается
  и когда исполнитель есть, а сканер не запускался (аудит #6). Новое
  ветвление (по данным, которые уже на экране):
  - исполнителей 0 → «Подключите агента — сессии появятся сами» + действие
    на гайд подключения;
  - исполнители есть, сессий 0 → «Сессии появятся, когда сканер начнёт
    работу на хостах» + строка-ссылка на `/system/status` (где видно
    здоровье) — **без обещания, что сессии «сами появятся»**.
- **Словарь**: `kora.week0Badge` → тихий бейдж «Демо-данные»
  (tooltip остаётся развёрнутым, без «контракт-моков»);
  `kora.chat.title` «Чат (срез 3)» → «Чат» (§8).
- **Продолжение сессии ≤1 клик** (J7, критерий §10.7): строка сессии в
  реестре — сразу действие «Продолжить» для steerable-сессий (сегодня
  клик ведёт в транскрипт, продолжение ищется внутри).

## 6. Поверхность 4: Система без тупиков

- **Статус** (`/system/status`): health-панель (`StatusPanel health`)
  рендерится **всегда, когда health.data есть** — независимо от метрик
  (факт #3: данные в руках, прячет их только структура ветвлений
  `StatusPage.tsx:37–77`). Метрики 501 → HonestLine под панелью:
  «Метрики появятся позже». Метрики сломались (не 501) → HonestLine
  с Retry, health не исчезает. Новая структура ветвлений:
  1. `health.isError` → EmptyState error + Retry (единственный оставшийся
     полноэкранный EmptyState — health реально нет).
  2. health ok → `StatusPanel health` + (метрики error → HonestLine,
     board-501 → HonestLine «в этом режиме метрик нет», ok → как сегодня).
- **Сессии/Трассировки → disabled-слоты** в навигации (паттерн `soonKey`,
  как «Хранилища» в `navItems.ts:133`): пункт виден, недоступен, тултип
  «появится позже». Маршруты `/system/sessions*`, `/system/traces`
  **сохраняются** (легаси-редиректы `legacyRedirects.ts:19–21` работают,
  закладки не ломаются), но в board-режиме страницы заменяются
  HonestLine-плейсхолдером вместо 501-EmptyState. Ссылки на них из
  `crumbsFor` остаются валидными.
- **Система сжимается**: навигация домена = Статус · Настройки ·
  Автоматизация · Устройства (живые) + 2 disabled-слота. Ни одного
  пункта, ведущего в 501-экран (J8, критерий §10.8).

## 7. Новые/расширяемые примитивы (контракт для FE, без кода)

### 7.1 `HonestLine` — честная неполнота строкой

Одна строка: тихий текст + опциональное действие-ссылка. Вариант
`status` (нейтральная неполнота) и `warning` (что-то живое, но не всё).
Semantics: `role="status"`. Токены: `--text-sm`, `text-foreground-secondary`,
`--radius-md`, границы `--color-border-subtle`. Никаких новых цветов/шрифтов.

### 7.2 `EmptyState` — расширение `techDetail`

Существующее проп-поле `detail` (сейчас = сырой `error.message` в открытом
виде, `EmptyState.tsx:61–63`) переименовывается по смыслу: detail рендерится
**под раскрытием** «Технические подробности» (button + скрытый блок,
`aria-expanded`/`aria-controls`), никогда открытым по умолчанию. Обычный
`message` — всегда человеческая фраза из словаря. Все существующие вызовы
с сырым message проходят ревизию: человекочитаемая фраза → `message`,
сырой текст → `techDetail`.

### 7.3 Палитра ⌘K (Ф2)

- Триггер: овал поиска в TopBar (клик/фокус) и `⌘K`/`Ctrl+K`. Овал-колодец
  остаётся сигнатурой — палитра наследует `--radius-xl` и рендерится как
  elevated-оверлей (`--color-bg-elevated`, `--shadow-float`).
- Содержимое: единый ввод, четыре честных раздела результата — Навигация
  (маршруты, чистый клиент-сайд индекс), Задачи (`GET /tasks?q=`), Агенты
  (исполнители/хосты, существующий список), Память (существующий поиск
  `/api/memory/search`; дефолт-раздел — память, сегодня's контракт сохранён).
- Обещание шапки и выдача совпадают — закрывается разрыв J3.
- А11y: `role="dialog"` + `aria-modal`, фокус-ловушка, Esc закрывает,
  `↑/↓` выбор, Enter переход, возврат фокуса в триггер. Триггер ≥24×24
  (фактически овал — сильно больше).

## 9. State-матрицы ключевых новых состояний

### 9.1 Кокпит-блоки Обзора («Кто занят» / «Что ждёт меня»)

| Состояние | Условие | Вид |
| --- | --- | --- |
| default | данные ок, есть контент | строка агрегата / плитки со счётчиками; каждая цифра — ссылка на свой список |
| loading | первый запрос | skeleton той же высоты строки (без layout-сдвига) |
| error | запрос упал | HonestLine «Не удалось получить занятость · [Повторить]» — блок не исчезает молча |
| empty/zero | 0 исполнителей или 0 задач | «Кто занят» не рендерится; вместо него HonestLine «Агентов пока нет…» с действием. «Что ждёт меня»: пустые плитки не рендерятся |
| partial | executors ok, assignments error (или наоборот) | живая половина рендерится, вторая — HonestLine с Retry (независимые запросы, как health/metrics в StatusPage) |
| hover/focus (ссылки блока) | указатель/клавиатура | действующие токены: `text-iris-bright`, outline 2px `iris-bright` offset 2 |
| disabled | — | не существует (блок либо рендерится, либо нет) |

### 9.2 Строка ростера хоста (Ф3) и строка исполнителя в реестре

| Состояние | Условие | Вид |
| --- | --- | --- |
| default | presence ok | бейдж состояния словами («на связи»/«не отвечает»), работа-строка из assignments |
| loading | refetch реестра | skeleton строки, прежний контент не мигает (veto на «прыжок») |
| error | реестр недоступен | HonestLine «Не удалось обновить пульс · [Повторить]» — строки не исчезают |
| offline/устарел | presence stale по meta | вердикт словами + возраст пульса (существующий `linkVerdictAge`) |
| revoked | терминальный | tombstone-паттерн действующий (ExecutorSheet) |
| «Обновить пульс» | нажатие | busy-состояние кнопки (spinner 150ms), вердикт обновляется ниже; никакого «пинга» |
| disabled (revoked-строка) | — | действия кроме Delete скрыты — как сегодня |

### 9.3 Пустая Кора (корень)

| Состояние | Условие | Вид |
| --- | --- | --- |
| default | сессии есть | реестр + фильтры в URL (Ф3) |
| loading | первый запрос | skeleton (действующий) |
| error | не 501 | EmptyState error + Retry (действующий) |
| empty-вариант A | исполнителей 0 | HonestLine + CTA «Подключить агента» → гайд; мета скрыта |
| empty-вариант B | исполнители есть, сканер не приносил сессии | HonestLine «Сессии появятся, когда сканер начнёт работу на хосте»; никакого «Подключите исполнителя» |
| empty-вариант A/B + фильтры | пусто под фильтром | «Ничего не найдено под фильтром · [Сбросить]» — URL-first, сброс чистит `?host&agent&status` |
| disabled | — | не существует |

### 9.4 Disabled-слот навигации (Сессии/Трассировки)

| Состояние | Условие | Вид |
| --- | --- | --- |
| default | не живой раздел | кнопка disabled + бейдж «позже» + тултип (`nav.soonSessions`/`nav.soonTraces`) |
| focus | клавиатура | слот остаётся в Tab-порядке? — **нет**: `disabled` убирает из Tab-порядка; имя места остаётся читаемым визуально (не color-only, бейдж-текст) |
| hover | курсор | курсор `not-allowed`, тултип объясняет |
| error/loading | — | не применимы |

Примечание a11y: disabled-слот вне Tab-порядка — осознанно (паттерн
«Хранилища» уже принят и проверен); информация не теряется, т.к. состояние
объявлено текстом бейджа и строкой честности на Обзоре (не цветом —
WCAG 1.4.1).

## 10. Критерии приёмки (пронумерованные, проверяемые)

Продуктовые (JTBD рамки архитектора):

1. **J1**: «кто чем занят / что ждёт меня» читается с первого экрана Обзора
   ≤10 с (занятость агентов + очередь + входящие без скролла на 1440×900).
2. **J2**: канбан задач не деградировал — все существующие тесты доски
   зелёные (регресс-критерий, не трогаем).
3. **J3**: поиск в шапке честен: овал/⌘K открывает палитру, чьи разделы
   покрывают память+задачи+агентов+навигацию; нет состояния «обещает всё,
   ищет память».
4. **J4**: консолидированное живое исполнение — строка хоста/карточка
   исполнителя отвечает «чем занят сейчас» без перехода в другой раздел
   (данные уже на клиенте).
5. **J5**: подключение агента за ≤5 мин без документации: при пустом реестре
   первый экран = ConnectGuide; SSH-карточка свёрнута при непустом реестре.
6. **J6**: телефон одной рукой: первичные действия кокпита/Коры — цели
   ≥44×44px на вьюпортах <768px (выше базовых 24px WCAG 2.5.8); навигация
   не требует двух рук (нижний сайдбар-паттерн действующий).
7. **J7**: продолжение сессии Коры ≤1 клик от реестра (строка → «Продолжить»);
   корень Коры = реестр сессий.
8. **J8**: ни одного мёртвого пункта меню — каждый пункт навигации либо
   ведёт на живую поверхность, либо честный disabled-слот; состояние
   «появится позже» одной строкой на Обзоре.

Дизайн-приёмка (проверяются на Mock-адаптере + review против спеки):

9. Ни один сырой `error.message` адаптера не виден в UI без раскрытия
   «Технические подробности» (проверка всех вызовов EmptyState с message).
10. `/system/status` в board-режиме показывает health-панель (StatusPanel)
    + HonestLine о метриках; «сломанная система» больше не рендерится
    при живом health.
11. Ключи `agents.strip.emptyHint`, `kora.list.emptyMessage`,
    `kora.week0Badge`, `kora.chat.title`, `agents.linkcheck.trigger`,
    `agents.provision.authPasswordNote` заменены по §8 в ru и en;
    grep по продовым ключам не находит «срез», «моки», «pip», «passwordAuth»,
    «Неделя 0».
12. State-матрицы §9 покрыты тестами на уровнях компонентов (loading/error/
    empty/partial для кокпит-блоков; empty-варианты A/B Коры; disabled-слоты).
13. Все новые интерактивные элементы: фокус-кольцо 2px `iris-bright`
    offset 2, цель ≥24×24 (≥44 на мобильных для первичных), не
    перекрываются (2.4.11); информация не только цветом (1.4.1);
    `prefers-reduced-motion` и `data-motion="reduced"` не ломаются
    (палитра появляется без анимации в reduced-режиме).
14. Регресс-гейты: freeze-тесты (TasksLayout), URL-first фильтры,
    return=-механизм, фокус-дисциплина шелла, j/k-навигация — зелёные.

## 11. Срезы

- **Ф1 «без новых API» (~0.5 волны)** — решает 8 из 10 аудита:
  порядок блоков (ExecutorSheet «Сейчас в работе» из `/api/assignments`,
  Кора реестр-первым + мета вниз, ProvisionCard свёрнута при непустом
  реестре, пустой реестр → ConnectGuide), disabled-слоты Сессий/Трассировок,
  HonestLine + `techDetail` в EmptyState, StatusPage health-всегда,
  микрокопии §8, Обзор: ссылки в Задачи/Исполнение (без live-блоков),
  «Обновить пульс».
- **Ф2 «палитра ⌘K + кокпит-блоки из живых данных» (~0.5 волны)**:
  палитра (§7.3), блоки «Кто занят»/«Что ждёт меня» на Обзоре, строка
  честности, снятие quick-links-тройки.
- **Ф3 «ростер-консолидация + Кора-фильтры» (с координацией UI-29 /
  Кора-срез-3)**: строки хостов с консолидированной работой и
  сессии-счётчиком, фильтры Коры `?host&agent&status` в URL,
  «Продолжить» ≤1 клик.

**Явно НЕ делаем**: канбан (архитектура не трогается), TextEngine,
`return=`-механику (заморожена, только переиспользуем), существующие
URL-фильтры списков, бейджи-систему, Активность (UI-28), группировку
active→queued→terminal, j/k-навигацию, фокус-дисциплину шелла, soon-слот
паттерн (переиспользуем как есть), новые цвета/шрифты/токены, изменения
роутинга и маршрутов, server-side изменения (все срезы читают существующие
эндпоинты).

## Self-review дизайнера (протокол two-pass)

**Пасс 1 (план)**: кокпит на Обзоре из живых executors+assignments+inbox;
Агенты перестроены «ростер → работа → конфигурация»; Кора = реестр сразу;
Система = health-всегда + disabled-слоты; HonestLine/techDetail как два
примитива честной неполноты; палитра ⌘K закрывает разрыв обещания поиска.

**Пасс 2 (самокритика)**: (1) «Кокпит — это дашборд, который сами запрещали?»
— нет: анти-дашификация-правило сохранено дословно — пустой блок не
рендерится, счётчик без смысла запрещён; кокпит отвечает на JTBD J1, а не
украшает. (2) «Палитра дублирует сайдбар» — палитра отвечает на обещание
шапки (сейчас ложное), сайдбар остаётся первичной навигацией; палитра —
ускоритель, не замена (recognition over recall сохранён: разделы результата
подписаны, дефолт-раздел память). (3) Отвергнуто в пассе 2: полноэкранный
«режим борды»-экран для метрик (третий вариант статуса) — это снова
неполнота-экран, нарушает П1; вынесено в HonestLine. Disabled-слоты с
сохранением в Tab-порядке — отвергнуто (фокус-ловушка на недостижимом;
объяснение перенесено в бейдж+строку честности, не color-only). (4)
Без брендинга опознаётся? Связка «строка честности + данные-раньше-мета +
карточка-замыкается-на-работу» не читается как generic-SaaS: у нас нет
hero-градиентов, карточных сеток-близнецов, emoji-иконок; смелость осталась
в колодце (одна сигнатура). Anti-slop blacklist не затронут. (5) Открытые
допущения: (a) live-блоки Обзора держат частичную деградацию по
независимым запросам — если gateway не отдаёт executors в L1-режиме, блок
просто не рендерится (действующая capability-модель); (b) «Продолжить
≤1 клик» зависит от механики руления Коры (срез-3) — если PIN-шаг обязателен,
критерий считается от строки реестра до подтверждённого ввода; (c) палитра
в Ф2 — клиент-сайд индекс без server-side search ранжирования; ранжирование
не обещается, разделы честные.
