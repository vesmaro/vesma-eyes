# 07b — Мастер подключения хоста (4 шага) и список подключённых

> Status: **v1.0, дизайн-лид, 2026-09-27**. Переработка `/agents/harnesses`
> по критике владельца: «одна большая форма» → пошаговый мастер, вечное
> «не проверено» → живой прогресс установки с конечными состояниями.
> Опирается на: `07a` (словарь), серверный контракт provisioner
> (`docs/design/2026-09-23-connect-provisioning.md` — job-машина, typed-ошибки,
> SSE `provisioning.*`), enrollment-контракт (`2026-09-22-executor-enrollment.md`).
> Стейт-машина `draft → queued → connecting → installing → watching → done/failed`
> уже реализована сервером — UI маппит её на человеческий прогресс (§3), не изобретает.

## 1. Структура страницы «Подключить»

Заголовок: «Подключить хост». Под ним — одна строка: «Подключаем машину за 4 шага:
машина → доступ → харнес → проверка. Агент установится сам.»

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ Подключить хост                                [Как это работает]           │
│ ─────────────────────────────────────────────────────────────────────────── │
│ ① Машина ─── ② Доступ ─── ③ Харнес ─── ④ Проверка        ← шаги-индикатор   │
│ ┌──────────────────────────────────────────────────────────────────────────┐│
│ │  (шаг активный; пройденные — сворачиваются в строку-резюме с [Изменить]) ││
│ └──────────────────────────────────────────────────────────────────────────┘│
│ ─────────────────────────────────────────────────────────────────────────── │
│ ПОДКЛЮЧЁННЫЕ ХОСТЫ (3)                            [Открыть реестр хостов →] │
│ ┌─ карточка ─────────────┐ ┌─ карточка ─────────────┐ ┌─ карточка ────────┐ │
│ │ ● laptop-go-1          │ │ ◐ vpnus-1              │ │ ○ laptop-zcode-1  │ │
│ │ на связи · 12 с назад  │ │ молчит 4 мин —         │ │ выключен          │ │
│ │ zcode · задачи: 1      │ │ проверить              │ │ владельцем        │ │
│ └────────────────────────┘ └────────────────────────┘ └───────────────────┘ │
│ ТОКЕНЫ РЕГИСТРАЦИИ (3)                                     [Создать токен]  │
│ … (строки-статусы, §7)                                                      │
└──────────────────────────────────────────────────────────────────────────────┘
```

- Шаги-индикатор: номера в кольцах 24px, пройденный — галка + подпись muted,
  текущий — ирис-кольцо, будущий — контур. Клик по пройденному = возврат с
  сохранением введённого. Цели ≥24×24, ринг `--color-focus`.
- Кнопка «Как это работает» — дровер (не свёрнутая внизу страница-помощь прод):
  4 коротких абзаца «что произойдёт»: сервер сам зайдёт на машину по SSH,
  поставит агента, агент начнёт докладываться, вы одобрите. Плюс строка
  «Понадобится: адрес машины и способ входа».
- Плотность операционная (`--text-data`, строки 40px), но поля формы — комфорт
  (высота 40px, `05` §2.5). Один primary на странице: «Продолжить» → на шаге 4
  превращается в «Подключить».

## 2. Шаг 1 — Машина

Поля (лейбл слева, подсказка под полем, ошибки инлайн — канон `05` §2.5):

| Поле | Подпись | Подсказка |
| --- | --- | --- |
| Адрес | «Адрес машины» | «IP или имя: `192.168.1.50`, `vpn.example.org`» |
| Порт | «SSH-порт» | предзаполнен 22; «обычно 22 — меняйте, если точно знаете» |
| Имя | «Как назовём хост» | «Понятное вам имя: laptop-go-1» |

Под полями — secondary-кнопка **«У меня нет ключа — сгенерировать»** с подписью
«Сделаем на сервере и покажем один раз». Это рекомендованный путь (кнопка выше
поля ключа, визуально как next-step подсказка). Клик → инлайн-блок: сгенерированный
ключ (mono, маскируется глазком «Показать» — «Показать ключ» прод сохраняется,
клик-цель 24px), кнопки «Скопировать открытый», «Скачать», строка «Открытую часть
добавьте на машину в `~/.ssh/authorized_keys` — покажем команду» + copy-кнопка.
Приватная часть в форму не возвращается: мастер скажет «Ключ создан. На шаге 2
выберите „вставить свой“ или укажите созданный — путь запомнен».

Валидация: live после первого blur (не на каждом символе). Ошибки —
«Адрес не похож на IP или имя: проверьте опечатки» / «Порт от 1 до 65535».
Имя уже занято — «Такое имя есть у vpnus-1. Возьмите другое».

## 3. Шаг 2 — Доступ

Способ входа — radio-карточки (кликабельная зона ≥44px, selected — ирис-край):

| Вариант | Подпись человеческим языком | Рекомендация |
| --- | --- | --- |
| **SSH-ключ — вставить** | «Приватный ключ текстом. Так заходит человек — так зайдёт и сервер» | дефолт |
| **Взять из ssh-config сервера** | «Если машина уже есть в конфиге сервера — просто выберите её имя» | вторая |
| **Пароль** | «Работает, но пароль в памяти сервера — не рекомендуем» | последняя, warning-текст |

Пояснение секрета (одна строка под выбранным вариантом):
**«Секрет увидит только сервер — в момент установки. В базу не пишется и
повторно не показывается. Если сервер перезапустится во время установки,
подключение придётся повторить.»** Это честная transit-only модель
(`connect-provisioning.md` §Security) — говорим её пользователю, потому что
она отвечает на настоящий вопрос «куда попадёт мой ключ».

- Поле ключа: textarea mono, «Показать/Скрыть» (eye-кнопка 24px), маска по умолчанию.
  Кодовая фраза — опциональное поле под ним: «кодовая фраза ключа (есть не у всех ключей)».
- Путь пароля: поле пароля + строка «Пароль используется один раз — для установки».
- Если на шаге 1 ключ был сгенерирован — radio «созданный на сервере» предвыбран
  и помечен «(создали на прошлом шаге)».
- Ошибка входа не на шаге 4, а здесь — префлайт: кнопка «Продолжить» сначала
  проверяет вход (typed-ошибки сервера, человекочитаемо в §5).

## 4. Шаг 3 — Харнес

Заголовок блока: «Чем будет работать агент». Под ним строка-пояснение:
**«Харнес — программа, через которую агент работает: например, zcode. Если
сомневаетесь — выберите „агент найдёт сам“: он обнаружит, что установлено.»**

- Dropdown харнеса со словарём сервера; последний пункт —
  **«Не знаю — агент найдёт сам»** (рекомендация, `harness_hint` не отправляется).
- Свёрнутый блок «Дополнительно» (шеврон, 240ms): адрес борда для машины —
  предзаполнен адресом текущего сервера, подпись «Обычно менять не нужно:
  машина в VPN или локальной сети». Правка доступна, ошибка формата — инлайн.
- Опция «строгая проверка отпечатка» и fingerprint — тоже в «Дополнительно»,
  подпись «Для параноиков: если знаете отпечаток ключа машины — вставьте, сверим».

## 5. Шаг 4 — Проверка (замена тупика «Подключить»)

После «Подключить» форма НЕ исчезает в список: превращается в **живой прогресс**
(данные — SSE `provisioning.created/progress/ok/failed`, никогда не содержит
секретов — серверный контракт). UI-маппинг стейт-машины job'а:

| Фаза job | Что видит пользователь | Вид |
| --- | --- | --- |
| queued → connecting | «Заходим на машину…» | строка + спиннер 16px, таймстамп mono |
| connecting (host-key) | «Сверяем отпечаток машины…» | fingerprint SHA256:… (mono, обрезан) + «первое подключение — отпечаток запомнен» |
| installing | «Ставим агента…» | прогресс-лента шагов job.steps с таймстампами |
| watching | «Агент запущен. Ждём первый доклад — обычно до 2 минут» | countdown-строка, не таймер-спиннер |
| done | **зелёная итоговая карточка** (§5.1) | — |
| failed | **красная итоговая карточка** (§5.2) | — |
| timeout (bootstrap 10 мин / register) | **жёлтая итоговая карточка** (§5.3) | — |

Прогресс-лента: строки `--text-data`, каждая — шаг + время; новая появляется
240ms `--ease-enter`; reduced-motion — появление мгновенное. Пользователь может
свернуть мастера в мини-карточку и работать дальше — завершение придёт тостом
(канон toast `05` §3) с кнопкой «Открыть хост».

### 5.1 Готово (success)

```
●  laptop-go-1 на связи
   Агент установлен и докладывается. Умения пока не назначены —
   задачи хост не найдут, пока не назначите.
   [Открыть хост]  [Назначить умения]  [Дать задачу]
```

Зелёный — только по факту первого доклада (пилюля «на связи», не оптимизм).
«Назначить умения» ведёт на карточку хоста, блок «Умения и роли» —
замыкает петлю, которой не было в проде.

### 5.2 Ошибка (typed → человеческий язык)

Формат: заголовок с ошибкой + 2–3 конкретных «что проверить» + кнопки
«Повторить подключение» (новый job; токен переиспользуется если жив —
контракт §B) и «Проверить связь». Маппинг typed-ошибок:

| Код сервера | Заголовок | Что проверить |
| --- | --- | --- |
| `ssh.unreachable` | «Не достучались до машины» | адрес и порт; машина включена; брандмауэр пропускает SSH |
| `ssh.auth_failed` | «Сервер не смог войти» | ключ вставлен целиком; ключ добавлен на машину; не перепутан логин |
| `ssh.host_key_mismatch` | «Машина отвечает, но отпечаток не тот» | «Отпечаток другой, чем запомнили. Если вы переустанавливали машину — подтвердите новое подключение в деталях хоста. Если нет — не подтверждайте: это может быть чужая машина» |
| `ssh.sudo_required` | «Нужен root без пароля» | у пользователя должен быть sudo без запроса пароля (установку делает root) |
| `bootstrap.exit.*` | «Установка оборвалась (код N)» | «Показать хвост ошибки» (раскрыть stderr ≤200, маскированный) + «проверьте место на диске и доступ к серверу с машины» |
| `ca.unavailable` | «Сервер не смог выдать сертификат» | «на сервере не настроен CA — это настройка администратора» |

Host-key mismatch — единственная ошибка с blocked-retry: кнопка «Повторить»
disabled с пояснением; развязка = отдельное owner-действие «Запомнить новый
отпечаток» в деталях хоста (старый→новый показываются) — контракт pin по identity.

### 5.3 Таймаут

```
◐  Машина молчит 10 минут
   Агент поставлен или ставился, но первый доклад не пришёл.
   Что проверить: адрес и порт доступен с машины? машина в той же сети?
   [Проверить связь]  [Повторить проверку позже]
```

«Повторить проверку позже» закрывает мастер; хост остаётся в списке со статусом
«ждёт первый доклад» — жизненный цикл не обрывается (`07a` §4).

## 6. Список «Подключённые хосты»

Карточка хоста (не таблица строк): статус-пилюля по `07a` §4, имя, харнес,
счётчик активных задач, последняя активность человеческим языком. Клик — карточка
«Жизнь хоста» (`07c`). Состояния:

- loading — скелетон 3 карточек;
- empty — «Хостов ещё нет. Подключите первую машину — агент поставится сам» +
  primary «Подключить хост» (якорь на мастер);
- error — «Список не прочитался — сервер ответил ошибкой» + «Повторить»;
- карточка выключенного хоста — пилюля «выключен владельцем», действия
  «Включить» прямо на карточке (без ухода в карточку).

Продающий момент: под списком строка «Изменить можно всё, кроме харнеса —
он задаёт правила машины» со ссылкой «подробнее» на детали карточки.

## 6.1 Ручной путь (self-service, без SSH)

Сохраняется как свёрнутая альтернатива: кнопка «Подключить вручную (токен)»
под мастером → экран токена регистрации: кнопка «Создать токен» → токен + TTL-дуга
15 мин + блок команд с кнопками копирования + строка «Токен одноразовый: живёт
15 минут и работает один раз». Показ токена — один раз, с предупреждением
«Скопируйте сейчас — потом не покажем». Это тот же словарь, что и мастер,
без регресса `f40bd04`.

## 7. Токены регистрации (список)

Строки `--text-data` (замена «Токены подключения» прод):

| Как в UI | Расшифровка |
| --- | --- |
| «Создан · только что · живёт до 14:15» | created + TTL-возраст |
| «Использован · laptop-go-1 · 14:02» | used (без дубля «использован использован») |
| «Истёк · 13:41» | expired |
| «Отозван · вами · 12:30» | revoked |

Кнопка «Создать токен» — secondary; при 3 живых — disabled с tooltip
«Максимум 3 живых токена. Отзовите лишний» (disabled с пояснением — канон `05` §2.1).
Отзыв токена — ×-цель 24px + confirm «Токен станет непригодным. Отозвать?».

## 8. State-матрица мастера (блокер-канон)

| Компонент | Матрица |
| --- | --- |
| Шаги-индикатор | default/hover(кликабельны пройденные)/focus/active(текущая)/disabled(будущие с tooltip «Сначала предыдущий шаг») |
| Поля (адрес/порт/имя/ключ/пароль/фраза) | полный набор `05` §2.5 + live-валидация после blur |
| Radio-карточки способа входа | default/hover/focus/selected/disabled(пароль при helm-флаге off — с пояснением «выключено администратором») |
| Кнопки «Продолжить»/«Подключить» | `05` §2.1 + loading «Подключаем…» (повторный клик заблокирован) |
| Прогресс-лента | loading(скелетон)/running(шаги добавляются)/success/error/timeout/reduced-motion |
| Мини-свернуть | collapsed(плавающая пилюля «Подключение идёт · шаг installing»)/expanded |
| Список хостов/токенов | loading/empty/error/stale(SSE-разрыв — «данные на HH:MM») |

A11y: wizard — `role="group"` c `aria-labelledby` заголовка шага; каждый шаг —
заголовок H2; фокус после перехода шага — на его заголовке (`tabindex="-1"`,
announce polite). Ошибки — `aria-live="polite"`, префикс «Ошибка:» (не цветом одним).
Все цели ≥24×24 (мобильный 44px). `Esc` закрывает дровер помощи, не мастер.
`prefers-reduced-motion`: прогресс без спиннер-анимаций — текстовые фазы.
