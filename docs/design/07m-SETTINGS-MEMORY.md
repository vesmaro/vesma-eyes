## 0. Решения поверх брифа (записаны до проектирования)

| Вопрос | Решение | Почему |
| --- | --- | --- |
| Каркасный паттерн Коры (`07l`: 100vh, ресайз-швы, внутренние скроллы) — применим к Настройкам? | **Нет.** Настройки — страница-конфигурация с общим скроллом; каркас 100vh нужен рабочим областям с панелями и ресайзом, у Настроек панелей нет. Заимствуется только приём «секции-якоря + мини-навигация сверху» | Принцип `07l` §1 («приложение, не страница») применим к пространствам работы, не к чтению; насильный каркас породил бы пустые вертикали и второй скролл ради скролла |
| Иерархия префиксов в тегах (`task:*`, `project:*`) | **Не вводим.** В данных стенда префиксов нет — рисовать кластеры из ничего = фейковая структура. Честно: плоское облако + строка «словарь тегов — черновик, не утверждён» (по записи M-241, без id в основном слое — `07a` §1.4) | Честность стенда: структура показывается, только когда она есть в данных |
| Масштаб облака тегов | **3 ступени S/M/L по производным счётчикам** (см. §2.2), размер — усиление, не единственный носитель: у каждого тега tooltip «N записей» и счётчик в карточке | Размер как единственный канал — нарушение 1.4.1 по духу; число обязано читаться |
| «20–30 фикстурных тегов» | Сейчас из data.js выводится 17 уникальных тегов. Добавляем демо-кластер v8 (6 узлов колодца: настройки, навигация, пульс, теги, хоткеи, перевод) → **23 тега**. Счётчики — всегда производные от записей (`07j` §2.2.3: литерал в разметке = ревью-баг) | Диапазон брифа выполняется без выдуманных счётчиков |
| Пульс — второй датасет? | **Нет**: проекция тех же событий, что гонит импульсы канваса Обзора (паттерн Эфира Коры `07j` §2.3 — «projection, not a second dataset»). Возраст — из offset-якоря загрузки, не рукописные часы | Один источник правды; часы из offsets — прямое требование брифа и канон `07j` §2.2 |
| Четвёртый цвет импульса для «индексации»? | **Нет.** Словарь импульсов `06` §5 заморожен (recall/ирис, write/золото, error/красный). Событие «индекс» живёт только в ленте Пульса: точка `--color-confidence-dim` + текст, импульса на канвасе не даёт | Расширять словарь импульсов ради строки фильтра — неверный обмен; текст всегда рядом с точкой (1.4.1) |
| Хоткеи `g p` и `g s` | `g p` → **Пульс** (сейчас ведёт в Записи — дрейф от канона `03` §7); `g s` → **Настройки** (сейчас ведёт в Проводник — тот же дрейф). Проводник остаётся в домене «Рабочий стол» и палитре | Канон `03` §7 восстановлен; расхождение таблицы хоткеев и карты — баг, не фича |
| Настройки дублируют тумблеры топбара (тема/плотность/движение) | Сознательное дублирование с **одним источником правды**: те же store-ключи, одни apply-функции; переключение в любом месте синхронизирует всё. Расхождение состояний — ревью-баг | Два входа к одной настройке — норм; два состояния одной настройки — баг |
| Секция «Сессия» vs чип пользователя топбара | Дублирование сознательное: Настройки = сводка + выход в одном месте; источник один — `vesmaro.authSession` (`07k` §5.1) | Recognition over recall; выход из Настроек не требует искать чип |
| Прод-секции Настроек (6: Внешний вид/Поведение/Доска/Навигация/Исполнение/Автоматизация) | Стенд v8 показывает **5 честных секций**: Внешний вид, Навигация, Язык, Сессия, О стенде. Секции без реального содержимого в стенде не рисуются (канон «пустой слот не рендерится») | Честность стенда; прод-карта секций — контракт продукта, не стенда |

## 1. «Настройки» (`/settings`) — страница-конфигурация

**Задача**: одно место, где меняется вид стенда и видна сессия; каждое
управление либо реально работает, либо честно говорит, что это заглушка.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ Система / Настройки                                              ⌘K          │ крошки 40px
│ Настройки · вид стенда и сессия                                              │
│ [Внешний вид] [Навигация] [Язык] [Сессия] [О стенде]   ← мини-навигация     │
│ ───────────────────────────── миелин ──────────────────────────────────────  │
│ ВНЕШНИЙ ВИД                                                                  │
│ Тема                    Как выглядит колодец: глубина или береста.           │
│                         ( Колодец ) ( Береста ) ( Системная )  ← radio-карточки
│ Плотность               Сколько строк видно: чтение или работа.              │
```

### 1.1 Каркас страницы и мини-навигация

- Общий скролл страницы (решение §0); ширина контента `max-width: 760px`,
  выравнивание по левому краю контентной колонки (читаемая мера, не лента
  на весь вьюпорт).
- **Мини-навигация** под H1: `<nav aria-label="Разделы страницы">` из
  linkbtn-ссылок на якоря `#appearance #navigation #language #session #about`.
  Активный раздел подсвечивается точкой `--synapse-recall` + текст
  `--color-iris-bright` (канон активной секции сайдбара `03` §3). Клик —
  плавный скролл (reduced — мгновенный), у якорей `scroll-margin-top: 56px`
  (2.4.11: цель не прячется под крошками).
- Секции: caps-заголовок `--text-caps` + `--tracking-caps` (`ВНЕШНИЙ ВИД`),
  под ним строки управления. Строки разделены `--myelin-hairline`; фон —
  `--color-bg-base` (страт-тинты на карточках с текстом запрещены, `02` §1).
- **Строка управления** = grid `[название+описание | управление]`: название
  `--text-ui` medium, описание-подсказка `--text-sm` `--color-text-secondary`
  (человеческим языком, «что изменится»), управление прижато вправо; на
  <768px — в столбик, управление после описания, вся строка карточки
  радиокнопки остаётся целью ≥44px.

### 1.2 Внешний вид

| Управление | Вид | Реальный эффект в стенде |
| --- | --- | --- |
| **Тема** | radio-карточки ×3: «Колодец» (тёмная), «Береста» (светлая), «Системная» | Реальный. Ключ `stand-theme`: `dark` / `light` / `system`. «Системная» = слушаем `prefers-color-scheme` (`matchMedia`, живая реакция на смену темы ОС). Тёмная — отсутствие `data-theme`; светлая — `data-theme="light"`; системная — атрибут ставится по медиа-запросу. Тосты «Тема: колодец (тёмная)» / «Тема: береста (светлая)» / «Тема: как в системе» |
| **Плотность** | radio-карточки ×2: «Созерцательная» (56px строки), «Операционная» (32px) | Реальный. Существующий ключ `stand-density` → `data-density` (комфорт/компакт). Текущие тосты топбара уже называют плотности словами брифа — переиспользуются |
| **Сократить движение** | тумблер | Реальный. Существующий ключ `stand-motion` → `data-motion="reduced"` (зеркало `prefers-reduced-motion`, канон `06` §7). Подпись-описание: «Стенд также слушается системной настройки „уменьшить движение“» |

- Карточки радио: имя варианта + одна строка-пояснение («Колодец — глубокие
  поверхности, свечение = данные»; «Созерцательная — строки от 56px, чтение»).
  Выбор применяется немедленно, кнопки «Сохранить» нет (настройки вида —
  обратимы мгновенно).
- Источник правды один: переключение темы из топбара/палитры обновляет
  выбранную радио-карточку Настроек и наоборот. В топбар-тумблере при
  `stand-theme="system"` клик выходит из «системной» в явную тему (тост
  «Тема: теперь выбрана вручную» — честный выход из режима).

### 1.3 Навигация

| Управление | Вид | Реальный эффект |
| --- | --- | --- |
| **Сайдбар** | radio-карточки ×2: «Развёрнут» / «Свёрнут» | Реальный. Существующий ключ `stand-sidebar`; применение — тот же `app.classList.toggle("sidebar-collapsed")`, что у кнопки «Свернуть» и хоткея `[` |
| **Горячие клавиши** | тумблер «Включены» | Реальный. Новый ключ `stand-hotkeys` (`off` = выключены): guard в общем keydown-обработчике шелла. Выключаются одиночные (`/`, `?`, `[`), `g`-серии и `j/k/x`. **Остаются всегда: `Esc`** (закрытие оверлеев — 2.1.2, трапа клавиатуры быть не может) **и `Ctrl+K`/`Cmd+K`** (палитра — командный вход, не «горячая клавиша-ускоритель») |

- При выключенных хоткеях шпаргалка (`?` недоступна — открывается кнопкой
  «Шпаргалка» в подвале сайдбара) получает первую строку: «Горячие клавиши
  выключены. Включить — в Настройках →» (ссылка на `/settings#navigation`).
  Строки таблицы шпаргалки при этом не скрываются — справочник остаётся
  справочником.

### 1.4 Язык

- Нативный `select` «Русский / English» с `<label>`. Выбор EN → тост
  «Английский интерфейс появится в продуктовой версии — стенд остаётся
  на русском», значение возвращается на RU (выбор не применяется).
- Честная заглушка в каноне `[data-demo-action]` (07k): тот же текст тоста,
  что у тумблера RU|EN топбара — одна формулировка в двух местах, i18n-пара
  одна (§8).

### 1.5 Сессия

- Строки читают живую сессию `vesmaro.authSession` (`07k` §5.1):
  «Вы вошли как: <имя> · <роль человеческим словом: владелец/участник>»,
  «Вход: <человеческий интервал по `07a` §1.5, точный таймстемп в tooltip>».
- Кнопка «Выйти» — secondary (выход обратим — confirm не нужен, `05` §2.1),
  поведение каноническое `07k` §5.3: сессия удалена → тост «Вы вышли из
  аккаунта» → редирект на Обзор (Настройки — гейт-раздел «Система»).
- Страница гейтится как «Система» (§4.4), поэтому аноним до строк сессии не
  доходит — гейт-экран вместо контента; матрица «сессии нет» на странице
  не существует по построению (но безопасный рендер «—» обязателен на случай
  сбоя хранилища, файл://).

### 1.6 О стенде

- «Версия»: `vesma-eyes <STAND.version> · срез <STAND.slice>` — единственный
  источник `data.js` (канон `07k` §1.1; в data.js срез меняется на **v8**).
  Подпись «демо-данные; ничего не отправляется» — постоянная честность стенда.
- «Ссылки»: «Галерея дизайн-системы →» (`gallery.html`, публична — аддендум
  `07k`) и «Демо-сеялка Коры» (`kora-seed.html`) с бейджем **«служебное»**
  (`--text-caps`, контур золото-dim — стилистика бейджа «эксп», `03` §1) +
  tooltip «Пишет демо-состояния хранилища для проверки миграции».

### 1.7 Правило реального эффекта (сводная таблица)

| Управление | Эффект | Ключ/механика |
| --- | --- | --- |
| Тема ×3 | реальный | `stand-theme` + `prefers-color-scheme` для «системной» |
| Плотность ×2 | реальный | `stand-density` → `data-density` |
| Сократить движение | реальный | `stand-motion` → `data-motion="reduced"` |
| Сайдбар ×2 | реальный | `stand-sidebar` |
| Горячие клавиши | реальный | `stand-hotkeys=off` → guard шелла |
| Язык RU/EN | **честная заглушка** | тост «в продуктовой версии», выбор не применяется |
| Выйти | реальный | `vesmaro.authSession` → Обзор (`07k` §5.3) |
| Профиль (чип топбара) | заглушка (уже, `07k` §5.2) | тост — из Настроек не дублируется |

Правило: каждое управление несёт эффект или тост-объяснение; мёртвых
переключателей нет. Новые ключи настроек живут в существующем пространстве
`stand-*` и миграции не требуют (миграция `07l` §5.2 касается только
`vesmaro.kora*`); чтение — безопасными геттерами (мусор → дефолт, `07l` §5.2).

### 1.8 State-матрицы (тумблер, radio-карточки, select)

| Компонент | Матрица |
| --- | --- |
| **Тумблер** (switch) | default off/on (дорожка `--color-bg-elevated`/`--color-iris-solid`, ползунок inverse) / hover (дорожка `--myelin-strong` поверх тинта) / focus-visible (ринг `--color-focus` 2px/2px вокруг всей цели) / active (ползунок расширяется на 2px, без прыжка текста) / disabled — не бывает в v8 / клик-цель: видимая 44×24, зона попадания ≥44×44 мобильный / reduced-motion: сдвиг ползунка мгновенный / текст состояния рядом («Включены», «Сократить») — никогда не цветом одним (1.4.1) |
| **Radio-карточка** | native `<input type="radio">` в `<label>` (семантика сначала): default (край `--color-border-subtle`) / hover (край `--myelin-strong`) / focus-visible (ринг на карточке — видимое кольцо, не системный dotted) / checked (край 2px `--color-iris` + wash `--strata-system` + точка ✓) / disabled — не бывает / клавиатура: Tab входит в группу, ←/→ меняют (нативно), применение мгновенное / a11y: группа = `fieldset` + `legend` с названием строки («Тема») |

## 2. «Теги» (`/memory/tags`) — инспектор словаря памяти

**Задача**: увидеть, чем помечена память, найти тег по префиксу и уйти
в отфильтрованные Записи одним кликом.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ Память / Теги                                                    ⌘K          │
│ Теги · словарь памяти                                                        │
│ Каждая запись помечена тегами. Размер тега — сколько записей им помечено.    │
│ [⌕ Поиск по тегам… по началу слова]        23 тега · 68 записей с тегами     │ ← производные
│                                                                              │
│ #security #ui #process #memory #design        ← L (≥8 записей)               │
│ #agents #contract #sync #pairing #reporting   ← M (4–7)                      │
│ #tags #motion #a11y #kora #settings …         ← S (≤3)                       │
│                                                                              │
│ ┌ #agents ───────────────────────────────────────────────────────────────┐  │
│ │ Всё про агентов и их работу (из словаря).                              │  │
│ │ Записей: 4 · Связанные: #ui #contract #process   ← кликабельны          │  │
│ │ [ Показать записи → ]   (memories.html?tag=agents)                     │  │
│ └─────────────────────────────────────────────────────────────────────────┘  │
│ Словарь тегов — черновик, ещё не утверждён владельцем.                       │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 2.1 Облако: масштабирование S/M/L

- Ступени по **производному** счётчику записей с этим тегом (memories +
  wellNodes — один проход по фикстурам): **L ≥ 8**, **M 4–7**, **S ≤ 3**.
  Типографика ступеней: L `--text-body` semibold, M `--text-ui`,
  S `--text-data`; все — `--color-text-secondary`, hover → primary (контраст
  по `02` §4 на всех ступенях; размер меняет иерархию, не читаемость).
- Чип облака — `<button>` (не `<span>`, канон чипа `05` §2.2), высота ≥24px
  на всех ступенях (2.5.8), `aria-pressed` для выбранного, tooltip
  «<тег> — N записей» (число дублирует размер — 1.4.1 по духу).
- **Легенда** в строке подзаголовка («Размер тега — сколько записей им
  помечено») — легенда обязательна, размер сам себя не объясняет.
- Выбор: клик по тегу открывает карточку (§2.3); повторный клик по выбранному
  снимает выбор и закрывает карточку (паттерн `aria-pressed` фильтра Записей).

### 2.2 Поиск по префиксу

- Поле ввода (`05` §2.5, полный набор состояний), placeholder «Поиск по
  тегам…», фильтрация по **началу** имени тега (префикс, как в брифе),
  debounce 300ms, индикатор — точка, не спиннер. Облако фильтруется живо,
  ступени не пересчитываются (счётчик — свойство данных, не выборки).
- Счётчик найденного: «Найдено: N» рядом с полем (polite-регион) — при
  фильтрации число тегов в шапке не мигает.

### 2.3 Карточка тега

- Появляется под облаком при выборе тега; вход 240ms `--ease-enter`
  (reduced — мгновенно); заголовок карточки получает фокус (`tabindex="-1"`,
  announce polite — канон `03` §8).
- Содержимое (все значения — производные):
  - **Описан ли**: если тег есть в черновом словаре — описание словаря;
    если нет — честно: «Описания пока нет — тег вырос из записей».
  - **Сколько записей**: «Записей: N» (`tabular-nums`).
  - **Связанные теги**: топ-3 по совместной встречаемости в записях
    (co-occurrence, один проход по фикстурам); кликабельны — выбор
    переключается на них (облако подсвечивает, карточка обновляется).
- Действие: «Показать записи →» → `memories.html?tag=<тег>` — связь с
  существующим фильтром Записей (frontend донастраивает чтение `?tag=` в
  текущий `tagFilter` memories.html; синхронизирует `aria-pressed` чипов).

### 2.4 Фикстуры

- `data.js` дополняется: (а) `tagMeta` — описание для тегов чернового словаря
  (ui, agents, memory, sync, security, process, reporting, design, motion,
  pairing…); (б) демо-кластер v8 — 6 узлов колодца (M-36x, кластер «stand»):
  теги `settings`, `navigation`, `pulse`, `tags`, `shortcuts`, `i18n` →
  итого **23 тега** в облаке. Распределение по ступеням получается естественным
  (4–5 L, 7–8 M, остальные S) — искусственной накачки счётчиков не делаем.
- Счётчики шапки («23 тега · 68 записей с тегами») — вычисляются при загрузке;
  литерал в разметке — ревью-баг (`07j` §2.2.3).

## 3. «Пульс» (`/memory/pulse`) — живая лента памяти

**Задача**: полный журнал событий памяти с фильтрами; источник тех же
импульсов, что бегут по колодцу Обзора.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ Память / Пульс                            сейчас 14:06 · импульсов за час: 37│
│ Пульс · лента памяти                                                         │
│ [Все события ▾] [Все серверы ▾]                        N событий в ленте     │
│ ┌──────────────────────────────────────────────────────────────────────────┐ │
│ │ ● поиск нашёл «Схему провенанса» — открытие записи    agb · 2 мин назад  │ │
│ │ ● агент agb записал «Порядок моков в tokens.test»     mnemos-01 · 4 мин  │ │
│ │ ◆ индекс: 214 записей переиндексировано               core · 9 мин       │ │
│ │ ● поиск нашёл «Heartbeat-контракт» — ссылка свитка    mnemos-01 · 12 мин │ │
│ │ ◆ агент agb дополнил черновик тег-словаря             mnemos-02 · 18 мин │ │
│ │ … внутренний скролл (весь журнал) …                                     │ │
│ │ ▸ 3 новых события — к свежим                                            │ │
│ └──────────────────────────────────────────────────────────────────────────┘ │
│ Каждая точка здесь — импульс по ребру колодца на Обзоре →                    │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 3.1 Словарь событий памяти (строка ленты)

Анатомия строки: точка 8px + текст события + провенанс «кто · сервер ·
возраст» mono `--text-caps` (формат Эфира Коры `07j` §2.3, переведённый на
память). Цвет дублируется текстом — всегда (1.4.1).

| Тип события | Точка | Текст-шаблон | Импульс на канвасе Обзора |
| --- | --- | --- | --- |
| нашлось (recall) | `--synapse-recall` ирис | «поиск нашёл „X“ — <запрос / ссылка свитка / переход>» | да, ирис (`06` §5) |
| запись (write) | `--synapse-write` золото | «агент <имя> записал „X“» / «<имя> дополнил „X“» | да, золото |
| индекс (index) | `--color-confidence-dim` | «индекс: <что пересчитано>» | **нет** — событие ленты, не импульс (§0) |
| сбой (error) | `--synapse-error` красный | «<сервер> не ответил — переподключились за N с» | да, красный |

- Строка кликабельна, если у события есть запись: клик →
  `memories.html?id=<id>` (свиток записи). Сигнальные строки без записи
  (связь, как в Эфире) — не кликабельны, без ложного курсора.

### 3.2 Живая механика

- **Фикстуры — проекция**: данные ленты = `feedSeed` + ротация `feedPool`
  (те же, что гонят `stand:pulse` в канвас), дополненные событиями «индекс»
  из агентских фикстур. Возраст каждой строки — `minAgo`-offset от якоря
  загрузки страницы (канон `07j` §2.2: никаких рукописных часов); возрасты
  пересчитываются ежеминутно, tooltip строки — точное время.
- **Часы в шапке** («сейчас 14:06») — вычисляются из якоря, `tabular-nums`,
  обновление ежеминутно; это единственное место страницы с «текущим временем».
- **Вставка новых**: новое событие (ротация пула, интервал 15–30 с) всплывает
  сверху — 280ms `--ease-enter`, ≤1 вставки/сек (канон `04` §1); список держит
  ≤50 строк, старое уходит без анимации.
- **Пауза при скролле**: если пользователь прокрутил от верха, вставки не
  двигают ленту — копится плашка «N новых событий — к свежим» (кнопка, sticky
  над лентой; клик — прыжок к верху, счётчик сбрасывается). Плашка объявляется
  polite (4.1.3).
- **Счётчики шапки** — производные: «импульсов за час» — из `counters`
  фикстур, «N событий в ленте» — длина выборки; литералов нет.

### 3.3 Фильтры

- Два нативных select с видимыми label: **«Все события»** (нашлось / запись /
  индекс / сбой) и **«Все серверы»** (mnemos-01, mnemos-02, abyss-lab,
  seal-vault). Сервер события выводится из провенанса записи (owner →
  abyss-lab); сигнальные строки несут сервер из текста.
- Смена фильтра — перерисовка выборки 150ms fade (`--ease-in-out`), счётчик
  «N событий в ленте» обновляется; сочетание фильтров = пересечение.

### 3.4 Связка с канвасом Обзора

- Подвал страницы — одна строка-выход: «Каждая точка здесь — импульс по ребру
  колодца. Полный колодец — на Обзоре →» (ссылка `index.html`). Ошибка не
  тупик, словарь общий: точка строки ленты = цвет импульса канваса (канон
  `06` §5 «где дублируется»).
- Реализация одного источника: события ленты и импульсы канваса читают одни
  фикстуры; расхождение цветов ленты и канваса — ревью-блокер.

### 3.5 Состояния

| Состояние | Вид |
| --- | --- |
| loading | скелетон 3 строк ленты |
| фильтр без результатов | «По этому фильтру событий нет» + [Сбросить фильтр] |
| пусто (всё) | «Пока тихо — события появятся, как только память заработает» + [На Обзор →]; в стенде с фикстурами не встречается, матрица обязательна |
| SSE-разрыв | топбар-пилюля берёт связь на себя («подключаемся…»/«нет связи», `05` §2.4); лента честно замирает — строка-плашка «Лента отстала: показаны события до 14:02», новые не имитируются (`06` §5: пустота честнее выдуманных данных) |
| reduced-motion | вставки без анимации, часы и возрасты работают (текст, не движение) |

## 5. Общие правила (канон)

- **Словарь `07a`**: жаргон нулевой — ни «SSE», «offset», «URL-параметр»,
  «фикстуры» в основном слое; возрасты — человеческими интервалами («2 мин
  назад»), точные таймстемпы — в tooltip; id записей — только по клику/в
  деталях. Новые термины-оставленцы не вводятся: «Пульс» и «Теги» получают
  строку-пояснение при первом показе («Пульс — лента событий памяти: что
  искали, что записали» — tooltip H1, паттерн Коры `07l` §1.3).
- **Счётчики-производные**: любое число на трёх страницах вычисляется из
  фикстур при загрузке (`07j` §2.2.3); литерал в разметке — ревью-баг.
- **RU aria**: все новые контролы — RU `aria-label`; точки событий и тумблеры
  никогда не только цветом (1.4.1); live-регионы polite для тостов, плашек
  «N новых», счётчика найденных тегов.
- **Честность стенда**: заглушки — только через тост-объяснение (паттерн
  `data-demo-action`, `07k`); фейковые жизнь и структура запрещены (`06` §5,
  §0 этой спеки).
- **Motion `06`**: всё интерактивное ≤400ms, каскады ≤8 шагов, reduced —
  мгновенно; новых амбиентных движений нет (дыхание ириса топбара остаётся
  единственным в шелле).

## 6. WCAG 2.2 AA — именованные критерии

- **1.4.1 Use of Color**: тип события в Пульсе — точка + текст; выбранные
  радио/чипы — край + точка ✓ + текст; ступени облака дублируются числом в
  tooltip и карточке.
- **1.4.3 / 1.4.11 Contrast**: все новые пары — из `02` §4 (muted 4.8:1
  worst-case; `--color-confidence-dim` на base — графика ≥3:1, текст рядом
  primary); ринги `--color-focus` ≥8:1 на своих подложках.
- **2.4.1 Bypass Blocks**: мини-навигация Настроек — `<nav aria-label>`; skip-link
  шелла продолжает работать.
- **2.4.7 / 2.4.11 Focus Visible / Not Obscured**: ринги на тумблерах,
  radio-карточках, чипах облака, строках ленты; `scroll-margin-top: 56px` на
  якорях и на первом элементе после sticky-шапок ленты.
- **2.5.8 Target Size**: тумблер ≥44×24 (зона ≥44×44), радио-карточки ≥40px
  высоты, чипы облака ≥24px, строки фильтров select 40px (мобильный 44px
  везде).
- **3.2.1 / 3.2.2 On Focus / On Input**: фокус не меняет настроек; радио и
  select применяются сразу — это ожидаемое поведение настроек вида, контекст
  (страница) не меняется; редирект «Выйти» — только явным действием.
- **3.3.2 Labels or Instructions**: каждая строка Настроек = видимое название
  + описание; select связаны `<label for>`; группы радио — `fieldset/legend`.
- **4.1.2 Name, Role, Value**: тумблер `role="switch"` + `aria-checked`;
  нативные radio/select; чипы облака — `<button>` + `aria-pressed`; якорная
  nav — список ссылок с `aria-current` для активной.
- **4.1.3 Status Messages**: тосты, «N новых событий», «Найдено: N» — polite
  до скриптов; гейт-экран Настроек наследует фокус-поведение `07k` §3.

## 9. Самокритика (проход 2)

- **Настройки — «страница галочек»-клише?** Паттерн настроек универсален;
  отличие держится на строках человеческим языком («что изменится» вместо
  «Preferences»), честных заглушках с тостом-объяснением и словаре колодца
  («Колодец/Береста», «созерцательная/операционная»). Проверка «сними бренд»:
  опознаётся как настройки, но не как SaaS-кит из одинаковых карточек-тумблеров
  — сетка строк с описаниями, ни одного декоративного блока.
- **Облако тегов — приём эпохи flickr?** Риск принят: облако здесь — навигация
  (каждый чип = фильтр Записей), не украшение; ступени сдержанные (три
  типографических, без цвета-размера-веса одновременно), глубину даёт карточка
  тега. Если при прогоне новичка облако читается как «декор» — ступени
  схлопываются в один размер (запасное решение записано, решение по данным
  прогона).
- **Пульс vs живая лента Обзора — дубль?** Разделение честное: Обзор — 8
  последних строк-заголовков без фильтров; Пульс — полный журнал с фильтрами
  по типу и серверу, паузой скролла и часами. Данные одни — расхождений
  содержимого быть не может; расхождение цветов точки — ревью-блокер.
- **Синхронизация настроек** — главный инженерный риск спеки: пять ключей
  вида меняются из трёх мест (топбар, палитра, Настройки). Контракт: одни
  apply-функции шелла, одно событие перерисовки контролов; расхождение
  состояния — блокер. «Системная» тема добавляет медиа-запрос — тест-кейс:
  смена темы ОС при открытых Настройках обновляет карточки без перезагрузки.
- **Горячие клавиши выключателем** — новый класс состояния «управление
  отключено»: шпаргалка и строки документации обязаны говорить, что хоткеи
  выключены, иначе пользователь читает мёртвый справочник (найдено в
  самокритике, добавлено в §1.3/§4.3).
- **Токен-дисциплина**: новых токенов не ввожу — ступени облака, точка индекса
  (`--color-confidence-dim`), бейдж «служебное» собираются из существующих имён
  `02`/`03`.
- **Расхождение с брифом**: иерархия префиксов тегов не спроектирована — данных
  нет (§0, записано); секции Настроек — 5, а не 6 прод-секций — пустые слоты
  не рендерятся (§0).

## 10. Открытый вопрос владельцу (1, с рекомендацией)

1. **Выключатель горячих клавиш в продукте**: отключать ли всё, кроме `Esc`
   и `Ctrl+K` (мой дефолт §1.3), или палитра тоже выключается? Рекомендация:
   `Esc` и `Ctrl+K` остаются всегда — это доступность (выход из оверлея) и
   командный вход, а не ускоритель; «выключить хоткеи» должно значить
   «перестать перехватывать одиночные клавиши».
