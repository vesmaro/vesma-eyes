## 0. Диагноз (по коду, 1.37.1)

Запрос владельца — «что *сейчас* происходит». Ни одна существующая поверхность
на него не отвечает:

| Поверхность | Что показывает | Где | Чего не отвечает |
| --- | --- | --- | --- |
| Канбан `/tasks` | снимок статусов: колонки + карточки | `TaskBoardPage.tsx` | статусы без динамики: SSE (`taskEvents.ts`) патчит кэш молча — карточка *переезжает*, но кто двинул, когда и что было до — на доске не видно; «шуршание» (запуски, отчёты, провалы) не оставляет на канбане никакого следа |
| Список `/tasks/list` | те же статусы строками | `TaskListPage.tsx` | та же проекция — снимок, не поток |
| Исполнение `/agents/execution` | события исполнения: assignment.* + отчёты, actor-подписано | `ExecutionFeedPanel.tsx`, `executionFeedStore.ts` | агенто-центрично и **безысторично**: лента — ring-buffer `FEED_CAP=200` в памяти вкладки, «SSE has no history, so a fresh page starts empty» (docstring стора); нет фильтров по задаче/хосту, нет задачного контекста строкой, после F5 — пусто |
| История `/tasks/:id?tab=history` | merged таймлайн событий + памяти **одной** задачи | `GET /api/tasks/:id/history` (`app.py:2141`) | задача-центрично: кросс-поток «что шуршит прямо сейчас по всем задачам» из неё не собрать; actor из payload в UI-дайджест не поднимается |
| Пульс `/memory/pulse` | лента записей памяти | `PulseFeed.tsx` | домен памяти, не задач |
| Audit-таблица `events` | **весь** поток фактов уже пишется: `task.*` (с actor), полный цикл `assignment.*` (в т.ч. терминальные, `store.py:2599`), `executor.*`, `task.report` | `store.py` (`_log`), схема `store.py:680` | поверхности нет: таблица видна только пер-задаче через «Историю» |

Итого: данные для ответа на вопрос владельца **уже собираются** (audit-таблица
+ SSE с actor c 1.35.0) — не хватает одной задачно-центричной поверхности
«живой поток». Это чисто UI-дыра, не серверная.

## 1. IA: место «Активности»

**Подраздел раздела «Задачи», маршрут `/tasks/activity`**, между «Список» и
«Входящие» (заказ владельца: «рядом с Канбан/Список/Входящие/Архив»; поток —
операционный вид, живёт рядом с операционными проекциями):

```
Канбан · Список · Активность · Входящие · Архив
```

- `navItems.ts`: ребёнок домена задач `{ to: "/tasks/activity", key:
  "nav.taskActivity", icon: Activity, end: true }` (lucide `Activity` —
  существующий набор); крошка «Задачи › Активность» (`crumbsFor` + один case).
- Внутри `TasksLayout` — значит, один SSE-поток поддерева уже смонтирован
  (`useTaskEvents`), новая страница свой EventSource **не открывает** (тот же
  принцип, что у UI-10: один поток на домен).

Чем «Активность» **не является** (границы, чтобы не размыть):

| Не дублирует | Почему |
| --- | --- |
| «Исполнение» `/agents/execution` | то агенто-центрично: «кто я как исполнитель, что у меня в руках». Активность — задачно-центричный кросс-поток с историей и атрибуцией; не агрегирует в счётчики (тот же принцип нарративов §4.2 UI-10), но отвечает на вопрос «что происходит с задачами», а не «что происходит с агентами» |
| «История» `/tasks/:id` | та задача-центрична: одна задача, таймлайн + память. Активность — все задачи, без памяти |
| «Пульс» `/memory/pulse` | домен памяти, свои хранилища и scope |
| Логи/метрики | лента — метаданные фактов (переход, отчёт, запуск), не логи и не содержимое; тела отчётов — клип 200 знаков, как на wire |

## 2. Модель потока

Единая хронологическая лента **фактов**, новые сверху. Каждая строка несёт
пять ответов — ЧТО + ЗАДАЧА + КТО + ГДЕ + КОГДА:

```
[иконка типа] ЧТО (глагол факта) · ЗАДАЧА (ссылка, ?return=) ·
КТО (actor-бейдж: человек/устройство/агент/машина) ·
ГДЕ (хост, если известен) · КОГДА (относительное, absolute в title)
```

### 2.1 Типы событий v1 (словарь = audit-таблица + SSE, без изобретения нового)

| Семья | Виды | Иконка (lucide) | Акцент |
| --- | --- | --- | --- |
| Задача | `task.created`, `task.moved`, `task.updated`, `task.archived`, `task.unarchived` | `Plus`, `ArrowRight`, `Pencil`, `Archive`, `ArchiveRestore` | нейтральный (текст-secondary) |
| Исполнение | `assignment.created/claimed/started/done/failed/cancelled/expired` | `ClipboardList`, `Hand`, `Play`, `Check`, `X`, `Ban`, `Hourglass` | семантические токены: `done` → `--color-success`, `failed/expired` → `--color-error`/`--color-warning` (как бейджи UI-10) |
| Отчёт | `report` (intermediate/final) | `FileText`, финал — `Flag` | нейтральный; финал подсвечен |

Информация никогда не кодируется цветом одним: иконка + текстовый глагол +
бейдж (WCAG 1.4.1). Три фильтр-семьи (задача/исполнение/отчёт) — полный словарь
v1; остальное (`executor.*`, `pairing.*`, `provisioning.*`, `automation.*`) —
вне дефолтной ленты (§7).

### 2.2 ЧТО — глаголы (микрокопии строк)

Русские глаголы фактов, активный залог, без канцелярита: «создана»,
«переведена: в работе → решено» (имена колонок — существующий `COLUMN_RU` —
«в работе», «решено»…), «взята в работу», «исполнение начато», «завершено»,
«провалено», «отменено», «истекло», «отчёт (промежуточный)», «финальный
отчёт», «в архиве», «вернулась из архива», «правка деталей».

### 2.3 КТО — actor-грамматика (ADR 0012 Amd §A.5, формат не меняем)

| Actor на wire | Класс | Отображение |
| --- | --- | --- |
| `ui` | человек | бейдж «владелец» (в single-tenant борде ui-нога одна) |
| `device:<id> <name>` | устройство | бейдж с именем устройства (`<name>`; без id в строке — id в `title`) |
| `machine:board` | машина | «борд» |
| `machine:<executor_id>` | агент | имя из реестра `/api/executors` (resolve на клиенте по уже загруженному ростеру; fallback — сырой id) |
| `machine:reaper` / `machine:validation-sweep` | сервис | «фоновый сервис (reaper)» / «валидационный свип» |
| (нет actor — старые записи до 1.35.0) | — | строка без бейджа КТО — честная деградация, не заглушка «неизвестно» |

Класс виден и текстом (не только цветом бейджа): «владелец» / имя устройства /
имя агента. Для `assignment.*`/`report`, где actor-поля нет, КТО берётся из
declared identity самой строки (`created_by`/`claimed_by`/`report.agent`) —
это существующее поведение UI-10 (`feedItemFromEvent`), переносим без изменения
семантики.

### 2.4 ЗАДАЧА и ГДЕ

- ЗАДАЧА — ссылка `/tasks/:id?tab=…&return=<текущий URL активности с
  фильтрами>` (контракт UI-18, `withReturn` из `lib/returnParams.ts`): отчёт →
  `?tab=reports`, исполнение → `?tab=execution`, переходы статусов — сама
  карточка. Возврат обратно в ленту с её фильтрами обязателен.
- ГДЕ — хост исполнения: `executor_id` строки → `host` из реестра
  (`/api/executors`, поле присутствует у исполнителей; TTL-presence сюда **не**
  тащим — хост это факт места, не живость). Неизвестен (создание задач,
  удалённый исполнитель) — слот молча отсутствует.

## 3. Источник данных

### 3.1 Уже есть (нулевой серверный ценой)

- **Live**: `/api/events` (SSE) уже несёт **все** v1-виды: `task.*` с `actor`
  (14 сайтов эмиссии), `assignment.*` с embedded-поручением, `report` с
  агентом. Новых SSE-видов не нужно — дозаправка ленты идёт из существующего
  потока (подписка страницы через поток домена, паттерн `executionFeedStore`).
- **История**: audit-таблица `events` (`id` монотонный, `ts`, `kind`,
  `task_id`, `payload` с actor) — полный бэкфилл, включая терминальные
  переходы поручений (`store.py:2599`) и `task.report` (`store.py:2098`).

### 3.2 Новое — ТРЕБОВАНИЯ к серверу (не реализация): `GET /api/activity`

Агрегирующее чтение над `events` (проекция, не новый источник истины).

| Требование | Форма |
| --- | --- |
| Курсор | `before_id` (строго ниже — страницы стабильны при live-дозаправке) + `limit` (default 50, жёсткий кап 200 с silent clamp + `truncated: true` — конвенция `GET /api/reports`, CV-6; неположительный limit → 422) |
| Фильтры | `type=` (csv из словаря v1: `task|assignment|report` или точные kind'ы; мусор → 422 по конвенции kind-фильтра отчётов), `task_id=` (exact; неизвестная задача → пустая страница 200, не 404 — «фильтр, не ресурс»), `agent=` (матчит declared identity и `machine:<id>`), `host=` (best-effort: резолв исполнителя на чтение; исполнитель сменил хост — фильтр честно не матчит старое) |
| Строка ответа | `{id, ts, kind, task_id, task_title?, actor?, executor_id?, host?, detail?}`; `task_title` — best-effort join с задачами (удалена — поля нет, UI показывает сырой id); `detail` — клип 200 знаков |
| Политика actor | см. §7: для не-аутентифицированных ног поля `actor` НЕТ в ответе (server-side strip, additive-совместимо) |
| Bucket-вид (Ф2) | `?bucket=hour&hours=24` → `{buckets:[{ts, total, by_type:{task,assignment,report}}]}` — те же фильтры, те же классы доступа; один параметр, отдельного эндпоинта не нужно |
| Доступ | OPEN-чтение, как остальные листинги (граница — cluster ingress), с strip-правилом actor |
| Retention | единый с `events`; капа глубины — серверное решение (TTL/лимит строк — вынести на verdict TL), UI обязан уметь показать «дальше журнала нет» по концу курсора, не выдумывать свою глубину |

Явно **не** требуется: новых SSE-видов, записи новых событий,WebSocket,
агрегатных таблиц, поиска по тексту.

## 4. Визуализация (просьба владельца «в идеале»)

Два сдержанных варианта; смелость ровно в одном месте (канон §11) — лента
остаётся тихой.

### Вариант A — «Суточный пульс» (рекомендован, Ф2)

Компактная 24-часовая гистограмма над лентой: 24 одночасовых вёдра из
`?bucket=hour&hours=24` (на экранах <640px — 12 двухчасовых вёдер). Высота
столбика = число событий; сегменты внутри столбика — три семьи типов цветами
**существующих** токенов (задача — iris, исполнение — confidence, отчёт —
success) + текстовая легенда. Hover/focus — точные числа; каждый столбик —
кнопка с `aria-label` («14:00–15:00 — 12 событий: 3 задачи, 7 исполнений,
2 отчёта»), клик — фильтр ленты на этот час (`?from=&to=` в URL). Никакой
анимации роста при `prefers-reduced-motion` / `vesmaro.motion="reduced"` —
как и всё на страницах операций, гистограмма уважает оба режима (токены
`motionStore`).

### Вариант B — таймлайн-дорожки по агентам (отложен)

Swimlane'ы «исполнитель → полоса времени» смотрятся эффектно, но: поток у нас
— **точечные факты**, а не интервалы; дорожки требуют горизонтальной прокрутки
на мобиле и второй визуальной грамматики рядом с лентой. Цена высока, ценность
v1 — сомнительна. Не делаем сейчас (§8); если владельцу понадобится «кто чем
занят» — это ближе к ростеру «Хостов» с presence, чем к ленте.

### Каркас поверхности (desktop ≥1024px)

```
┌ TopBar: Задачи › Активность ─────────────────────── [● В реальном времени] ┐
│ Фильтры: [тип ▾] [агент ▾] [хост ▾] [задача: t-… ×]      (всё в ?params)  │
│ ┌ Суточный пульс (24ч) ──────────────────────────────────────── 24 бара ┐ │
│ │      ▂        ▄ ▆     ▂                        ▁ ▃ ▁                   │ │
```

Плотность — операционная (строки `--row-h`, гэп `--list-gap`, реагируют на

## 5. State-матрица (блокирующие находки недопустимы)

### 5.1 Страница

| Состояние | Условие | Вид |
| --- | --- | --- |
| loading | первый GET | скелет-строки (существующий паттерн `components/skeletons`), без layout-скачков |
| empty | 200, 0 строк (в т.ч. после фильтров) | честная пустота: «Активности пока нет — как только задачи и агенты зашуршат, события появятся здесь сами» (+для фильтров: «Под эти фильтры ничего не попало — сбросьте их»); без фейковых строк |
| error | GET упал | inline-блок с текстом «Не удалось загрузить активность» + кнопка «Повторить»; лента не заменяется заглушкой навсегда |
| live | SSE open | индикатор «В реальном времени» (точка + текст; не цветом одним) |
| degraded | SSE reconnecting | существующий амбер-паттерн UI-10: «данные на 14:32 — переподключаемся»; после reconnect — refetch (транспорт at-most-once, конвенция EventStream) |

### 5.2 Строка / дозаправка

| Состояние | Условие | Вид |
| --- | --- | --- |
| default / hover / focus-visible | — | как строки списков домена: hover — фон well→elevated (instant), focus — outline 2px `iris-bright` offset 2, не перекрыт (2.4.11); вся строка — цель ≥24px (2.5.8) |
| fresh | новое событие из SSE | flash-fade 2s **без сдвига строк** (паттерн `FRESH_MS` UI-10); `aria-live=off` на списке, терминальные — через скрытую polite-область |
| новые при прокрутке | пользователь не наверху ленты | строки НЕ подвигают контент: плашка «N новых событий — показать» сверху; клик — prepend + скролл к верху |
| буфер полон | клиентский кап 500 | тихая вытеска старейших в живом буфере; глубина добирается курсором «Показать ещё» |

| `activity.filter.task` | `Задача` | `Task` |
| `activity.chart.label` | `Активность за 24 часа` | `Last 24 hours` |
| `activity.chart.barAria` | `{{range}} — {{total}} событий: {{tasks}} задач, {{assignments}} исполнений, {{reports}} отчётов` | `{{range}} — {{total}} events: {{tasks}} task, {{assignments}} execution, {{reports}} report` |

Глаголы строк — §2.2; бейдж actor — §2.3. Тон — от лица системы, без
«упс/ой»; пустые состояния приглашают, не извиняются.

## 7. Границы

- **Ретеншн/объём**: глубина ленты = глубина `events` (кап — решение сервера,
  §3.2); страница ≤200; живой буфер ≤500. UI не имитирует бесконечную
  историю: конец курсора — честное «Это вся глубина журнала».
- **Приватность actor (предложение политики)**: факты (kind, задача, время,
  host, declared-identity отчётов) — OPEN-чтение, как все листинги;
  **атрибуция** (`actor`: устройство `<name>`, «владелец») — только
  аутентифицированным ногам `ui`/`mnd_` (header или cookie): сервер strip-ит
  поле из `/api/activity` для остальных (поле отсутствует — additive-контракт
  не ломается). Обоснование: audit-дисциплина ADR 0012 отвечает на вопрос
  «кто ездил на mnd_» — этот ответ не должен бесплатно читать гость LAN;
  машинные actor'ы (`machine:*`) не персональные и остаются. SSE — отдельный
  вопрос (там actor уже летит всем подписчикам потока): вынести на verdict TL,
  Ф1 не блокирует (лента умеет строки без КТО).
- **Вне словаря v1**: `executor.*`, `pairing.*`, `provisioning.*`,
  `automation.*`, `enrollment.*` — события życia борда, не задачного потока;
  доступны своими поверхностями. Корa `session.transcript_viewed` — **не**
  включаем: это аудит *чтения*, а не исполнения задач (приватность + другой
  адресат). Опционально в Ф2+: presence-переходы `executor.online/offline`
  только фильтром `?type=presence`, вне дефолтной ленты (шум).
- **Мобильное (минимум)**: одна колонка; строки переносятся (ЧТО+ЗАДАЧА+
  КОГДА в первой строке, excerpt скрывается); фильтры — в disclosure;
  гистограмма 12×2ч вёдер; тач-цели ≥24px; лента остаётся вертикальной —
  никаких горизонтальных скроллов.

## 8. Критерии приёмки (проверяемые) и что НЕ делаем

1. `/tasks/activity` в навигации «Задачи» между «Список» и «Входящие»; крошка
   «Задачи › Активность»; RU/EN (`nav.taskActivity`).
2. Строки ленты = ЧТО+ЗАДАЧА+КТО+ГДЕ+КОГДА; actor рендерится по грамматике
   §2.3 (включая fallback на id и честное отсутствие для старых записей);
   запись без actor не ломает строку.
3. Все ссылки drill-down несут `return=` (контракт UI-18): возврат из
   `/tasks/:id` восстанавливает URL активности с фильтрами (e2e: DOM равен).
4. Весь стейт списка в URL (`?type&agent&host&task_id&from&to`): direct-open
   по закладке воспроизводит вид; freeze-gate `TasksLayout.freeze.test.tsx`
   остаётся зелёным (страница внутри поддерева не ломает правило).
5. Фильтры `type/task_id/agent/host` применяются серверно (`/api/activity`);
   мусорные значения → 422 → честный error-state, а не тихая пустота.
6. Live-дозаправка из существующего SSE: новое `task.moved`/`assignment.done`/
   `report` появляется во ленте ≤2s, строки не сдвигаются (flash 2s);
   `aria-live=off`, терминальные — в polite-области.
7. Обрыв SSE: амбер-маркер «данные на HH:MM»; после reconnect — refetch
   (at-most-once); двойного потока EventSource нет (один поток на домен).
8. Курсор: «Показать ещё» дозагружает страницы без дублей при live-дозаправке
   (before_id-семантика); конец — честная подпись.
9. Empty-состояния: без фильтров и с фильтрами — по §5.1; loading-скелет без
   layout-скачков; error с «Повторить».
10. (Ф2) Гистограмма из `bucket=hour` согласована с лентой (одинаковые
    фильтры); каждый столбик — кнопка с `aria-label`; reduced-motion
    (media + `vesmaro.motion`) отключает анимации.
11. A11y: клавиатурный проход (фильтры → гистограмма → лента → «ещё»), фокус-
    кольца `iris-bright` видимы и не перекрыты, цели ≥24×24, тип не кодируется
    цветом одним (иконка+текст), контраст пар из `tokens.css` соблюдён.
12. Политика actor: анонимная нога GET получает ответ без поля `actor`
    (server-side strip); залогиненная ui/mnd_ — с actor.

**НЕ делаем**: swimlane-дорожки агентов (вариант B отложен); kora-аудит и
семьи `executor/pairing/provisioning/automation/enrollment` в дефолтной ленте;
поиск по тексту событий; экспорт/RSS; новые SSE-виды и новая запись событий;
новые цвета/шрифты/токены; ретеншн-UI (только честная подпись конца);
модификацию событий из ленты (лента read-only, действия — в задаче/канбане);
отдельный WebSocket.

## 9. Срез реализации

- **Ф1 — лента (~0.5 волны суммарно)**: сервер `GET /api/activity` (курсор,
  фильтры, strip-политика actor; bucket'ы не нужны) ~0.1–0.15; FE: стор
  GET+SSE-merge (паттерн `executionFeedStore`, но с бэкфиллом), страница
  `/tasks/activity`, навигация/крошки, i18n §6, state-матрица в тестах,
  e2e §4.2–4.9 ~0.3–0.4. Сервер может идти параллельно FE за контрактом-шейпом
  (mock-адаптер по конвенции недели 0).
- **Ф2 — визуализация (~0.2 волны)**: `bucket=hour` на сервере, «Суточный
  пульс», mobile-вариант 12×2ч, плашка «N новых», клик-фильтр часа
  (`?from&to`).
- Зависимости: Ф1 не ждёт ничего внешнего (SSE уже готово); Ф2 ждёт bucket-параметр.

## Self-review дизайнера (протокол two-pass)

**Пасс 1 (план)**: задачно-центричная лента фактов из `events` + live из
существующего SSE; actor-грамматика §A.5 как есть; гистограмма-24ч сверху;
фильтры в URL; `return=` на drill-down.

**Пасс 2 (самокритика)**: «это же второй UI-10?» — нет: UI-10 безысторичен
(ring-buffer вкладки, fresh page = empty) и агенто-центричен; Активность
обязана иметь историю (весь смысл «что происходит») и задачный ключ строки —
потому и нужен один агрегирующий GET, а не «просто покажем буфер». «Гистограмма
— не slop-дашборд?» — риск принят и смягчён: один смелый элемент на
поверхность, сегменты текстом в легенде и aria, клик ведёт в ленту (данные,
не украшение); если владелец сочтёт лишним — Ф2 отвязывается без ущерба Ф1.
«Плавающие» ответы сняты: пустота честная (не «данных нет»+спиннер), конец
журнала подписан, actor-дыры старых записей не маскируются. Отвергнуто в
пассе 2: показывать presence-точки агентов в строках (дублирует Хосты,
дороже поддержки, шум); автопреpend с сдвигом контента (враждебно чтению);
цветные полосы строк по типу (цвет-без-текста). Anti-slop: ноль новых
токенов/шрифтов, иконки lucide из существующего набора, плотность канбана;
идентичность поверхности — только «Суточный пульс», и та опциональна.
**Открытые допущения**: (1) actor в SSE остаётся открытым всем подписчикам
потока — если TL решит ужать до ui/mnd_, лента деградирует без ломки (п.12
проверяется тем же тестом); (2) `host`-фильтр best-effort (mutable-поле) —
если владельцу нужна строгая история «на какой машине *было*», это серверное
решение денормализации в events, вынесено за скоуп; (3) кап ретеншена `events`
— вердикт TL, UI-часть (честный конец) не зависит от цифры.
