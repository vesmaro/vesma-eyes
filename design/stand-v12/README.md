# Стенд «ВАУ v12» (ME-061, experiment/wow-v12)

Скаффолд + интеграция арт-направления `design/docs/15-WOW-DIRECTION.md`
(спека — источник истины; отклонения — ниже, «Отклонения от спеки»).

## Запуск

```bash
cd design/stand-v12
python3 -m http.server 8126
# вход: http://localhost:8126/overview.html (index.html редиректит сюда)
```

Порядок скриптов на страницах: `stand-v12.js → data.js → living.js →
synapse.js` (бутстрап режима обязан опередить парс living.js; synapse
ждёт `window.STAND`).

## Что взято из stand-v11-base

- `living.js` — байт-в-байт; шина `stand:feed-event`, словарь v2, Нейра
  с аксоном, курьеры, В3-карточка.
- `data.js` — байт-в-байт; демо-лента = единственный источник «жизни»
  между демо-нажатиями (`?demo=0` глушит).
- `synapse.js` — копия + правка плотности (единственная, санкционирована
  спеком §3.1 «Активы»).
- Продуктовые стили живого слоя (`.living-*`) — перенос без правок.
- Структурные хуки каркаса: `.topbar` (Ж1), `.topbar-status` + `.pill.live`
  (слот Нейры), `.sidebar` (Ж2), `.side-domain .side-label`
  «Память/Задачи/Агенты» (узлы-источники курьеров), `[data-exec-count]`.

## Дефолт «Полный» для концепт-стенда (§4)

`living.js` НЕ правлен (прод-дефолт остался `calm` — supersede гейтится
вердиктом владельца, 12 §1 п.6). Стендовский дефолт: `stand-v12.js` до
парса living.js ставит вкладочный оверрайд `stand-living-override=full`
— только если пользователь ничего не выбрал сам; `?living=` и выбор в
Настройках сильнее. Выключаемость: клик по Нейре / «Спокойный» /
«Выключен» / reduced — все четыре уровня живы.

## Демо-хуки шины

На `overview.html` (под тикером), `shell.html#living`, `tasks.html`:
кнопки `task.start / task.done / owner.wait / owner.clear / error`
публикуют события в единый `stand:feed-event` (08 §3.1). «error» бьёт
дважды (300ms) — карточка В3 после двух подряд. Пробуждение Обзора
публикует `write` (mem = M-233) на 1.4s — тот же издатель-уровень стенда,
не второй источник.

### Бюджеты волны 3 (честно)

- **living-extra чанк: 4418 байт gzip против бюджета 4096 (+8%)**.
  Причина: в песочнице нет terser/esbuild — минификация наивная
  (токен-склейка esprima, без property-mangling). Читаемый исходник —
  `js/src/living-extra.src.js` (минified `js/living-extra.js` — его сборка).
  Прогон terser в CI снимает превышение (оценка 3.2–3.6KB gzip).
- Бюджет кадра паутины: инструмент `window.__webFrameMs` (среднее за
  секунду); фиксация числа — в консоли при приёмке (статически: ≤120
  рёбер × sin + ≤50 arc — на порядок ниже 0.3ms).
- living-core (living.js 941 строка) — не тронут: 8 KiB-бюджет 07n §3 цел.

## Отклонения и аппроксимации (§8/§13: «не молча»)

Снятые вердиктами §13 (фиксируются как закрытые):
- ~~каскад пробуждения слоем-veil~~ → поштучная волна в движке (§13.1);
- ~~пауза тикера клик-перехватом~~ → тикер = данные, гасится только
  fade-swap по `data-living`/`aria-pressed` Нейры (§13.3);
- ~~крошки/редирект~~ → приняты (§13.5).

Живые отклонения (все — некритичные, оговорены спекой или выбраны FE):

1. **▸N свечение при task.done** (§13.8.3): living.js не экспортирует хук
   прибытия курьера (execBadgeGlow приватен, зовётся только для
   owner.wait) — данные инкрементируются сразу по событию, свечение
   синхронно с событием; комментарий в `tasks-v12.js`.
2. **Курьер по Ж4 для событий Эфира** (§3.2): маршрутизация словаря v11
   зашита в living.js (task.* — от строки «Задачи» по Ж2) — движок взят
   как есть, маршрут не менялся.
3. **Кора, топология Эфира** (§13.6.2): Эфир оставлен правой колонкой
   верхней зоны по ASCII §3.2, ширина фикс 320px, drag крыла убран;
   разделитель крыльев Пульта — hairline. Если дизайн-лид имел в виду
   Эфир крылом САМОГО Пульта — перестановка одной сетки, готов по сигналу.
4. **i18n** (§13.6.9): ключи kora.* собраны в комментариях модулей;
   i18n-слой в скаффолде отсутствует (волна 07n).
5. **Drag доски Задач**: отсутствует — борд заморожен по лору (M-189);
   «во время drag хореография не стартует» (§13.8.2) выполняется тривиально.
6. **Замер рендера палитры** (§13.7.6): инструмент встроен
   (`window.__paletteRenderMs`, console.debug); среда стенда безбраузерна
   на сборке — число фиксируется в консоли при приёмке (статически: ~80
   пунктов индекса, фильтр+DOM-рендер — на порядок ниже бюджета 80ms).
7. **Береста-окно** (§13.4/§12.2): ждёт владельца; герой наследует тему.
8. **Свёрнутый Пульт** (§13.6.7): порог ≤60px по Ж4 (drag/стрелки до
   40px) — v7-пороги восстановлены по смыслу, точные константы v7 не
   переносились.
9. **Общий ambient-планировщик** (§14.1): ротация Нейра→жилы живёт внутри
   living.js и не экспортируется — паутина держит собственный билет с
   фазовым сдвигом; объединение потребует санкционированной правки living.js.
10. **Раскладка графа паутины** — Math.random (детерминизм спеки — только
    якорь события по типу: выполнено hash-функцией).
11. **Кроссфейд статики <45fps** — двухканвасный (CSS opacity 240ms),
    в чанке; поведение по §14.1.
12. **Весма «показать»** — зов из UI (кнопка на Полигоне + API
    `window.Vesma.show/bring/call`); онбординг-зова в стенде нет (нет
    онбординга) — путь жив, триггер придёт с онбордингом.
