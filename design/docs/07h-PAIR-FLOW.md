# 07h — Подключение телефона: страница `/pair`

> Status: **v1.0, дизайн-лид, 2026-09-27**. Срез v3 стенда — вторая большая
> дыра: публичная страница подключения устройства. База: ADR 0012 (протокол
> QR-пейринга и device-токены, ратифицирован) + Amendment 2026-09-23
> (scope `control`, §A.7 гранулы) + прод-реализация (`PairPage` — нога
> устройства, `PairingDialog` — нога владельца, `/system/devices` — отзыв и
> гранулы). Словарь — `07a`; живые исходы — `07b` §5; страница вне Shell —
> канон ADR 0012 §2.3. Демо-фикстура связи со стендом: T-121 «Пейринг QR»,
> M-204 «Решение по пейрингу», M-340 «QR-окно 90 секунд» (кластер sealbox).
>
> **v1.1 (2026-09-27):** аддендум §12 — заметная кнопка возврата «На борт»
> у центрального блока во всех фазах (директива владельца по вердикту v3).

## 0. Честные расхождения с брифом (записаны до проектирования)

Бриф формулирует флоу как «подтвердите вход» **на телефоне** и «обычно 5–15
секунд». Ратифицированный протокол (ADR 0012 §2, Security-вердикт) устроен
зеркально: подтверждение — **на доверенной стороне** (экран владельца:
панель «запрос подключения» → [Подтвердить]); телефон после скана ждёт и
показывает verify-цифры для сверки. Обратное («тап-подтверждение на
устройстве») — это rejected-модель cloud-relay (zcode), не наша.

Решение: спека следует протоколу (подтверждение на экране владельца) и
пишет микрокопирайт телефона честно — «дождитесь подтверждения на экране
владельца». Если владелец хочет инверсию — это изменение ADR 0012, не UI-правка
(открытый вопрос в финальном отчёте).

Вторая поправка: брифовский таймер «QR истёк» — TTL протокола **3 минуты**
(ADR §6; M-340 фиксирует 90-секундное окно sealbox — это другой контур, не борд).
UI показывает TTL-дугу и «истёк → начните заново», никогда не мёртвый QR.

## 1. Страница: место и хром

- Роут `/pair` — **вне Shell** (прод-канон ADR 0012 §2.3): без сайдбара,
  сессии и статус-зоны; аутентифицированная страница и есть threat model
  публичной поверхности. Свой лаконичный хедер: знак ириса + заголовок
  «Подключение устройства» + тумблер темы ◐ (единственная настройка).
- Композиция: центральная колонка max-w-md, вертикальный ритм `--space-4`,
  фон `--color-bg-base`, карточка фокуса на `--color-bg-well` `--radius-lg`.
- Тема: тёмная по умолчанию, светло-совместимая (`[data-theme="light"]`,
  пары `02` §4). **QR-контраст ≥3:1 к подложке в обеих темах** (ADR §6,
  WCAG 1.4.11) — светлая «тихая» подложка под QR, не тёмная.
- Wake-lock по возможности: экран телефона не гаснет в активных фазах.

## 2. Фаза «до скана» (код получен с экрана владельца)

```
┌──────────────────────────────────────────────┐
│ ◉ Подключение устройства                  ◐  │
│                                              │
│  Отсканируйте QR камерой телефона            │
│  ┌────────────────────────┐                  │
│  │        [QR-код]        │  TTL-дуга: «истечёт через 2:14» │
│  └────────────────────────┘                  │
│  код: mne-XXXX-… [Копировать]  ← ручной путь │
│                                              │
│  1. Откройте на телефоне камеру              │
│  2. Наведите на код — откроется страница     │
│  3. Страница сама отправит код — подтвердите │
│     на экране владельца                      │
│                                              │
│  ▸ Что это даёт?                             │
└──────────────────────────────────────────────┘
```

- **3 шага-подсказки** человеческим языком (нумерованный список `--text-sm`,
  шаг 3 называет честного подтверждателя: «на экране владельца», §0).
- **QR большой** (≥240px, белый фон-плашка, quiet-zone 4 модуля), TTL-дуга
  + countdown mono tnum («истечёт через 2:14»). При `expires_at` локальные
  часы гасят QR: **затухание 240ms `--ease-exit`** → состояние «Код истёк —
  срок действия кода вышел (3 минуты)» + primary **«Запросить новый код»**
  (не мёртвая страница: новый POST /pairing). SSE `pairing.expired`/`revoked`
  и 10-секундный статус-полл закрывают разрыв (прод-механика диалога).
- **Ручной путь равноправен** (ADR §2 a11y, no-scanner): код mono, кнопка
  «Копировать», подпись «Нет камеры? Введите код вручную на странице
  vesmaro на телефоне». QR несёт alt-описание (URL-цель).
- **«Что это даёт?»** — свёрнутый блок (шеврон ≥24px, 240ms `--ease-enter`,
  состояние персистентно в сессии):
  «Телефон станет вторым экраном борта: смотреть память, задачи и сессии,
  двигать задачи и отвечать на входящие — с подтверждением владельца при
  подключении. Устройство видно в списке устройств, доступ отзывается в
  один шаг». Ссылка «как отозвать — в Настройках · Устройства».
- Инвариант ADR §3.5: **код и verify-цифры никогда не рендерятся в одной
  фазе** (код нужен устройству здесь; цифры появятся после скана).

## 3. Фаза «после скана» (exchange → 202 awaiting)

```
┌──────────────────────────────────────────────┐
│ ◉ Подключение устройства                  ◐  │
│                                              │
│  Код принят — ждём подтверждения             │
│  ┌────┐ ┌────┐ ┌────┐ ┌────┐                 │
│  │ 4  │ │ 7  │ │ 1  │ │ 9  │  ← verify, mono │
│  └────┘ └────┘ └────┘ └────┘                 │
│  Сверьте цифры с экраном владельца:          │
│  он увидит этот код при подтверждении.       │
│  Это защита от чужого кода — не пароль.      │
│                                              │
│  ● Ждём подтверждения на экране владельца…   │
│  (спиннер честный: автопроверка через минуту)│
│                                              │
│  [Проверить сейчас]                          │
└──────────────────────────────────────────────┘
```

- Состояние «Ожидаем подтверждение…» — честный спиннер 16px + строка
  постуры опроса: «Проверим ещё раз автоматически через минуту; кнопка
  работает и вручную» (прод-канон: устройство без сессии не жжёт попытки
  exchange — budget 5/10 мин). **Времянные обещания брифа («5–15 секунд»)
  не даём**: подтвердитель — человек на другом экране; вместо этого честная
  постура «через минуту / вручную».
- Verify-цифры крупно (14px-боксы → 56px, mono) + назначение одной строкой:
  «защита от чужого кода — не пароль» (честная семантика ADR §3.5).
- `role="status"` polite на смену фаз; спиннер не одинок — текст рядом.

## 4. Фаза «успех» (exchange → 200 issued)

```
● Телефон подключён
  Токен сохранён на этом устройстве — копировать его никуда не нужно.
  Откройте vesmaro на телефоне — увидите тот же борт: память, задачи,
  сессии.
  [Готово]
  права: control · действует до 27 окт (продлевается активностью)
```

- Итоговая зелёная карточка (канон `07b` §5.1): зелёный — только по факту
  200, не оптимизм.
- **Микрокопирайт по ADR 0012 §5**: токен сохранён на устройстве (никто
  ничего не переносит); кнопка «Скопировать токен» — демо-аффорданс для
  явного переноса в другое приложение этого устройства (прод-модель, три
  честных вердикта копирования сохраняются).
- Scope-строка человеческим языком: «полный доступ» для control / «только
  просмотр» для read + «действует до [дата] (продлевается активностью)»
  (sliding 30 д / hard 90 д, ADR §A.7). Точная дата — mono tnum.
- [Готово] → закрывает страницу-проводник на телефоне; путь в борт — через
  PWA/ярлык, страница не притворяется, что «вошла в систему».

## 5. Фаза «отказ / ошибка» (честные вердикты)

Формат `07b` §5.2: заголовок-вердикт + одна-две строки «что это значит» +
действия. Маппинг статусов прод-контракта:

| Случай | Заголовок | Что проверить / что произошло |
| --- | --- | --- |
| 403 (чужой IP) | «Код привязан к другому адресу» | «Скан должен идти с той же сети, где открыт борт. Если вы в VPN — подключитесь к ней» |
| 404 | «Неизвестный код» | «Проверьте код — возможно, опечатка при ручном вводе» |
| 410 (истёк/использован) | «Код истёк или уже использован» | «Код живёт 3 минуты и работает один раз. Запросите новый на экране владельца» |
| 429 | «Слишком много попыток» | «Подождите ~10 минут — лимит защиты от подбора» |
| 503 (pairing off) | «Подключение отключено на сервере» | «Владелец выключил пейринг или не настроил вход. Проверьте на экране владельца» |
| отказ владельца | «Подключение отклонено» | «Владелец отклонил запрос: устройство не получит доступ, код погашен» |
| сеть/сбой | «Подключить не удалось» | «Сервер не ответил. Проверьте сеть и повторите» |

Кнопки: [Ввести код заново] (на форму) / [Запросить новый код] (если
уместно). Ничего не зависает молча — каждый терминал имеет выход.

## 6. State-матрица QR-блока и страницы (блокер-канон `05`)

| Компонент | Матрица |
| --- | --- |
| **QR-блок** | loading («Загружаем QR…») / live (QR + TTL-дуга) / expiring (≤20 с — дуга warning, текст тот же) / expired (затухание + «Запросить новый код») / revoked (SSE: «Владелец отменил пейринг» + выход на форму) / reduced-motion (затухание — мгновенное, дуга статична) |
| **verify-карточка** | default (4 цифры) / waiting (спиннер + постура) / success (переход §4) / rejected (§5) / expired (§5) |
| **Форма ручного кода** | поля `05` §2.5 (клик-цель ≥24px, мобильный 44px) / busy («Подключаем…», повторный клик заблокирован) / error (вер­дикт §5 инлайн, не тостом) |
| **«Что это даёт?»** | collapsed / expanded (персистентно) / focus на шевроне |
| **Хедер + тумблер темы** | default/hover/focus-visible; тема применяется мгновенно, без анимации (смена темы `06` §2 in-out ≤150ms) |

A11y: страница — один `main` + H1; фазы объявляются `aria-live="polite"`
(заголовок фазы меняется, контент перерисовывается); verify-группа —
`role="img"` с aria-label «Код подтверждения: 4 7 1 9»; QR — alt «QR-код
подключения: открывает vesmaro на телефоне»; фокус-ринг `--color-focus`
на тёмной и светлой (8.2:1 / 7.3:1); все клики ≥24×24.

## 7. Motion (канон `06`)

- Смена фаз: вход 240ms `--ease-enter`, выход `--ease-exit`; reduced-motion —
  мгновенно.
- TTL-дуга — плавная по секундам; при reduced-motion — статичный текст
  countdown без анимации дуги.
- Затухание истёкшего QR — 240ms opacity (не «мигание», не «встряска»).
- Спиннер ожидания — единственный живой элемент фазы; glow-бюджет: ни одного
  источника на странице, кроме focus-ринга (страница публичная — свет не
  декорирует секреты).

## 8. Security-микрокопирайт (канон ADR 0014/0012)

Правило: каждое обещание безопасности — одной строкой, человеческим языком,
в момент, когда вопрос возникает; абзацы-дисклеймеры запрещены (канон `07a` §6).

| Момент | Строка |
| --- | --- |
| «Что это даёт?» | «Управлять бортом с телефона: смотреть память, задачи, сессии; изменения — с правами, которые выдаёте вы» |
| после скана (verify) | «Это защита от чужого кода — не пароль» |
| успех | «Токен сохранён на этом устройстве. Никто не должен был его копировать» |
| успех (scope) | «полный доступ» / «только просмотр» + «действует до [дата] (продлевается активностью)» |
| как отозвать | «Отзыв — в Настройках · Устройства: один шаг, доступ пропадает сразу» |
| TTL | «Код живёт 3 минуты и работает один раз» |

Ссылка на `/system/devices` в тексте успеха и в «Что это даёт?» — путь
отзыва всегда виден с обеих сторон пейринга. На странице устройства
(гранулы, ADR §A.7) микрокопирайт не дублируется — там свой канон, здесь
только обещание места.

## 9. Связка с ногой владельца (вне этой спеки, для целостности)

Владелец-side флоу («Подключить устройство» → QR → панель запроса с именем,
IP и verify → [Подтвердить]/[Отклонить]) описан прод-реализацией
`PairingDialog`; стенд-срезу достаточно, чтобы экран владельца на стенде
(`/system/devices`-слот) следовал тому же словарю: «запрос подключения»,
«сверьте четыре цифры», «устройство подключено». Расхождений словаря между
сторонами быть не должно — таблица §8 — общий источник.

## 10. WCAG 2.2 AA — именованные критерии

- **1.4.11 Non-text Contrast**: QR ≥3:1 к подложке, TTL-дуга и точки фаз ≥3:1.
- **1.4.3 Contrast**: все строки по парам `02` §4 (worst-case light: muted 4.8:1).
- **2.4.7 / 2.4.11**: ринг не перекрыт (страница без sticky-шапок — offset 2px).
- **2.5.8 Target Size**: копирование кода, тумблер темы, «Проверить сейчас» ≥24×24 (мобильный 44px — вся страница и есть мобильный сценарий).
- **3.3.1 Error Identification / 3.3.3 Error Suggestion**: вердикты §5 — текстом
  с «что проверить», не цветом и не тостом.
- **4.1.3 Status Messages**: смена фаз — polite; успех — `role="status"`.

## 11. Самокритика (проход 2)

- **Риск «инструкции ради инструкции»**: три шага-подсказки нужны только тем,
  кто видит страницу первый раз; после первого успеха стенд их не прячет, но
  они компактны и не двигают фокус — проверено против правила «пустые
  состояния зовут к действию»: здесь действие одно (скан), подсказки его не
  заменяют.
- **Риск «фейковой безопасности»**: страница не рисует замки и бейджи
  «защищено»; честность — в формулировках (§8) и в отказе от verify-инвара
  в одной фазе с кодом. Проверка «сними бренд»: флоу опознаётся по
  «TTL-дуга + честный подтверждающий на другой стороне + вердикты вместо
  зависаний» — не сводится к WhatsApp-деску и zcode-релэю (иная топология).
- **Риск расползания TTL**: все числа из контракта (3 мин, 5/10 мин, 30/90 д)
  — UI не хардкодит обещания, кроме тех, что в строках §8 как копирайт
  контракта; смена TTL сервером = правка строк i18n, не механики.
- **Расхождение с брифом (подтверждение на телефоне)** — зафиксировано в §0;
  спека не проектирует фичу, противоречащую ратифицированному протоколу,
  но оставляет владельцу явную точку решения.

## 12. Аддендум v1.1 — кнопка возврата «На борт»

> Директива владельца (вердикт v3, 2026-09-27): выход нашёлся только в правом
> верхнем углу («На борт») — «капец неочевидно». Страница публичная и вне Shell
> (§1): крошек, сайдбара и привычной навигации нет, заблудиться проще всего
> именно здесь. Возврат — главное действие после «передумал», поэтому он
> получает заметный контрол у центрального блока, а не мелкую ссылку по краю.

### 12.1 Решение

Кнопка **«← На борт»** живёт в центральном блоке во **всех фазах** в одном и
том же слоте — не мигрирует между фазами (мышечная память):

| Фаза | Позиция кнопки |
| --- | --- |
| до скана (§2) | над карточкой QR, сразу под заголовком страницы |
| ожидание (§3) | тот же слот — кнопка стоит на месте |
| успех (§4) | тот же слот, над зелёной карточкой; [Готово] остаётся главным завершением фазы |
| отказ / ошибка (§5) | тот же слот; рядом [Ввести код заново] / [Запросить новый код] |

- **Анатомия**: иконка lucide `arrow-left` 16px + лейбл «На борт» (`--text-ui`
  medium); высота **44px** (страница и есть мобильный сценарий — 2.5.8),
  радиус `--radius-md`, цель ≥44×44.
- **Стиль — primary-outline, заметно, но не первично**: контур `--color-iris`
  1.5px, текст `--color-iris-bright` (9.1:1 dark / 5.9:1 light — AA), hover —
  фон `--myelin-strong`, active — тинт `--strata-system`, focus — ринг
  `--color-focus` 2px/2px. Не solid-заливка: первичное действие фазы
  (QR-скан, «Запросить новый код», «Готово») остаётся главным — возврат
  «цветной второй», как и просил владелец.
- **Ссылка в правом верхнем углу остаётся** — вторичной (ghost, muted):
  для привычки «выход справа сверху». Кнопка и ссылка ведут в одно место
  (`/`) — конфликта целей нет.
- **Поведение**: переход на `/` без подтверждений — «передумал» это чистый
  выход; введённый код не сохраняется; повторный вход по истории возвращает
  в текущую фазу (URL-first, канон `03` §1).

### 12.2 A11y и копирайт

- `aria-label`: «На борт — вернуться на главную» (иконка не одна — 1.4.1).
- Состояния — матрица кнопки `05` §2.1 (outline-вариант) без особенностей;
  loading не нужен — переход мгновенный.
- Копирайт по правилу 5 секунд: «На борт» понятно без подсказки и согласовано
  со страницей — слово уже живёт в «Что это даёт?» (§2, «вторым экраном
  борта») и в существующей верхней ссылке; термин не вводится заново.

### 12.3 Самокритика

- **Риск конкуренции с QR**: крупная кнопка над QR может увести до скана.
  Принято: outline вместо заливки, слот над карточкой читается как навигация,
  а не как шаг флоу. Проверка на стенде: если сканы просядут — кнопка
  уменьшается до 40px, но не исчезает (решение владельца).
- **Проверка «сними бренд»**: возврат-кнопка над карточкой — общий паттерн
  онбордингов; отличие — честная топология (кнопка ведёт в борт, а не
  «назад» на ту же страницу) и сохранённый привычный выход справа сверху.
