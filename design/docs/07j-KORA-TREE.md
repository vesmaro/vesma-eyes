# 07j — Кора: дерево сессий v5 (модель, планировка, пульт)

> Status: **v1.0, дизайн-лид, 2026-09-28**. Supersede `07d` и `07i` в части
> модели сессий и планировки страницы. Две силы: директива владельца
> (2026-09-28, вечер) и огрехи «Первого пользователя» (прогон 2026-09-28).
> Директива: (1) нет наследованной цепочки «Хост → Список Агентов → Сессии
> каждого агента → Общие сессии» — общие сессии живут узлом на уровне хоста;
> (2) рабочая зона по умолчанию развёрнута и центральная; (3) сессии — в правую
> панель, вторым блоком после «Хостов и агентов»; (4) нижняя панель остаётся,
> но с другим функционалом — «Пульт» (Эфир + Дайджест). База: `07a` (словарь,
> правило 5 секунд), `07c` (принцип «жизнь»), `03` (IA), `05` (компоненты),
> `06` (motion), `02` (токены). Кода не содержит: реализация —
> `@gcw-senior-frontend-developer`; фикстуры — те же руки, по §2 этой спеки.

## 0. Что меняется против 07d/07i

| Было (07d/07i) | Стало (07j) |
| --- | --- |
| Сессия = {host, harness, state, line} | сессия = {id, host, агент-экземпляр, **имя**, state, started, lastActivity, topic, shared} (§1) |
| Центр = список сессий, транскрипт по клику за 1–2 шага | центр = **рабочая зона, всегда развёрнута**: транскрипт выбранной сессии; без выбора — Эфир (§3.1) |
| «Открыть полностью» ведёт на ту же страницу, дублируется | удалено; ссылка на сессию — одна, в «О сессии» (§3.4) |
| Инфо-карточка вместо контента (07i «б») | детали — свёрнутый блок «О сессии» вверху Блока 2; контент никогда не перекрывается (§3.4) |
| Док внизу = «Рабочая область», транскрипт | низ = **«Пульт»**: вкладки Эфир \| Дайджест + бейдж «ждут владельца» (§4) |
| Глобальная легенда «Покрытие» в центре | «Что мы видим с ваших машин», свёрнутый блок внизу правой панели (§3.5) |
| Демо-времена руками, счётчики руками | «счётчик = производная фикстур»; все времена из offsets (§2) |
| Мёртвый ввод «Ввод появится позже» | удалён; строка честности у свитка остаётся (§4.5) |

Что переносится дословно из 07d (не переизобретаем): строка-сводка с
кликабельными числами (§6), пустые состояния (§4), честная coverage-строка
свитка (§3), канон свитка (Lora, ≤72ch, mono-времена, живая догрузка снизу),
инструменты чтения «Следить за хвостом»/поиск/копирование (07i §4) — живут
в рабочей зоне центра, не в Пульте.

## 1. Модель данных v5

### 1.1 Сущности

```
Session {
  id: "sess-…"              // только в деталях (07a §1.4)
  host: имя хоста
  agent: harness-экземпляр  // { харнес, хост }: «zcode на laptop-go-1»
  name: человеко-имя        // задача («Командная: UI-10») или первая реплика
                            // владельца, ужатая до ≤48 знаков
  state: "идёт" | "завершена" | "прервана"
  startedMinAgo, lastActivityMinAgo   // offsets от якоря «сейчас» (§2.2)
  topic: задача или первая реплика целиком   // для «О сессии»
  shared: bool
  participants: [harness-экземпляры]  // только если shared
  coverage: "full" | "partial" | "none"
  digest?: { этапы[], решения[], память[] }   // §4.3
  transcript?: [{ minFromStart, who, text }]
}
```

- **Агент** в дереве = harness-экземпляр (харнес+хост): то, через что на
  машине идёт работа. Узел подписан именем харнеса («zcode», «core»); слово
  «агент» в заголовке блока получает пояснение при первом показе (§3.3).
- **Общая сессия** (`shared: true`) — командная работа нескольких агентов в
  одном эпизоде. Живёт **только** в узле «Общие сессии» её хоста; под
  участниками **не дублируется** (иначе дубли в счётчиках и в дереве).
  Участники перечислены текстом в строке и в «О сессии» (никогда цветом одним).
- Имя сессии — производная, не ручное поле: если сессия привязана к задаче —
  «Командная: UI-10» (для shared) или имя задачи; иначе — первая реплика
  владельца, ужатая до 48 знаков. Правит огрех «два раза laptop-go-1 · zcode»:
  «хост · харнес» остаётся только вторичной mono-подписью источника.

### 1.2 Дерево (замена наследованной цепочки)

```
Хост (piлюля связи, 07a §4)
├─ Агент: zcode · laptop-go-1  ── личные сессии агента
├─ Агент: core · laptop-go-1   ── личные сессии агента
└─ Общие сессии · N            ── shared-сессии этого хоста (узел хоста)
```

Правила:
- один экземпляр сессии в дереве — ровно одно место (под агентом или в
  «Общих сессиях»);
- пустой узел «Общие сессии» не рендерится (канон «пустой слот не рендерится»,
  `07c` §3);
- хост без агентов показывается строкой с объяснением состояния («агент ещё
  ставится», «выключен владельцем») — тупиков в дереве нет;
- клик по имени агента → Блок 2 в контексте «сессии агента»; клик по имени
  хоста → контекст «все сессии хоста» + строка хост-инфо; шеврон — раскрытие
  ветки. Две цели на строку: [шеврон ≥24px] [имя-кнопка].

### 2.2 Правило «счётчик = производная фикстур» (фикс P1-счётчика и P2-времён)

1. Фикстуры хранят **offsets** (`startedMinAgo`, `lastActivityMinAgo`,
   `minFromStart` реплик), а не строки времени. При загрузке страницы якорь
   «сейчас» фиксируется, все времена — вычисленные: «открыта 41 мин», «вчера
   18:04» = anchor − offset. Противоречие «реплики живой сессии за 18:04»
   невозможно по построению.
2. Транскрипт живой сессии sess-41a2: реплики на offsets 0, 2, 5, 5, 9, 23,
   24, 39 минут от старта (≤41 — директива); последний ход = 39 мин от старта
   = «активность 2 мин назад». Содержимое прежнее (разбор падений → моки →
   fake timers → 41 тест зелёный) + финальная пара: «вы: обнови память по
   итогам» → «zcode: записал в память: правки токенов, 41 тест зелёный»
   (даёт Дайджесту ссылку в Память, §4.3).
3. Все числа на странице считаются рантаймом из этих же фикстур и в HTML не
   пишутся руками: строка-сводка (§3.2), «за 24 ч» (offset < 1440), счётчики
   узлов дерева, бейдж «ждут владельца» (из фикстур задач: N = 1), счётчик
   Эфира. Правило канонизируется: **число в разметке = баг ревью**.
4. Производная сводки (демо): «1 хост на связи · 1 молчит · 2 сессии идёт ·
   за 24 ч: 5» — sess-2e55 (25 сент) и sess-7f13 (26 сент) в окно не попадают,
   что и чинит огрех «24 ч: 3 при сессии двухдневной давности».

### 2.3 События Эфира

Эфир — **проекция тех же фикстур** (открытия, реплики, завершения, сигналы
связи), не второй набор данных. Демо-лента (сверху новые):

| Возраст | Событие | Импульс (06 §5) |
| --- | --- | --- |
| 2 мин | zcode на laptop-go-1 записал итог в память | write (золото) |
| 4 мин | core на laptop-go-1 продолжил «Командную: UI-10» | write |
| 12 мин | pi на vpnus-1 доложился после паузы | recall (ирис) |
| 26 мин | zcode и core начали «Командную: UI-10» | write |
| 41 мин | zcode на laptop-go-1 открыл сессию «Правка тестов токенов» | write |
| 1 ч 12 мин | hermes на vpnus-1 завершил «Утренний прогон задач» | recall |
| 4 мин ◆ | vpnus-1 молчит 4 мин — проверить связь | error (красный) + [Проверить связь] |

Формат строки: [возраст mono tnum] [точка цвета события] [«<харнес> на <хосте>
<сделал что>» — активный залог, человеческие имена, задачи в кавычках-ёлочках,
без id]. Сигналы связи (молчит/на связи/проверить) — события того же потока.

### 3.2 Шапка и сводка

Без изменений от 07d §6, плюс: фильтр хоста — **один на страницу** и действует
на Блок 2, Эфир и подсветку дерева (чужие хосты приглушаются, выбранный
подсвечен; дерево не скрываем — ориентиры не теряются). Это закрывает и
огрех «переключатель игнорирует фильтр». Числа сводки кликабельны к
quick-фильтрам Блока 2 («идущие», «за 24 ч»), считаются из данных (§2.2).

### 3.3 Блок 1 «Хосты и агенты» (верх правой панели)

- Заголовок caps «ХОСТЫ И АГЕНТЫ» + строка-пояснение при первом показе:
  «Агенты — программы, через которые на машине идёт работа: например, zcode»
  (снимает конфликт со словарём 07a §2, где «агент» = служба).
- Дерево §1.2: хосты с пилюлями связи (07a §4: точка + текст: «на связи ·
  доклад 12 с назад», «молчит 4 мин», «выключен владельцем», «ставится…»).
- У агента — счётчик сессий mono muted («· 2»); у «Общих сессий» — тоже
  («· 1»). Узел «Общие сессии» получает подпись при первом показе: «Одна
  сессия — несколько агентов: командная работа».
- Раскрытие — nested disclosure (§6.2), состояние веток персистентно в
  сессии браузера.

### 3.4 Блок 2 «Сессии [контекст]» (низ правой панели)

- Заголовок: «СЕССИИ · все» / «СЕССИИ · zcode на laptop-go-1» /
  «СЕССИИ · laptop-go-1» — контекст всегда назван словами (recognition over
  recall). При контексте хоста над списком — строка хост-инфо: пилюля связи +
  [Открыть карточку хоста] (hosts.html?host=…).
- Строка сессии: **имя** (`--text-ui`, главная) + пилюля состояния (точка +
  «идёт · 41 мин» / «вчера 18:04» / «прервалась 3 ч назад» — состояние
  видно в любом режиме, фикс P3) + для shared — «zcode + core» текстом.
  Возраст — mono tnum. «хост · харнес» — не повторяем: контекст уже в
  заголовке (в «все» — вторичная подпись mono muted).
- Сортировка: идущие сверху, далее по lastActivity; список уважает фильтр
  хоста всегда. Пустые состояния — таблица 07d §4 дословно.
- **«▸ О сессии»** — свёрнутый блок вверху Блока 2 (решение против таба:
  таб съедал бы высоту списка постоянно, disclosure — по требованию; детали
  не вместо контента, а рядом). Внутри: полное имя и topic, точное время
  старта/активности (tooltip), участники (shared), «Покрытие этой сессии»
  (полная формулировка по участникам), [Скопировать ссылку на сессию]
  (`/kora?session=<id>` — единственное место ссылки; кнопок «Открыть
  полностью» больше нет: центр уже полный), «▸ Технические детали»
  (id `sess-…`, источник-сканер, границы, «Управление: в планах» — без
  «срез 3 (ADR 0019)»: атрибутика уходит в i18n-комментарии и дизайн-док).
- Если выбранная сессия вне текущего контекста — над списком строка-ссылка
  «Сейчас открыта: <имя>» (выбор не теряется молча; фикс родственный P3).

### 3.5 Покрытие: два имени вместо двух «Покрытий»

| Блок | Имя | Где |
| --- | --- | --- |
| Глобальная легенда | **«Что мы видим с ваших машин»** | свёрнутый блок внизу правой панели (после Блока 2); содержимое — таблица 07d §5 + строка «Покрытие растёт по мере готовности сканеров»; формулировки без слова «скоро»: «полный ход появится по мере готовности сканеров» |
| Сессия | **«Покрытие этой сессии»** | строка в шапке свитка (07d §3) + полная формулировка в «О сессии» |

## 4. Пульт (нижняя панель)

### 4.1 Роль и рамка

Нижняя панель остаётся, функционал другой (директива 4; вердикт пользователя).
Имя — **«Пульт»**, пояснение при первом показе: «Пульт — лента событий и
разбор сессии». Caps-лейбл «РАБОЧАЯ ОБЛАСТЬ» упразднён: рабочая зона — центр,
и она не нуждается в вывеске. Высота развёрнутого Пульта: `clamp(200px, 30vh,
320px)`; сворачивается в полосу 48px (как 07i §3 — один header-элемент,
высота фиксирована, live-обновления тинтами, `--radius-lg`, `--shadow-float`,
фон `--color-bg-well`).

### 4.2 Вкладки и умный дефолт

- Вкладки — сегмент-контрол (`05` §2.1-кнопки + selected): **[Дайджест |
  Эфир]**. Справа — бейдж **«ждут владельца: N»** (mono, из фикстур задач;
  клик → `/tasks/inbox`; виден всегда, на полосе тоже).
- Умный дефолт: нет выбранной сессии → Эфир уже в центре, Пульт — полоса с
  приглашением «Выберите сессию — её разбор появится здесь» (некликабельная
  часть полосы не претендует на действие; бейдж кликабелен). Выбор сессии →
  Пульт разворачивается на вкладке **Дайджест**.
- Персист: `vesmaro.koraPanel = "digest" | "ether"` — пишется только явным
  кликом по вкладке; заданное значение приоритетнее умного дефолта при
  последующих выборах. Смена сессии внутри (Б) вкладку не переключает.
- Эфир существует **в одном месте за раз**: в (А) — центр; в (Б) — вкладка
  Пульта (та же лента, компактный рендер). Дублей нет (правило 07i §6).

### 4.3 Дайджест (вкладка выбранной сессии)

Авто-сводка выбранной сессии — производная транскрипта; в стенде фикстурная
выжимка (`digest` в модели §1.1):

```
ДАЙДЖЕСТ · Правка тестов токенов
ЭТАПЫ: 1. разобраны 3 падения · 2. порядок моков поправлен ·
3. fake timers вместо таймаута · 4. прогон: 41 тест зелёный
РЕШЕНИЯ: fake timers вместо sleep; тесты не переписывались
ПАМЯТЬ: запись «Порядок моков в tokens.test»  [Открыть в Памяти]
```

- «Упомянутые записи памяти» — строки-ссылки в `memories.html`; id `M-…`
  только в tooltip/деталях (07a §1.4).
- Пустые состояния не-тупики: нет выжимки у идущей сессии — «Разбор появится,
  когда сессия наберёт ход»; терминал не сканируется — «Этот терминал пока не
  сканируем — разбора не будет, пока сканер не готов» + ссылка «Что мы видим
  с ваших машин»; сессия не выбрана — приглашение §4.2.

### 4.4 Эфир (вкладка и центральная лента)

Лента §2.3: новые строки всплывают сверху, без дёрганья (§6.3); фильтр
хоста — общий (§3.2); импульс цветом события — только на реальное событие,
дублируется текстом (06 §5). Сигналы «молчит N мин» несут [Проверить связь].

### 4.5 Что убрано из низа

Мёртвый ввод «Ввод появится позже» — удалён (фейковая консоль была смелым
местом 07i; смелое место теперь Пульт). Строка честности «Управлять сессией
отсюда пока нельзя — только читать. Это в планах» остаётся одной строкой под
свитком в центре (07a §3.5). «Следить за хвостом» и поиск — в тулбаре рабочей
зоны центра, не в Пульте. Командный ввод — не в v5 (срез 3). Заметки
владельца — вне v5, не упоминаем.

## 6. A11y и motion

### 6.1 A11y

- **Live-region**: `#kora-live` (`role="status"`, `aria-live="polite"`,
  `sr-only`) — первым элементом после `<body>`, до любых `<script>` (фикс P2).
- **Дерево — nested disclosure, не `role="tree"`** (решение по простоте):
  хост/агент — кнопка-имя + кнопка-шеврон (`aria-expanded`/`aria-controls`),
  сессии — вложенный `ul`. Без roving tabindex и стрелочной механики; Tab-стоимость
  (~27 стопов при полном раскрытии) приемлема для дерева из 4 хостов и гасится
  свёрнутым дефолтом (раскрыты хосты с активными сессиями).
- **Фокус при выборе сессии** (из дерева или Блока 2) → заголовок рабочей
  зоны (H2 `tabindex="-1"`), announce polite: «Открыта сессия: <имя>». Esc
  снимает выбор, фокус → строку сессии (лестница 03 §7).
- Aria-роли: Блок 1 — `nav aria-label="Хосты и агенты"`; Блок 2 — список
  `role="list"`, строки-кнопки с полным текстом; рабочая зона — `region
  aria-label="Ход сессии"`; Пульт — `region aria-label="Пульт"`; вкладки —
  `role="tablist"/tab/tabpanel` с `aria-selected`.
- Live-слои: новые реплики свитка — `aria-live="off"` (07d); Эфир —
  `role="log"`, `aria-live="off"` (лента шумная), смена сессии/вкладки —
  `polite`; состояние всегда точка + текст (1.4.1).
- Клавиатурный путь: фильтр → сводка → Блок 1 → Блок 2 → центр → Пульт;
  ловушек нет (2.1.2); бейдж, [Проверить связь], вкладки, шевроны — цели
  ≥24×24 (44 на мобильном).

### 6.2 Motion (канон 06, токены без исключений)

| Что | Как |
| --- | --- |
| Раскрытие ветки дерева | 150ms `--duration-fast` + `--ease-enter`; сворачивание — `--ease-exit` |
| Смена сессии в рабочей зоне | crossfade `--duration-normal` (250ms; директивные 240ms — нижняя граница окна токена, отдельное значение не вводим — прецедент 07i §12) + `--ease-in-out`; высота центра не прыгает: скелетон 2 абзацев на loading |
| Раскрытие/сворачивание Пульта | `--duration-normal` + enter/exit; полоса не меняет высоту сама |
| Эфир: новая строка | всплытие сверху 240ms `--ease-enter`, сдвига остального нет (слот под строку резервируется); reduced — мгновенно |
| Вкладки Пульта | тинт `--duration-instant`, без геометрии |
| Подсветка/приглушение дерева при фильтре | opacity-тинт `--duration-fast` |
| reduced-motion | всё выше — мгновенно/opacity ≤80ms; импульсы → статический тинт 1.5s (06 §7) |

## 8. Мобильный (<768px) и плотности

- ≥1024px: правая панель 320–360px, центр flex-1, Пульт на всю ширину контента.
- 768–1024px: правая панель → дровер поверх (кнопка «Хосты и сессии» в шапке);
  Пульт на всю ширину.
- <768px: Пульт — bottom sheet (сворачивание кнопками ≥44px); дерево —
  карточный вид; свиток ≤72ch сохраняется; все цели 44px.
- Плотность операционная (дерево, Блок 2, Эфир); свиток и Дайджест —
  созерцательные (Lora), как 07d §1.

## 9. WCAG 2.2 AA — именованные критерии

- **1.4.3 Contrast**: пары `02` §4; вторичная mono-подпись источника — muted
  на well ≥4.5:1.
- **1.4.11 Non-text Contrast**: точки пилюль, selected-край строки, вкладки.
- **1.4.1 Use of Color**: состояние сессии/события Эфира — всегда точка +
  текст; участники общей сессии — текстом.
- **2.4.7 / 2.4.11**: фокус при выборе уходит в заголовок рабочей зоны —
  под поверхностями сфокусированного не остаётся; ринг offset 4px на
  плавающем Пульте.
- **2.5.8 Target Size**: шевроны и вкладки ≥24×24, мобильный 44.
- **2.1.2 No Keyboard Trap**: Esc-лестница (Пульт → выбор → ничего).
- **4.1.2 Name, Role, Value**: `aria-expanded`/`aria-controls` disclosure,
  `aria-selected` вкладок.
- **4.1.3 Status Messages**: смена сессии/вкладки — polite через `#kora-live`,
  который в разметке раньше скриптов.

## 11. Самокритика (проход 2)

- **Снял бренд**: опознаваемые знаки v5 — «узел „Общие сессии“ у хоста» +
  «имя сессии = первая реплика владельца» + «Пульт с умным дефолтом Эфир/
  Дайджест». Не сводится к Slack-сайдбару (дерево — хосты/харнесы, не люди),
  к IDE-доку (док упразднён), к SaaS-киту (счётчики-производные вместо
  статик-чисел).
- **Риск двух Эфиров** (центр в (А) и вкладка в (Б)): снят правилом «один
  экземпляр ленты за раз» (§4.2) — противоречие между «центр показывает
  Эфир» и «Эфир во вкладке Пульта» разрешено явной посадкой по состоянию;
  вынесено открытым вопросом владельцу.
- **Риск дерева-овершеллинга**: 4 хоста × ветки могут дать простыню.
  Митигация: дефолтно раскрыты только ветки с активными сессиями, счётчики
  у свёрнутых узлов, «Общие сессии» не рендерится пустым.
- **Риск «имя = первая реплика» даёт длинные строки**: лимит 48 знаков с
  ellipsis и полным topic в «О сессии»; перенос строки запрещён — плотность
  списка сохраняется.
- **Токен-дисциплина**: 240ms директивы посажены на `--duration-normal`
  (250ms, окно 240–400) — магических значений не вводим; 30vh Пульта —
  layout-значение директивы, не motion-токен.
- **i18n**: все новые строки — ru/en одним PR (07-INTEGRATION §3); паритет
  словаря «Пульт/Эфир/Дайджест/Общие сессии» обязателен.
