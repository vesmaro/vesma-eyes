## 1. Структура страницы

Заголовок: **«Кора · сессии хостов»**. Под ним одна строка: «Кора — журнал
сессий: что агенты делали и что говорили. Записи только для чтения.»

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ Кора · сессии хостов      [Фильтр: ▾ Все хосты]  [Проверить связь]          │
│ ┌─ СЕССИИ ──────────────────────────────────────────────────────────────────┐│
│ │ ● laptop-go-1 · zcode    идёт · открытa 41 мин · активность 2 мин назад  →││
│ │ ○ laptop-go-1 · zcode    вчера 18:04–19:22 · 1 ч 18 мин                  →││
│ │ ○ laptop-zcode-1 · zcode 25 сент · 44 мин                                →││
│ │ … (скролл-restore, бесконечная лента батчами)                             ││
│ └───────────────────────────────────────────────────────────────────────────┘│
│ ▸ Покрытие (свёрнуто)                                                        │
└──────────────────────────────────────────────────────────────────────────────┘
```

- Никаких карточек «Что вижу/чего нет» и «Зачем Кора» наверху: они объясняли
  архитектуру сканеров вместо того, чтобы показывать сессии. Оба сливаются в
  свёрнутую «Покрытие» (§5).
- «Пилюля „Кора · срез 2"» убирается из основного слоя; дорожные заметки —
  в «Покрытие».
- Фильтр по хосту — dropdown с чипом выбранного хоста (анатомия чипа `05` §2.2);
  глубинная ссылка из карточки хоста `/kora?host=<id>` открывает фильтр
  предзаполненным.
- Плотность операционная; транскрипт — созерцательный (Lora, как свиток `04` §2).

## 2. Строка сессии

Анатомия: [точка статуса] [хост · харнес] [когда] [последняя активность] [→].

| Состояние сессии | Точка | Текст строки |
| --- | --- | --- |
| Идёт | ирис + пульс при событии | «идёт · открыта 41 мин · активность 2 мин назад» |
| Завершена | приглушённая | «вчера 18:04–19:22 · 1 ч 18 мин» |
| Прервана | warning | «прервалась 3 ч назад · дошли 20 мин» |

- Клик по строке → транскрипт (§3). Hover — только фон (никаких анимаций
  карточек — анти-клише канона).
- Пульс-импульс на строке идущей сессии — только на реальное событие ленты
  (`06-MOTION` §5); никогда по таймеру.
- Живая лента сессий: новые/обновлённые строки всплывают 240ms
  `--ease-enter`, reduced-motion — мгновенно; SSE-разрыв — строка
  «данные на HH:MM» вверху списка (канон спеки агентов §3.2).

## 3. Транскрипт сессии (read-only)

Клик по строке → раскрытие в правой панели (дровер, ≥560px; «открыть полностью» —
роут `/kora/:sessionId` для URL-шеринга):

```
┌───────────────────────────────────────────────────────────────────────┐
│ zcode · laptop-go-1                                  [×]              │
│ идёт · открыта 41 мин · последний ход 2 мин назад                    │
│ ──────────────────────────────────────────────────────────────────── │
│ ПОКРЫТИЕ ЭТОЙ СЕССИИ: полный транскрипт (zcode)                      │
│ ──────────────────────────────────────────────────────────────────── │
│ (транскрипт — «свиток»: Lora, --color-scroll-bg, ≤72ch)              │
│ 18:04  вы: поправь тесты в tokens.test.ts                            │
│ 18:06  zcode: разобрал 3 падения…                                    │
│ …                                                                     │
│ ▸ Технические детали                                                 │
└───────────────────────────────────────────────────────────────────────┘
```

- **Честная пометка coverage** — первая строка под шапкой, человеческим языком:
  - zcode: «полный транскрипт»;
  - vscode/pi: «видно только начало сессии: кто открыл и когда. Полный ход
    — скоро»;
  - прочие (hermes): «этот терминал пока не сканируем».
- Помечается не цветом, а текстом (WCAG 1.4.1); read-only природа — строка в
  шапке дровера, не бейдж-аббревиатура.
- Транскрипт: реплики — время mono muted + автор + текст Lora
  `--text-md`, `--leading-relaxed`, measure ≤72ch; живая идущая сессия
  дописывается снизу по ленте (новая реплика — 240ms enter).
- Управление сессией отсутствует по построению; вместо скрытия — одна строка
  над транскриптом: **«Управлять сессией отсюда пока нельзя — только читать.
  Это в планах»** (не обещаем руление среза 3; «продолжить с телефона» —
  тоже «скоро», формулировка §5.2).
- «Технические детали»: id сессии, сессии-сканер источник, границы
  транскрипта, ссылка openapi-контракта.

Состояния транскрипта: loading (скелетон абзацев) / error («Транскрипт не
прочитался» + Повторить) / частичное покрытие (пометка выше + «Показать, что
есть» — кнопка открывает усечённое начало с явной меткой конца:
«— на этом данные заканчиваются»).

## 4. Пустые состояния (главный фикс — прод врал)

Сегодня: «Сессий пока нет. Подключите исполнителя…» при работающих хостах —
лживое или непрозрачное. Правило против тупиков: почему + кнопка + куда смотреть.

| Ситуация | Формулировка | Действия |
| --- | --- | --- |
| Хостов нет вообще | «Хостов ещё нет — сессиям неоткуда браться. Подключите первую машину — сессии появятся сами» | [Подключить хост] · [Открыть Хосты] |
| Хосты есть, сессий нет | «Хосты подключены, но сканеры ещё не доложили. Если сессии уже шли — первые данные появятся с следующим докладом агента: обычно до 2 минут» | [Проверить связь] · [Открыть Хосты] |
| Сессии есть только по одному хосту | строка над списком: «По vpnus-1 сессий пока не видно — её сканер не докладывал» | [Открыть карточку хоста] |
| Фильтр дал пусто | «По этому фильтру сессий нет. Смените фильтр или посмотрите все» | [Сбросить фильтр] |

Формулировки обязаны отличать «нет данных» от «данные придут»: если хост
на связи и сканер активен — никогда не пишем «сессий нет» без про «до 2 минут».

## 5. Карточка «Покрытие» (внизу, свёрнутая)

Одна свёрнутая карточка вместо двух развёрнутых прод. Шеврон ≥24px, раскрытие
240ms, состояние персистентно.

Содержимое (человеческим языком, без kind/срезов/T-кодов):

| Харнес | Что видно |
| --- | --- |
| zcode | полный ход сессии: что делали и что говорили |
| vscode | видим начало сессий; полный ход — скоро |
| pi | видим начало сессий; полный ход — скоро |
| hermes | пока не сканируем |

+ одна строка внизу: «Покрытие растёт по мере готовности сканеров — список
обновим» (без обещаний дат и без внутренней нумерации).

Пояснение «Зачем Кора» сжимается в подпись при раскрытии:
«Кора читает сессии с ваших машин, пока вы работаете. Ничего отправлять и
регистрировать не нужно — сессии появляются сами, как только харнес работает.»

## 6. Верх страницы: связка с хостами

Строка-сводка под заголовком (данные реестра, не сканеров):

«2 хоста на связи · 1 сессия идёт · последние 24 ч: 4 сессии» — mono-числа
с tabular-nums, каждое кликабельно к соответствующему фильтру (сессии идущие /
за сутки). Клик по хосту в строке — предфильтр.

## 7. State-матрица

| Компонент | Матрица |
| --- | --- |
| Строка сессии | default/hover/focus(цель-строка)/active(открыт транскрипт)/loading/empty/error/stale(SSE) |
| Фильтр хоста | `05` §2.5 + dropdown open/close/Esc/клавиатура ↑↓ |
| Транскрипт | open/closing/focus-trap/Esc/loading/error/частичное покрытие/живая догрузка |
| «Покрытие» | collapsed/expanded(персистентно)/focus |
| «Проверить связь» | `07c` §5 правила |

A11y: список — `role="list"`, строки — кнопки с полным текстовым содержимым;
транскрипт — дровер `role="dialog"`; живые обновления ленты — `aria-live="off"`
(терминальные переходы — polite); контрасты — пары `02-TOKENS` §4;
все цели ≥24×24 (мобильный 44px); reflow 320px без 2D-скролла — строки
сессий сворачиваются в карточный вид <768px. `prefers-reduced-motion`:
всплытия мгновенные, импульс → статический тинт 1.5s.
