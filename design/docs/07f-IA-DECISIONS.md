## 1. Судьба страниц (верdictы)

### 1.1 «Сессии A2A» (`/system/sessions`) — убрать из меню, редирект на Кору

Страница сегодня: «Сессии A2A. Сессии недоступны в board-режиме… 501… Ф1» —
дублирует Кору и мертва. Вердикт: **удалить из меню; `/system/sessions` →
302-редирект на `/kora`** (с сохранением query: `?id=` → `/kora/:id`).

- Кора покрывает пользовательский вопрос («что агенты делали») полностью;
  A2A-техника — внутренний протокол, пользователю не нужный (словарь `07a` §3.5).
- Меню «Настройки/Система»: пункт «Сессии» удаляется в том же PR, что и редирект,
  чтобы не оставить скрытый вход в тупик.
- i18n: обе локали в одном PR (канон `07-INTEGRATION.md` §3).

### 1.2 «Статус» (`/system/status`) — остаётся в меню, пересобирается по 07e

Страница нужна (владелец проверяет здоровье в два клика), но пересобирается из
живых данных по `07e`: здоровье хранилищ, SSE, версии, хосты, счётчики,
последние события. Мёртвый блок метрик не рендерится; техническая причина —
одна строка в свёрнутых «Технических деталях», если когда-нибудь понадобится.

### 1.3 «Хосты» и «Подключение» — два входа в один мир

Сегодня это два разрозненных раздела с разной терминологией (hosts — «Карточка
исполнителя» со стеной полей; harnesses — «Добавить исполнителя» с большой формой).
Вердикт: **один домен «Агенты», три секции**:

```
Агенты /agents
├── Исполнение  /agents/execution    — кто чем занят (канон спеки агентов §1)
├── Хосты       /agents/hosts        — реестр + карточки жизни (07c)
└── Подключить  /agents/hosts/new    — мастер 07b + список подключённых
```

- «Хосты» = реестр: список карточек-жизни, клик → карточка 07c. Пустое
  состояние → CTA «Подключить хост».
- «Подключить» = мастер + под ним список уже подключённых (быстрый обзор без
  ухода) + токены регистрации.
- Рекомендация **«Исполнение» вместо «Харнесы·среды»** в меню: пользовательское
  слово про работу, не про инфраструктуру. (Меню «Специалисты» из концепта §2.1
  остаётся в домене при появлении реестра ролей; сегодня его нет — слот не
  рендерим, канон «пустой слот не рендерится».)

### 1.4 Прочие тупики прод

| Поверхность | Вердикт |
| --- | --- |
| Свернутая помощь «Как подключить внешнего агента» внизу формы | заменена кнопкой «Как это работает» рядом с формой (дровер, `07b` §1) |
| «Провести связь» / «Проверить по-настоящему» (две кнопки связи) | слиты в одну «Проверить связь» (`07a` §3.2) |
| Пилюля «Кора · срез 2», карточки «Что вижу/чего нет», «Зачем Кора» | убраны с основного слоя Коры → свёрнутое «Покрытие» (`07d` §5) |
| Пустое состояние Коры «Сессий пока нет» при живых хостах | заменено честным дифференцированным (`07d` §4) — прод-баг |
| «Возможности: возможности не заявлены», «использован использован» | словарные фиксы `07a` §3.3, i18n-линтер против дублей |

## 2. Обновлённая карта IA

Отличия от концепта §2.1 помечены: `+` новое, `~` переименовано/переехало,
`−` удалено.

```
Обзор /                                        — без изменений
Память /memory                                 — без изменений
  Записи · Поиск · Пульс · Теги · запись
Задачи /tasks                                  — без изменений
  Канбан · Список · Входящие · Отчёты · Архив · задача
Агенты /agents                                 + домен расширяется (было 2 секции)
  ~ Исполнение      /agents/execution          (стартовая, канон)
  + Хосты           /agents/hosts              (реестр машин + карточки жизни 07c)
  + Подключить      /agents/hosts/new          (мастер 07b + список + токены)
  − (Харнесы·среды  /agents/harnesses)         — расщеплён: реестр → Хосты,
                                               подключение → Подключить
Кора /kora                                     + новый роут верхнего уровня:
                                                 сессии всех хостов (07d)
  Кора /kora · транскрипт /kora/:sessionId
Документы /docs                                — без изменений (три хаба)
Рабочий стол /desk  [эксперимент]              — без изменений
Система /system
  ~ Статус        /system/status               пересобран по 07e, остаётся
  − Сессии A2A    /system/sessions             → редирект на /kora
  Уведомления · Устройства · Настройки          — без изменений
Галерея /gallery [стенд]                      — без изменений
```

Навигационные правила остаются каноническими (`03` §1–2): вложенность ≤3,
URL-first, крошки, палитра. Новые хоткеи: `g k` — Кора (в таблицу `03` §7).
Палитра Ctrl+K: секция «Сущности» пополняется сессиями (id `sess-…`) и хостами.

## 2. Что меняется против концепта (диффектом 07f)

| В концепте §2.1 | Стало | Почему |
| --- | --- | --- |
| «Харнесы·среды /agents/harnesses» | «Хосты» + «Подключить» | прод-реальность: подключение — это про машины (SSH), а не про типы харнесов; слово «харнес» — оставленец, не заголовок меню (`07a` §5) |
| нет Коры | `/kora` верхнего уровня | сессии — главный пользовательский контент агентского мира (критика владельца); «Сессии A2A» умерла, Кора — её живой наследник |
| `/system` включал «Сессии» | удалено | дубликат Коры, мёртвый 501 |
| «Подпрограммы» §2.5: подключение хранилища | добавляется строка «Подключение хоста»: мастер 4 шагов (`07b`) | флоу стал последовательностью с URL-состоянием (`/agents/hosts/new?step=2`), не замыканием формы |

Меню «Агенты» в сайдбаре получает счётчик активных исполнений (уже канон
топбара `03` §4) и точку-сигнал, если какой-то хост молчит >10 мин —
импульс только на реальный переход состояния (`06-MOTION` §5).

## 3. Правило против тупиков (канон)

**У каждого пустого состояния три обязательных элемента: почему пусто + что
сделать (кнопка) + куда ещё посмотреть.** Реестр по всем затронутым страницам:

| Страница | Пустое состояние | Кнопка | Куда ещё |
| --- | --- | --- | --- |
| Хосты (реестр) | «Хостов ещё нет. Подключите первую машину — агент поставится сам» | [Подключить хост] | — |
| Подключить (список) | «Хостов ещё нет…» | [Подключить хост] (якорь на мастер) | — |
| Карточка хоста · Недавно | «Тишина. Первые события появятся после первого доклада — обычно до 2 минут» | [Проверить связь] | Хосты |
| Кора (хостов нет) | «сессиям неоткуда браться» | [Подключить хост] | [Открыть Хосты] |
| Кора (хосты есть) | «сканеры ещё не доложили; если сессии шли — с следующим докладом, обычно до 2 минут» | [Проверить связь] | [Открыть Хосты] |
| Кора (фильтр) | «по этому фильтру нет» | [Сбросить фильтр] | все сессии |
| Статус (хостов 0) | блок «Хосты» с приглашением | [Подключить хост] | — |
| Токены регистрации (0) | «Токенов ещё не создавали — они нужны только для ручного подключения» | [Создать токен] | мастер |
| Транскрипт (усечённый) | «— на этом данные заканчиваются» | [Показать, что есть] | Покрытие |

Проверка канона: любое пустое состояние, не имеющее кнопки, — блокер ревью.

## 4. Зависимости и порядок внедрения

1. **Словарь 07a** — первым: строковые правки дешевле всего и снимают 80% боли
   («не проверено», дубли слов, англицизмы) даже без новых экранов.
2. **Мастер 07b + lifecycle-статусы** — требует только существующих
   provisioning/SSE контрактов (job-машина уже реализована сервером).
3. **Карточка 07c** — переупаковка существующих данных реестра.
4. **Кора 07d** — контракт заморожен; UI-работа, не серверная.
5. **Статус 07e** — только существующие источники, ноль серверных зависимостей.
6. **Редирект `/system/sessions` + меню** — с пунктом 4 (Кора должна жить
   раньше, чем умирает дубликат).

Каждый шаг самодостаточно зелёный и проходит продуктовую планку владельца:
прогон «новым взглядом» от точки входа (планка 2026-09-23).

## 5. Открытые вопросы (к вердикту владельца)

1. **Домен «Кора» — в сайдбаре верхнего уровня или секция домена «Агенты»?**
   Рекомендация: верхний уровень (сессии — самостоятельный контент, а не
   под-раздел реестра машин); если владелец хочет компактнее — секция «Сессии»
   в «Агентах» с роутом `/agents/sessions`, редирект `/kora` сохраняется.
2. **Старые закладки `/agents/harnesses`.** Рекомендация: 302-редирект на
   `/agents/hosts` (реестр), с query-совместимостью для глубоких ссылок
   исполнителей — сохраняет все существующие ссылки, ноль пользовательского
   шума.
