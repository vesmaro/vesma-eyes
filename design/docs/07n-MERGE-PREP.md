## Артефакт 1 — Шаблон journey-приёмки фазы (формальный гейт, условие Analytics)

Основание: АРХКОМ §3.2 («скрипт и критерии замораживаются ДО показа; ноль
blocker и ноль major = принято») и позиция Analytics (§4: регресс-набор
фиксируется до фазы 1, breach останавливает фазу). Шаблон копируется в
журнал приёмки без правок структуры.

```markdown
# Journey-приёмка фазы ИX — <название поверхности>
Дата показа: ГГГГ-ММ-ДД · Владелец: <имя> · Ведущий: <дизайн-лид/ТЛ>
Флаги фазы: <какие слои за каким флагом; откат — переключатель, не revert>

## 0. Предгейты (все до показа, иначе прогулка не начинается)
- [ ] Регресс-набор фазы зафиксирован (Analytics; breach = фаза стоит)
- [ ] Скрипт и критерии §1 заморожены коммитом/issue ДО показа;
      правка после старта прогулки = показ недействителен, новая приёмка
- [ ] «Одна поверхность за фазу»; карточка «что изменилось» у владельца
- [ ] Живой слой: при мерже выключен, дефолт «Спокойный» (§3.3) —
      для фаз И3/И4 отметить, в каком режиме показывается

## 1. Скрипт прогулки (заморожен до показа)
| # | Намерение владельца | Точка входа | Шаги (2–4) | Критерий успеха | Лимит |
| - | ------------------- | ----------- | ---------- | --------------- | ----- |
| 1 | <глагол: «найти…», «дать задачу…»> | <страница/палитра> | … | <наблюдаемое действие: «открылась запись X»> | 5 мин |
| 2 | … | … | … | … | 5 мин |
| 3 | … | … | … | … | 5 мин |

Точка входа одна на прогулку (с неё начинаются все намерения).
Критерий успеха — завершённое действие, не «понравилось».
Лимит: таймер ведёт ведущий; превышение = затруднение, прогулка продолжается.

## 2. Прогулка (факт, заполняется по ходу)
Намерение 1: 03:40 — успех / Намерение 2: 06:12 — major №1 / …

## 3. Четыре вопроса владельцу (фиксированные, порядок не менять)
1. «Сценарии прошли целиком, без вашей помощи?» — да/нет + где застряли.
2. «Что было непонятно или замедлило?» — место на экране + своими словами.
3. «Показать рядом, как это выглядит сейчас в main?» — да/нет.
4. «Этот вид становится единственным?» — да / нет / да после правок №…

## 4. Классификация затруднений
- blocker — намерение не завершено; данные врут; тупик без пути назад.
- major — завершено с посторонней помощью или повторными попытками;
  ожидание владельца обмануто (не там искал, не то понял).
- minor — трение без потери намерения (слово, тайминг, порядок).

Порог приёмки фазы: **0 blocker + 0 major**. Minor не блокирует — уходит
в issues следующей волны.

## 5. Вердикт и журнал
- Вердикт: принято / принято (только minor) / не принято (перечислить №).
- Issues: по одному на затруднение — id, страница, цитата владельца,
  severity, волна-исполнитель.
- Журнал: `docs/sessions/ГГГГ-ММ-ДД-phase-ИX.md` — вердикт, заметки
  владельца дословно, тайминги по намерениям, список issues.
  Коммитится в той же волне.

## 6. Правило
Фаза не «done», пока файла приёмки нет в репозитории.
Нет записи — фаза не существует (даже если «всё работало на демо»).
```

## Артефакт 3 — Бюджет living-layer (условие FE, АРХКОМ §3.5)

**Предложение строки в budgets** (механика — по образцу
`viewer/scripts/budget-docs-render.mjs`: CI-гейт после `npm run build`,
именованный чанк в `viewer/vite.config.ts`):

```text
living-layer    dist/assets/living-*.js    ≤ 8 KiB gzip
(ядро useVeinCanvas + морфология Нейры + швы жил; canvas-лойер —
отдельный чанк, не смешивается с app-кодом)
```

Оценка от стенда v10: `living.js` ~20 KB raw / ~6 KB gzip; канвас Нейры
28×28×dpr2 ~0.1 ms/кадр. Лимит ≤ 8 KiB gzip на чанк — запас ~33% к оценке.

Правила (все обязательные, по условию комитета «замер по стенду до вливания»):

1. **Отдельный named-чанк** `living` (по образцу пулов md-core/md-sanitize);
   попадание app-модулей в чанк = breach.
2. **Не в eager base set**: слой при мерже выключен (АРХКОМ §3.3) — чанк
   ленивый, first paint за него не платит; reachability-гейт по образцу
   md-sanitize (статическая достижимость из index.html = FAIL).
3. **Замер до вливания**: числа строки берутся со стенда v10
   (консоль-диагностика), не «по оценке»; пересчёт при каждом изменении
   морфологии (08 §1.2) — изменение лимита = осознанный коммит (дисциплина
   golden-значений, §3.4).
4. Рантайм-цель жилы ≤ 0.5 ms/кадр (08 §2.5) — отдельная строка отчёта
   стенда, не гейт сборки; 0.1 ms/кадр канваса Нейры — входящее значение.

2. **Легаси не переименовывается в волне**: `overview.*` живёт, пока
   `cockpit.*` не пройдёт journey-гейт И3; удаление легаси — отдельный
   коммит той же волны после приёмки.

Чек-лист И1 (до коммита волны):

- [ ] паритет-тест: сборка viewer падает при отсутствии ключа в `en.ts`
      (уже механика `Record<TranslationKey, string>`) — прогнан зелёным;
- [ ] grep-список семейств и счётчиков: `grep -oE '"[a-z]+\.' viewer/src/i18n/ru.ts | sort | uniq -c`
      — новое семейство в diff появляется только если оно есть в таблице выше;
- [ ] grep-проверка пересечений: ни один новый ключ не повторяет
      существующий полный ключ в ru.ts/en.ts;
- [ ] плейсхолдеры `{{name}}` совпадают в парах RU/EN (`interpolate()`).
