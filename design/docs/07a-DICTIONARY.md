# 07a — Словарь-подстановок: инженерный язык → человеческий

> Status: **v1.0, дизайн-лид, 2026-09-27**. Главный документ UX-флоу-слоя v2.
> Расширяет словарь лора `01-CHARTER.md` §6 и `04-SCREENS.md` §5 («Агенты»);
> применяется ко всем строкам домена «Агенты», Коры и системных страниц.
> Стимул: критика владельца 2026-09-27 — «непонятно как пользоваться… внутренний
> язык наружу; пустые состояния — технические оправдания вместо пути дальше».

## 1. Правило 5 секунд

Каждая строка интерфейса проходит тест: **«новый пользователь понял за 5 секунд,
что это значит и что с этим делать?»** Если нет — термин заменяется (§3),
объясняется при первом показе (§5) или переезжает в «Технические детали» (§6).

Производные правила (проверяются на ревью как канон):

1. **Статус никогда не одинок**: `[что это значит] + [когда обновлено] + [что сделать]`.
   Шаблон строки статуса: `«<состояние> · <возраст> · <действие рядом>»`.
2. **Пустое состояние = почему + кнопка + куда ещё посмотреть** (полный реестр — `07f` §4).
3. **Никаких дублей слов** («возможности: возможности не заявлены»,
   «использован использован» — прод-баги 2026-09-27; i18n-линтер отвергает
   повтор слова через двоеточие и подряд).
4. **Идентификаторы в основном слое не показываются**: `T-…`, `M-…`, `enr-…`,
   `SHA256:…`, mono-id хостов — только по клику «детали» или в tooltip
   (`--font-mono`, tabular-nums). Человек говорит «задача про UI-10», а не «T-128».
5. **Числа — человеческими интервалами**: «до 2 минут», «12 с назад», «41 мин».
   Точные таймстемпы — в tooltip и деталях.
6. **RU-first, без англицизмов** (канон `01` §5): «доклад», «умения», «связь» —
   не «heartbeat», «capabilities», «connectivity».

## 2. Лестница терминов: кто есть кто

Один слой понятий для всего домена «Агенты» (расширяет `2026-09-19-agents-section-spec.md` §0):

| Термин UI | Что это для пользователя | Пример |
| --- | --- | --- |
| **Хост** | машина, на которой работает агент — ваша или арендованная | `laptop-go-1` |
| **Агент** | лёгкая служба на хосте: сама ставится, сама докладывается, запускает работу | `vesmaro-agent` |
| **Харнес** | программа, через которую агент работает (см. термины-оставленцы §5) | `zcode` |
| **Исполнитель** | хост+агент, взятые в работу по задаче (слово живёт только в контексте поручений) | «исполнитель: laptop-go-1» |
| **Сессия** | эпизод работы харнеса: что делали и что говорили | «сессия zcode, 41 мин» |
| **Кора** | журнал сессий всех хостов (термин-оставленец, §5) | страница «Кора» |

Правило употребления: страница и список — про **хосты**; карточка — про **жизнь хоста**;
строка поручения — про **исполнителя**; журнал — про **сессии**. Слово «агент» в
UI-строках раздела — только про службу (агент установлен, агент молчит), не как
имя сущности меню.

## 4. Жизненный цикл связи хоста (замена «не проверено»)

Единый словарь пилюль для списка хостов, карточки и Коры (анатомия пилюли —
`05-COMPONENTS.md` §2.4; цвета и контраст — `02-TOKENS.md` §4). Пороги 2/10 мин
берутся из meta API — UI не хардкодит (требование спеки агентов §5.6).

| Состояние | Условие | Пилюля (точка + текст) | Пояснение и следующий шаг |
| --- | --- | --- | --- |
| **Ставится** | provisioning job active | ирис, «ставится…» | «Ставим агента на машину — обычно пара минут» |
| **Ждёт одобрения** | registered, pending | ирис-контур, «ждёт одобрения» | «Хост зарегистрировался. Проверьте данные и одобрите» + [Открыть] |
| **Ждёт первый доклад** | approved+enabled, докладов ещё не было | warning, «ждёт первый доклад» | «Агент установлен; обычно докладывается до 2 минут» + [Проверить связь] |
| **На связи** | последний доклад ≤2 мин | success + «на связи · N с назад» | последний доклад N назад; действие по контексту |
| **Молчит** | 2–10 мин | warning + «молчит N мин» | «Докладов нет N минут — проверить связь» + [Проверить связь] |
| **Не на связи** | >10 мин | приглушённая + «не на связи · N мин» | «Последняя связь N мин назад» + [Проверить связь] |
| **Выключен владельцем** | enabled=false | приглушённая + «выключен владельцем» | «Новые задачи не получает; доклады продолжаются» + [Включить] |
| **Отозван** | revocation | заштрихованная + «отозван» | «Доступ отозван N дней назад. Секрет больше не действует» |

Правило двух фактов (наследие спеки агентов §2.1): связь и занятость — независимые
факты, никогда не схлопываются: «на связи · последний доклад 12 с назад» и
«без задач 3 ч» — две строки, а не одна «простаивает 0мин».

## 5. Термины-оставленцы (имена собственные)

Остаются в интерфейсе — это идентичность продукта (канон `01` §6) — но **при
первом показе получают строку-пояснение** (tooltip или подпись под заголовком):

| Термин | Пояснение при первом показе |
| --- | --- |
| **Кора** | «Кора — журнал сессий всех хостов: что агент делал и что говорил» |
| **Харнес** | «Харнес — программа, через которую агент работает: например, zcode» |
| **Колодец** | канон «Обзора» (`01` §4) — пояснение уже входит в его пустое состояние |
| **Свиток** | внутренний термин системы чтения; наружу не выходит |
| **Борд** | в UI-строках заменяется на «сервер»; слово «борд» допустимо только в «Технических деталях» |
| **Поллер** | заменяется на «агент» во всех UI-строках |

## 6. Что живёт в «Технические детали»

Сворачиваемый блок в конце карточки хоста и Коры (раскрытие 240ms
`--ease-enter`, состояние персистентно; заголовок — кнопка с шевроном, цель ≥24px).
Сюда переезжает всё, что сейчас абзацами-дисклеймерами:

- идентификаторы: id хоста, `enr-…`, `T-/M-…` упоминаемых сущностей, fingerprint хоста (`SHA256:…`);
- версии: борд, агент, харнес; транспорт (`local/mesh`); `registered_via`, `used_ip`;
- полный абзац про allowlist («харнес задаёт, что агенту разрешено…»), `capabilities_source`, автодопуски;
- TTL и лимиты токенов, rate-limit, квоты provisioner (cap 2, cooldown);
- ссылки на ADR и openapi-контракты;
- «опасная зона»: Выключить/Включить, Отозвать, Удалить — с confirm-модалами,
  называющими последствие и число (канон `05` §2.1).

Правило: **в основном слое от каждого дискурса-абзаца остаётся максимум одна
строка-подсказка**; остальное — в детали. Ссылки на ADR в основном слое запрещены.

## 7. Самокритика (проход 2)

- «Умения» vs «Роли» — риск спутать. Митигация: на карточке хоста один блок
  «Умения и роли» с двухстрочным объяснением, а не два разрозненных поля.
- «Токен регистрации» всё ещё техницизм, но честный: слово «регистрация»
  уже в заголовке шага 4. Альтернатива «код приглашения» отвергнута —
  прячет природу одноразовости.
- Проверка «сними бренд»: словарь опознаётся по «доклад/умения/связь + lifecycle
  с следующим шагом» — не сводится ни к GitHub-клону («status: unknown»),
  ни к SaaS-киту («Health: OK»).
- Риск линтинга: паритет ru/en словарей обязателен в одном PR (канон `07-INTEGRATION.md` §3).
