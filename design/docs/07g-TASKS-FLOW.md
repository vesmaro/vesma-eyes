## 0. Честные расхождения с брифом и продом (записаны до проектирования)

1. **Колонки: 5 состояний vs 7 колонок WF-1.** Бриф: «колонки = 5 состояний»
   (state-машина `task:open / in-progress / blocked / resolved / done` в mnemos).
   Прод-борд ратифицирован как WF-1 с 7 колонками (backlog и validating —
   пред-валидационные дорожки слева от `open`, читаются workflow-статусом `open`).
   Решение: канбан стенда — **5 колонок состояний** (зеркало mnemos-машины);
   две прод-дорожки складываются в «открыто» со стейдж-чипом («на валидации» +
   честный таймер WF-1, просрочка 24 ч → метка «ждёт разбора архитектуры»).
   Мост для интеграции: борд-сервер маппится на модель стенда, не наоборот.

| Колонка стенда | Тег состояния mnemos | Сюда складывается из прода |
| --- | --- | --- |
| открыто | `task:open` | backlog, validating (со стейдж-чипом), open |
| в работе | `task:in-progress` | in-progress |
| блокировано | `task:blocked` | blocked |
| решено | `task:resolved` | resolved |
| готово | `task:done` | done |

2. **04-SCREENS §Задачи не существует** (v2.0 — 8 экранов без задач). Расширять
   нечего; база — концепт §«Волна 3» и прод. Противоречить нечему — фиксируем
   этот документ как канон домена «Задачи» стенда.

3. **Табы карточки: 4 у стенда vs 5 у прода.** Прод: Отчёты · История · Память ·
   Детали · Исполнение (дефолт «Отчёты»). Стенд объединяет «Детали» + «Память»
   в **«Обзор»** (принцип жизни `07c`: кто → чем занята → что было → что сделать)
   и делает его дефолтным. Расхождение дефолта записано в §6.

## 2. Канбан `/tasks`

```
┌──────────────────────────────────────────────────────────────────────────────────┐
│ Задачи · Канбан                              [Дать задачу]  фильтры: проект·исп·q│
│ ┌─ открыто 2 ──────┐┌─ в работе 1 ───────┐┌─ блокировано 1 ───┐┌─ решено ─┐┌─ готово ─┐
│ │ ▾ mnemos-eyes (2)││ UI-10 проводник    ││ ⛔ Пейринг-фолбэк ││          ││          │
│ │   Дозапись индекса││  ●0.92 #ui #agents││   не вышло:       ││  пусто   ││  пусто   │
│ │   core · 4 мин   ││  agb · 2 ч  ●отчёт ││   конфликт записи ││          ││          │
│ │   Чистка дублей… ││                    ││   agb · 1 д       ││          ││          │
│ │   ⚠ исполнитель  ││                    ││                   ││          ││          │
│ │   молчит 12 мин  ││                    ││                   ││          ││          │
│ └──────────────────┘└────────────────────┘└───────────────────┘└──────────┘└──────────┘
│ ▸ Готово за сегодня: 2 · Решено: 1            (мини-статы — mono tnum, кликабельны)│
└──────────────────────────────────────────────────────────────────────────────────┘
```

### 2.1 Колонка

- Заголовок: имя состояния (словарь колонок §0) + счётчик mono `--numeric-tnum`.
- **«Блокировано» подсвечено только реальной блокировкой**: колонка нейтральна,
  пока внутри нет задач; warning-полоса 2px слева появляется, когда есть ≥1
  карточка (и дублируется бейджем на карточке — не цветом одним, WCAG 1.4.1).
- Карточки внутри — группы-аккордеон по проектам; раскрытие персистентно
  (ключ `vesmaro.taskGroups`, общий со списком — прод-канон).
- Пустая колонка: «Здесь пусто — задачи в этом состоянии появятся, когда
  меняется их состояние в памяти» (`--text-muted`, по центру, без кнопки:
  колонка канбана — не страница; канон против тупиков применяется на уровне
  страницы — §8. Исключение: колонка «открыто» на пустом домене несёт [Дать
  задачу] — §7).
- SSE-автоперенос (агент меняет тег состояния в памяти): карточка всплывает
  240ms `--ease-enter`, уходит `--ease-exit`; reduced-motion — мгновенно.

### 2.2 Компактная карточка

Анатомия (максимум 6 элементов, вторичная строка — muted):

```
UI-10 проводник                    ← заголовок --text-ui medium (без T-id: 07a §1.4)
●0.92 #ui #agents +1               ← confidence-точка (золото+число в tooltip) · чипы ≤2 + «+N»
agb · 2 ч                 ●отчёт   ← исполнитель · возраст (mono tnum) · индикатор отчёта
```

- **Индикатор отчёта**: есть непрочитанный отчёт → золотая точка + tooltip
  «непрочитанный отчёт agb · 6 мин назад». Цвет — словарь write (`06` §5);
  никогда не цветом одним (число/слово в tooltip, счётчик ≥2 отчётов — «2 отч.»).
- Стейдж-чип «на валидации» + возраст таймера — для прод-дорожек (§0.1).
- Stagnation-строка: исполнитель в очереди молчит >10 мин → warning-текст
  «исполнитель молчит 12 мин» (честный возраст, T-127-фикстура).
- Клик по карточке → `/tasks/:id`; клик по чипу → фильтр; клик по точке
  отчёта → `/tasks/:id?tab=reports`.

### 2.3 DnD и честный confirm

- Pointer + клавиатура (dnd-kit, прод-канон ARCHCOM-3): ghost-overlay,
  оригинал полупрозрачен; drop — `--ease-spring` (единственная роль токена).
- **Перенос в «готово» — только через confirm**: «Закрыть „UI-10 проводник“?
  Состояние в памяти изменится на task:done — агенты это увидят»
  [Закрыть задачу] / [Отмена]. Молча закрыть задачу нельзя.
- Перенос в остальные колонки — сразу, с toast-подтверждением («Перенесли в
  „в работе“» — канал обратной связи `05` §3).
- Read-only / устройство без гранулы `tasks`: DnD выключен, tooltip «только
  чтение»; клавиатурная альтернатива остаётся у тех, кому мутации доступны:
  контекст-меню карточки → «Перенести в…» (паритет 2.1.1).

## 3. Список `/tasks/list`

- Таблица: `[☑] [заголовок] [состояние-бейдж] [приоритет] [возраст] [исполнитель] [отчёт ●] [теги ≤2]`.
- Сортировка кликом по шапке: возраст / приоритет / состояние (`aria-sort`,
  направление — стрелка + текст в tooltip). Группировка по проектам —
  аккордеон, персистентный (общий ключ с канбаном).
- Фильтры: исполнитель (хост/агент) · тег · состояние · **«есть отчёт»** · `q`.
  Диалект URL тот же, что у канбана — переключение вида переносит фильтры.
- Плотность: строки по density-токену (`--row-h` 32/40, тумблер в топбаре).
- **Bulk-выделение**: панель над таблицей (240ms `--ease-enter`):
  «Выбрано 3 · Сменить состояние · Назначить исполнителя · Архивировать · Отмена».
  **Каждое bulk-действие — confirm с числом и последствием**: «Архивировать
  3 задачи? Из канбана исчезнут; история и отчёты сохранятся».
- Хоткеи: `j`/`k` — по строкам, `x` — выделение, `Enter` — открыть (§9).

## 4. Входящие `/tasks/inbox` (AGG-1)

Входящие = `task:queue`-записи памяти (предложения агентов) + черновики
владельца (§7). Карточка-запись:

```
┌──────────────────────────────────────────────────────────────────────┐
│ Принёс agb · mnemos-01 · 26 мин назад              [источник, muted] │
│ «Разобрать дубли тегов M-241: три алиаса конфликтуют…»               │
│   (черновик-суть, Lora, clamp 3 строки, [Показать целиком])          │
│ #memory #tags #дубль            ← предложенные теги (чипы, клик=фильтр)│
│ [Принять]  [Принять с правкой]  [Отклонить]                          │
└──────────────────────────────────────────────────────────────────────┘
```

- **Принять** → канбан: попутно (опционально) выбор колонки и исполнителя;
  подпись «Попадёт в канбан; источник останется в памяти».
- **Принять с правкой** → инлайн-редактор (заголовок + теги) с честной
  подсказкой: **«Правка попадёт в память — агент увидит»**.
- **Отклонить** → confirm с причиной (селект: «дубль · не задача · не
  актуально» + комментарий) и обещанием: **«Отклонённое вернётся в память как
  пометка — не потеряется»**. После — карточка уходит 240ms `--ease-exit`,
  toast «Отклонено · пометка в памяти».
- Stale-источник (запись изменилась/сервер отозван): «источник изменился в
  памяти» — действия disabled с пояснением (канон stale `05` §2.3).
- Секция **«Черновики»** (если есть, `07c`-стиль миелин-разделителя): источник
  «вы · черновик», действия «Продолжить» (открывает мастер на шаге) / «Убрать»
  (confirm «Черновик будет удалён из памяти. Убрать?»).
- Пустое состояние: **«Входящих нет — агенты пока ничего не предложили»** +
  [Обновить] + [Открыть Кору] (что делают агенты — там).

## 5. Архив `/tasks/archive`

- Группировка: проекты → месяцы («сентябрь 2026», mono-заголовки секций).

  состояние („открыто“)?» → POST unarchive → toast + карточка в канбане.
- Пустое: «В архиве пока ничего нет — задачи попадают сюда из „готово“ или
  вручную» + [Открыть канбан].

## 6. Карточка задачи `/tasks/:id`

Принцип жизни `07c`: **кто → чем занята → что было → что сделать**.

```
┌──────────────────────────────────────────────────────────────────────────┐
│ Задачи / UI-10 проводник                        [Назначить] [Изменить] [Архивировать]│
│ UI-10 проводник                                    ● в работе · agb · 2 ч│
│ ────────────────────────────────────────────────────────────────────────│
│  Обзор | Отчёты ●2 | История | Исполнение          (табы-ссылки ?tab=)  │
│  (тело задачи — Lora-свиток ≤72ch)                                       │
│  ПАМЯТЬ ЗАДАЧИ: [M-128 черновик UI-10] [M-215 heartbeat] → /memory/:id   │
└──────────────────────────────────────────────────────────────────────────┘
```

- **Шапка**: заголовок H1 · состояние-пилюля (`05` §2.4 + слово) · исполнитель
  («agb · laptop-go-1», unverified-чип по ADR 0009 §8 пока нет верификации) ·
  возраст. T-id — в tooltip заголовка и «деталях» (07a §1.4).
- **Быстрые действия**: [Назначить исполнителя] [Изменить] [Архивировать
  (confirm: «Задача уйдёт из канбана; история и отчёты сохранятся»)].
  **«Запросить отчёт» отклонено сознательно**: отчёт исполнитель пишет
  добровольно (контракт докладов, M-215) — кнопки, которая заставляет агента
  отчитаться, в контракте нет; фальшивая кнопка = блокер честности (`06` §5).
- **Табы** — ссылки (deep-link `?tab=`, `aria-current`, крошки не рвутся):

| Таб | Содержимое | Пустое состояние |
| --- | --- | --- |
| **Обзор** (дефолт) | тело задачи (Lora-свиток) + привязанные записи памяти чипами → `/memory/:id` | «Память о задаче ещё не разошлась — записи появятся, когда агенты начнут ссылаться» |
| **Отчёты** | лента отчётов: кто · когда · статус (промежуточный/финальный); непрочитанные выделены (золотая точка + «новый»); клик → свиток отчёта (Lora ≤72ch); **T-id в сносках — только здесь** (канон M-148) | «Отчётов пока нет — исполнитель отчитается после первого этапа» |
| **История** | переходы состояний: «в работе → блокировано · вчера 15:40 · agb (автоперенос из памяти)»; актёры: вы / агент / устройство `device:<id>` (атрибуция ADR 0012 §A.2) | «Задача создана — история начнётся с первого перехода» |
| **Исполнение** | assignment-очередь (7 состояний, §3.1 спеки агентов, словарь `07a`): бейдж-состояние + хост/агент + пульс («пульс 40 с назад»; >2 мин — warning) + честный возраст; T-127: «в очереди 12 мин — исполнитель молчит» | «Исполнителя нет — задача ждёт в канбане» + [Назначить исполнителя] |

- Действия «Исполнения»: **«Снять»** — confirm «Снять agb с задачи? Исполнителю
  уйдёт сигнал остановки» → toast «Отмена отправлена» (асинхронность честна);
  **«Переназначить»** — шторка выбора с префиллом. Создание поручений — только
  здесь (граница доменов, спеки агентов §2.4).
- Архивная задача — read-only: аффордансов правки нет, «Вернуть из архива» —
  со страницы архива (ME-005, прод-канон).

## 7. Флоу «Дать задачу» (3 шага, канон живых исходов `07b`)

Входы: кнопка в шапке домена · пустые состояния хостов (`07c` §3) · палитра
Ctrl+K («Дать задачу»). Индикатор шагов как в `07b` §1; пройденные сворачиваются
в резюме с [Изменить]; состояние шага — в URL (`?step=2`).

**Шаг 1 — Что.** Заголовок + описание (markdown-подсказка под полем: «**жирный**,
списки, `код` — агент увидит формат»). Чипы тегов с подсказкой существующих
(комбобокс словаря тегов; новый тег честно помечается «тег новый»).

**Шаг 2 — Кому.** Карточки исполнителей с жизненным циклом связи `07a` §4 —
каждая обещает честный момент старта:

| Lifecycle исполнителя | Что обещает карточка |
| --- | --- |
| на связи | «Задача начнётся после ближайшего доклада — обычно до 2 минут» |
| молчит | «Задача встанет в очередь — агент заберёт её при возвращении» |
| ждёт первого доклада | «Задача начнётся, когда агент выйдет на связь» |
| выключен владельцем | «Недоступен: новые задачи не получает. Выбрать другого» (disabled с пояснением) |

+ radio **«В очередь без исполнителя»** — задача ждёт в канбане, исполнителя
назначите позже (не стыдливый вариант, а равноправный путь).

**Шаг 3 — Проверка.** Сводка (что · кому · теги) + primary «Дать задачу» +
secondary **«Сохранить как черновик Входящих»** (не отправлять, отложить:
черновик появится во Входящих с источником «вы · черновик»).

**Исходы (канон `07b` §5):**
- Принято — зелёная итоговая карточка: «Задача у agb. Видна в канбане и в
  очереди исполнителя» + [Открыть задачу] [Ещё одну] [К канбану].
- Ошибка — красная: заголовок «Дать задачу не удалось» + что проверить («нет
  связи с исполнителем — проверьте хост», «сервер ответил ошибкой — повторите»)
  + [Повторить] [Сохранить черновиком].

**Пустое состояние домена:** «Задач нет — начните с „Дать задачу“ или загляните
во Входящие» + [Дать задачу] [Открыть Входящие].

## 8. Реестр пустых состояний (канон `07f` §3: почему + кнопка + куда ещё)

| Страница | Пустое | Кнопка | Куда ещё |
| --- | --- | --- | --- |
| Канбан (задач нет) | «Задач нет — начните с „Дать задачу“ или загляните во Входящие» | [Дать задачу] | [Открыть Входящие] |

| Входящие (пусто) | «агенты пока ничего не предложили» | [Обновить] | [Открыть Кору] |
| Архив (пусто) | «задачи попадают сюда из „готово“ или вручную» | [Открыть канбан] | — |

## 10. Motion (канон `06`)

- DnD: ghost следует за курсором без лагов; drop — `--ease-spring` (только тут).
- Новая карточка / автоперенос агентом: 240ms `--ease-enter`; удаление/уход —
  `--ease-exit`; reduced-motion — мгновенно.
- Золотая точка отчёта появляется импульсом write по краю карточки (≤240ms)
  **только на реальный SSE-событие отчёта**; reduced-motion — статический тинт
  1.5s. Никаких таймерных пульсаций.
- Bulk-тулбар и confirm-модалы: 240ms `--ease-enter`.

## 11. State-матрицы новых компонентов (блокер-канон `05`)

## 12. WCAG 2.2 AA — именованные критерии

- **1.4.3 Contrast (Minimum)**: все бейджи/пилюли — пары `02` §4; вторичный
  текст карточек ≥4.5:1 (worst-case elevated 4.8:1 — `text-muted`).
- **1.4.1 Use of Color**: состояние задачи — бейдж с текстом; непрочитанный
  отчёт — точка + tooltip-текст + счётчик; блокировано — бейдж + иконка.
- **2.4.7 Focus Visible / 2.4.11 Focus Not Obscured**: ринг `--color-focus`
  на карточках-целях; sticky-шапки не перекрывают ринг (offset 4px — `03` §8).
- **2.5.8 Target Size (Minimum)**: чипы, точки отчётов, крестики ≥24×24
  (мобильный 44px).
- **2.1.1 Keyboard**: DnD имеет полный клавиатурный путь (меню «Перенести в…»);
  bulk-действия доступны без мыши.
- **4.1.3 Status Messages**: bulk-тулбар — `role="toolbar"`, добавление строк
  в выделение — polite; исходы мутаций — toast (канал `05` §3).

## 13. Самокритика (проход 2)

- **Риск generic-канбана** («Trello-клон с тёмной темой»): снимается тремя
  вещами, которых у шаблонов нет — карточка это запись mnemos (confidence,
  провенанс, чипы памяти), канбан зеркалит state-машину памяти (автопереносы
  агентов всплывают сами), закрытие задачи — confirm с обещанием «агенты это
  увидят». Проверка «сними бренд»: опознаётся по «канбан как зеркало памяти
  с золотыми точками отчётов и честными confirm на терминальные состояния» —
  не сводится к Trello/Linear/GitHub Projects.
- **Риск перегруза карточки**: 6 элементов — потолок; исполнитель и возраст
  вторичной строкой; чипы ≤2 + «+N» (не «все теги влезут»).
- **5 колонок vs WF-1 прод**: мост записан в §0; иначе интеграция упрётся в
  расхождение словарей на ровном месте.
- **Черновики во Входящих** — риск смешать «агенты предложили» и «я отложил»:
  митигируется отдельной секцией с источником «вы · черновик» и миелин-разделом;
  если в проде черновики приживутся плохо — откат: черновики живут только в
  мастере (URL-состояние), Входящие остаются чисто агентскими.
- **«Запросить отчёт»**: отказ от кнопки — сознательный; если контракт когда-нибудь
  получит отчёт-запрос, он добавляется одним элементом шапки, спека не мешает.
