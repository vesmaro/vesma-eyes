- **КОРА — ОТПРАВКА РУЛЕНИЯ ЧЕРЕЗ РЕЛЕ В КОМПОЗЕРЕ (A1 FE-нога реле, feat/relay-fe-leg).** Композер Коры отправляет руление: живая кнопка по честному per-session сигналу реле (исполнитель ЭТОЙ сессии approved+enabled и несёт capability `session-relay` — деривация над уже загруженным реестром исполнителей, ноль новых запросов; борд паркует ход по исполнителю сессии, поэтому relay-capable строка чужого исполнителя кнопку не оживляет), честные статусы доставки из 202-ответа — queued / delivered / failed («повторите» = новый POST с сохранённым черновиком); отказы называются поимённо (step-up-ритуал, истёкшая сессия владельца, причина сервера дословно). Серверных изменений ноль — capabilities уже отдаются в main.

## [1.97.1] — 2026-10-30

### Fixed

- **КОРА-КАСКАД: SEAM-КОММИТЫ НЕСУТ ЗНАЧЕНИЕ, НЕ УСТАРЕВШЕЕ ЗАМЫКАНИЕ (каскадные фиксы, релизный поезд 1.97.1).** Коммит шва (resize-handle и родственные механики) передаёт актуальное значение на момент отпускания — раньше в замыкание мог попасть устаревший стейт и шов «прыгал» при persistence.

- **DEEP-LINK ВЕТВИ ДЕРЕВА ПРИ ПРЯМОМ ВХОДЕ ПО URL (каскадные фиксы, релизный поезд 1.97.1).** Ветка дерева сессий открывается и при прямом входе по ссылке: первый рендер — это изменение «с нуля» (react.dev canon, lazy init), раньше join срабатывал только на смену выделения после загрузки.

- **ШЕВРОН ЧЕСТНО НЕАКТИВЕН ВО ВРЕМЯ ПОИСКА (каскадные фиксы, релизный поезд 1.97.1).** Во время активного поиска тоггл-шеврон дерева не выглядит кликабельным — механика сворачивания в поиске не работает, и кнопка честно это показывает вместо мёртвого клика.

- **УНИКАЛЬНЫЕ DOM-ID ВЕТВЕЙ ДЕРЕВА — FNV-ДИДЖЕСТ (каскадные фиксы, релизный поезд 1.97.1).** listId ветки дерева несёт FNV-дайджест вместо конкатенации с коллизиями — класс регрессий с дублирующимися DOM-id закрыт.

- **CANON-ФИКСЫ REACT-HOOKS (каскадные фиксы, релизный поезд 1.97.1).** Оба setState-in-effect устранены по канону react.dev — дерево больше не пишет в стейт из эффекта напрямую.

- **ПОВТОРНАЯ ВЫДАЧА COOKIE ТОЛЬКО НА УСПЕШНЫЙ ОТВЕТ (каскадные фиксы, релизный поезд 1.97.1).** Обёртка reissue коммитит cookie только когда родительский ответ успешен — при ошибке старая cookie больше не затирается.

- **КАПЫ ТЕЛА ДО АВТОРИЗАЦИИ ДЛЯ STEERING-ЗАПРОСОВ И KORA-SCAN (каскадные фиксы, релизный поезд 1.97.1).** Pre-parse капы тела (CWE-400, defense-in-depth): steering-трио — 128 KiB, kora-scan ingest — 6 MiB; превышение даёт честный 413 до авторизации.

- **SECURITY-ЗАГОЛОВКИ НА 413 (каскадные фиксы, релизный поезд 1.97.1).** Ответы капа тела несут полный набор security-заголовков — раньше отказ 413 уходил без них.

- **ГИГАНТСКИЙ CONTENT-LENGTH → 413 ВМЕСТО 500 (каскадные фиксы, релизный поезд 1.97.1).** Нереалистичный Content-Length деградирует в честный 413, а не в 500 после попытки чтения тела.

- **ТЕСТ-ГВОЗДИ ОТКРЫТОГО СОСТОЯНИЯ ДЕРЕВА И POINTER-ПУТЕЙ (каскадные фиксы, релизный поезд 1.97.1).** Запинена механика открытого состояния дерева (ручное закрытие переживает rerender, stored seed бьёт live-default) и pointer-пути коммита шва (клампнутое значение на release, откат на cancel).

- **СТАБ ДЕПЛОЙ-ТЕСТОВ НЕЗАВИСИМ ОТ PYTHON3 В PATH (каскадные фиксы, релизный поезд 1.97.1).** FakeWorld helm-стаб пинится на sys.executable — деплой-гейты не зависят от того, какой python3 первым в PATH.

## [1.95.0] — 2026-10-28

### Added

- **МОДЕЛИ+MCP — DISCOVERY INGEST НА БОРДЕ (board-mirror wave, FC-6/FC-7, релизный поезд 1.95.0).** Агентные отчёты discoveries больше не молча теряются (`extra=ignore`): discovery-маршрут принимает и хранит аддитивные `models` и `mcp_servers`-ноги. Честные 422-капы на входе (shrink-to-fit семья): models ≤64 установок, ≤50 строк/установка, ≤16 KiB весь объект, provider ≤60 — 422 без значения; mcp_servers ≤32 записей, ≤30 имён, ≤8 KiB/запись. Аудиты: `models.reported` / `mcp.reported` / `discovery.rejected` (с ногой-маркером).
- **ДЕТЕКТОР УТЕЧКИ КРЕДЕНШЕЛОВ НА INGEST (security-verdict H4).** Credential-образная строка в любом поле models/mcp роняет СТРОКУ/ЗАПИСЬ (никогда не хранится) и пишет аудит `models.credential_leak_suspected` — payload несёт имя поля, длину и sha256[:12], никогда само значение; только на ingest-пути. Каскад SEC+QA поезда — accept-after-fix (фикс-слайс в поезде: board-side redaction base_url, content-delta comparator, value-free 422, pre-parse cap, coverage детектора).
- **РОСТЕР МОДЕЛЕЙ + SSE.** Roster-проекция моделей: `discovered[]` + `seen_on` (по одной записи на executor_id+harness+exec_env — ГДЕ факт виден) + provenance-agent; live-обновления ростера по SSE-событию `model.inventory.changed`.
- **СЛОВАРЬ — ЧЕТЫРЕ MODEL-SERVER ПОВЕРХНОСТИ (owner-approved 2026-10-28).** ollama / lmstudio / llama-server / vllm — сознательные члены словаря модельных серверов: сидятся с пометкой (seed пустой таблицы + один insert с board_meta-флагом для существующих БД, удаления владельца не воскрешаются).
