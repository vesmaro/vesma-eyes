## [Unreleased]

### Added

- **Диаграммы mermaid рендерятся на недоверенных поверхностях — отчёты агентов, память (ME-013, ADR 0020 Amendment 1; release 1.45.0).** Раньше mermaid жил только в доках (доверенный корпус); теперь untrusted-профиль text-engine тоже отрисовывает `mermaid`-фенс — под жёсткими капами: 10 000 символов на диаграмму, 5 диаграмм на поверхность; при превышении источник показывается честным код-блоком без svg. Кап-счётчик парсится тем же парсером, что и рендерер, и зеркалит его предикат языка фенса (закрытие обходов из security-аудита: container-nested фенсы, entity-encoded пробелы в инфо-строке — обход зафиксирован эмпирически). Библиотека грузится лениво: entry не изменился (mermaid-код — 0 байт; +0.2 KiB gz — тест-данные смоука, долг ME-024); бюджеты 5×ok — md-core 49.8 / md-sanitize 53.7 / mermaid 315.6 KiB gz, пулы не менялись. Verification: vitest 185 файлов / 1486 passed / 0 failed, typecheck + eslint чисто, browser smoke 21 pass / 0 fail / 0 skip (включая новые ассерты: svg на недоверенной поверхности и честный fallback при превышении капа), cascade review — security auditor verdict CLOSED (2 BLOCKED-раунда отработаны в волне), архитектурный аудитор закрыт в волне.

### Changed

- **Документация рендерится через один общий Markdown-движок; санитайзер вырезан из горячего пути (ME-019 Ф2, ADR 0020; release 1.44.0).** `Markdown.tsx` (DocsMarkdown) стал тонкой обёрткой над text-engine core: корпусный пайплайн вынесен в `TextEngine/core/pipeline.corpus.ts` за границу чанка md-sanitize, типографика статей — ветка article-темы в `TextEngine/core/theme.tsx` с инъецируемыми хуками. В `vite.config.ts` — сплит vendor-пулов md-core/md-sanitize (ADR 0020 Ф2): entry не тянет санитайзер (md-sanitize вне eager-набора), диалог поиска docs отвязан от sanitize-пула (чанк DocsSearch 22.0 → 2.7 KiB gz), reachability-гейты в `budget-docs-render.mjs` фиксируют отсутствие статического ребра md-core → md-sanitize. Бюджеты: md-core 49.8 KiB gz (≤90), md-sanitize 53.7 KiB gz (≤60), docs-mermaid 315.6 KiB gz (≤450). Провенанс-баннеры (`<!-- GENERATED by sync_docs ... -->`) срезаются при сборке манифеста и не попадают ни в отрисованный документ, ни в поисковый индекс (HTML-комментарии вычищены из индекса, review P2-1). Пользовательский контент не менялся — golden-фикстуры байт-в-байт. Verification: vitest 1465 passed / 0 failed, eslint clean, browser smoke 12 pass / 0 fail / 1 skip, cascade review verdict accept-after-fix (P1 = 0, все P2 закрыты и перепроверены TL личным перезапуском).

### Added

- **Кора (Kora) — срез 2 «что делалось» (ADR 0019 rev.2).** (а) Сканеры vscode и pi по образцу zcode-сканера: read-only ридеры `server/kora/vscode_reader.py` (chatSessions JSONL envelope v3: списки + превью; kind:1-патчи НЕ применяются — полный транскрипт vscode остаётся известным пробелом) и `server/kora/pi_reader.py` (самоописывающийся JSONL: первая запись = id+cwd, parentId-цепочка не трогается; не-сессионные соседи run-history/subagent-artifacts/context-mode пропускаются), one-shot сканеры `scripts/kora/scan_vscode.py` / `scan_pi.py` с общей обвязкой `scan_common.py` (тот же ingest-контракт, тот же exit-код-словарь), анти-write-тесты по семействам (скан оставляет сторы байт-в-байт). (б) Единственный transcript-serving путь: `GET /api/kora/sessions/{id}/transcript` — ui-only (TL-решение передачи срезa 2; валидный mnd_ получает объясняющую стену 403 `metadata_only` по замороженному контракту, аноним 401, машинный токен — не транскрипт-класс), реестр ревалидируется на каждом ответе, курсор `after_seq`/`limit` (≤200) по замороженным формам, каждый байт контента через redaction choke-point с честным `redaction_applied`, каждый успешный ответ пишет аудит `session.transcript_viewed` (device_class/network_path/session_host) в существующую аудиторию доски; ридер `read_zcode_transcript` в `server/kora/zcode_reader.py` — mode=ro + WAL-snapshot-fallback, роль из message.data, kind из part.data (text/reasoning/tool), seq по порядку стора и не перенумеровывается, капы загрузки с явным маркером обрезки; стор задаётся `VESMARO_KORA_ZCODE_DB` (по умолчанию локальный ~/.zcode — транскрипты удалённых хостов честно 404 до W4). Сессии vscode/pi отвечают 422 `validation` с объяснением (не фейковая пустая страница). (в) Load-more (P4-7 недели 0): additive `limit`/`offset` в `GET /api/kora/sessions` (замороженная форма ответа не тронута — has_more выводится клиентом из count == limit), `useKoraSessionPages` на TanStack useInfiniteQuery + кнопка «Показать ещё» на `/kora`; mock- и HTTP-адаптеры говорят одинаково. (г) Coverage-честность срезa 2: zcode → `full` (списки + read-only транскрипты), vscode/pi → `lists-only` с названными пробелами. Системный таймер сканера НЕ реализован — директива срезa 1 «one-shot, без systemd» держится; вариант вынесен на решение владельца отдельно. Verification: pytest 1190 passed / 4 skipped, vitest 1285 passed (162 файла), tsc clean, eslint 0 errors, prettier чист по изменённым файлам.

- **Кора (Kora) — неделя 0, контракт-first: замороженные API-шейпы срезов 1–3 + UI-моки раздела (ADR 0019 rev.2, ратифицирован владельцем 2026-09-24).** Ветвь `feat/kora-week0-contract` замораживает wire-контракт ДО появления серверного кода, по таблице Consequences ADR («Неделя 0 — контракт-first»: OpenAPI-шейпы срезов 1–3 + UI-моки, до кода). (а) Контракт-артефакт `docs/kora/openapi.yaml` — канонический источник истины для срезов 1–3: `GET /api/kora/sessions` (лист производного реестра: executor_id + native_id PK-пара, harness, state live/idle/dead, origin relay/local, steerable, age, preview-кламп ≤160 знаков + блок coverage «что вижу / чего нет»); `GET /api/kora/sessions/{id}/transcript` (единственный transcript-serving путь: seq-курсор `after_seq`/`limit`, каждая запись через redaction choke-point, mnd_-стена = 403 с объяснением, не голый статус); `POST /api/kora/sessions` (новая сессия с телефона — первый релейный сценарий, relay-origin по построению) и `POST /api/kora/sessions/{id}/messages` (промпт через реле: 202 accepted ≠ delivered, честная delivery-статистика «не доставлено — повторите», confirm-режим дефолт, чужой triple → 404 серверно); step-up PIN `POST/GET/DELETE /api/kora/steering/step-up` (TTL ≤ 900с, руление по умолчанию выключено, чтение — без step-up). Производный реестр закреплён расширениями `x-kora-registry` (PK `[executor_id, native_id]`, инвариант `UNIQUE executors.host`, без церемоний регистрации), единый redaction choke-point — `x-kora-redaction` (модуль `server/kora/redaction.py`; всё, что уходит в UI — превью и транскрипты — проходит только через него; аудит `session.transcript_viewed` с device_class/network_path/session_host), SSE-словарь `session.listed/updated/closed` — additive-only, metadata-only (`x-kora-events`; `session.updated` = сигнал chat v1: браузер тянет хвост стора тем же authenticated GET, второго буфера контента на борде нет), `x-kora-no-acp` — сетевого ACP нет, CI-трипвайр духа гейта. (б) Гейт `tests/test_kora_contract_spec.py` (23 теста): эндпоинты/operationId, замороженные enums (harness zcode/vscode/pi без hermes — known-gap до T004; state; origin; коды ошибок), кламп превью, coverage-блок, курсорные параметры, метадата-only структура событий, PK/UNIQUE-host семантика, TTL-кэп 900с, отсутствие ACP-поверхности. (в) UI-моки раздела «Кора» (`viewer/src/features/kora/`) — НИКАКОЙ интеграции с бекендом: сгенерированные из артефакта типы (`koraContract.d.ts`, `npm run codegen:kora` — openapi-typescript над замороженным YAML, committed + drift-guard), gateway-сейм `koraGateway.ts` с единственной реализацией недели 0 — `KoraMockAdapter` (моделирует store-tail семантику §3: send → in-memory стор → seq-курсор перечитывание; step-up PIN гейт; 404 для чужих сессий), экран среза 1 `/kora` (список сессий + экран покрытия «что вижу / чего нет» + онбординг-карточка 3 кейса + честная плашка «Неделя 0 · контракт-моки»), экран срезов 2–3 `/kora/:sessionId` (read-only транскрипт с плашкой «чужая сессия — только чтение» для не-steerable, чат-панель с PIN step-up и send → store-tail для steerable), снапшот-тесты обоих экранов + контракт-тесты фикстур против сгенерированных типов. Раздел жив в навигации сразу (ранний контакт с UI — решение rev.2 #1), маршруты `/kora` и `/kora/:sessionId` в `routes.tsx`, провайдер по конвенции `GatewayContext` (контекст в `.ts`, Provider на route seam). Никакого серверного кода: когда срезы приземлятся, FastAPI `/openapi.json` обязан совпасть с артефактом, а `KoraHttpAdapter` подменит мок одной строкой в одном месте.
