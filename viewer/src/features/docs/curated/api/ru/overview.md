# API экосистемы

Здесь живёт карта программных интерфейсов всех проектов экосистемы памяти:
борд vesma-eyes, сервер памяти vesma, резидентный агент vesmaro-agent и
транспорт vesma-mesh. Один раздел — один проект; внутри раздела — либо
сгенерированный референс, либо страница из репозитория проекта на точном
пине.

## Карта проектов

| Раздел | Что за API | Как получено |
|---|---|---|
| [API борда](api/vesma-eyes/index) | HTTP API самого борда: задачи, память, назначения, исполнители, автоматизация, устройства | генерация из OpenAPI-снапшота (`scripts/gen_api_ref.py`), RU v1 |
| [HTTP API vesma](api/mnemos/http-api) | поверхность сервера памяти: CRUD записей, поиск, конвейер, DLQ, трассировки; контракт A2A-сессий | карта-указатель + страница из репозитория vesma на пине |
| [vesmaro-agent](api/vesmaro-agent/protocol) | проводной протокол агента (регистрация, клеймы, отчёты, discovery) и выжимка service charter v2 | тело протокола из репозитория на пине + кураторская выжимка |
| [vesma-mesh](api/mnemos-mesh/index) | публичного HTTP API нет — внутренний протокол | честная заметка с проверкой по пину репозитория |

## Правило свежести

Страницы этого хаба **синхронизированы из источника**, а не написаны руками:

- референс API борда генерируется из `viewer/board-openapi-snapshot.json` —
  провенанс каждой страницы это блоб-SHA спеки и дата снимка (в frontmatter
  и на бейдже страницы); изменение спеки означает регенерацию, ручные
  правки тела исключены;
- страницы vesma и vesmaro-agent синхронизируются из их репозиториев по
  полным SHA-пинам (`scripts/sync-config.yaml`, секция `api_hub`);
- на каждой странице бейдж «из `<repo>`@`<sha>`, синхр. `<дата>`» — по нему
  видно, какой именно коммит источника перед вами.

Язык оригинала сохраняется: сгенерированный референс борда пока русскоязычный
(v1), протокол агента — на английском (с бейджем «на языке оригинала»),
остальное двуязычно.

## Чего здесь нет и почему

Cortex, canon, canon-data и vitals не вошли: исследовательские и внутренние
репозитории без публичного API-контракта — решения зафиксированы в
`sync-config.yaml` (`api_hub.excluded_repos`), включение возможно только по
директиве владельца.
