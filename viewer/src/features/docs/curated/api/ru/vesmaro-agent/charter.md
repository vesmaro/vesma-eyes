## Миссия

vesmaro-agent — **резидентный представитель борда vesma-eyes на хосте**:
инвентаризирует живущие на машине харнессы, исполняет назначения борда
через них, возвращает отчёты с атрибуцией и делает сессии/состояние
видимыми для владельца — всё это **без переконфигурации хоста** (модель
node-exporter: один бинарник, только собственный loopback-порт). Агент —
**не транспорт**: перемещение байтов между хостами это vesma-mesh
(MM-033, фаза C; mesh-нога ездит на пиннированной библиотеке mesh-core,
креды — через их invite/enroll-флоу).

## Never-list («НЕ делаем»)

1. **Не транспорт** — транспорт это vesma-mesh, своих протоколов и
   кред-флоу агент не изобретает.
2. **Не второй node-exporter** — без экспортёра метрик и scrape-поверхности.
3. **Не мини-ОС** — без супервизии чужих сервисов, управления пакетами,
   cron и сетевой конфигурации хоста.
4. **Не замена валидации борда** — борд остаётся гейтом своих вердиктов
   (на native-Canon edge агент — строгий валидатор по ADR 0021, это
   делегирование, не подмена).
5. **Никакого контента инструкций/сессий в payload'ах** — имена, счётчики,
   пути, хэши; два ограниченных исключения discovery v3 — потолок, не
   прецедент.
6. **Никакой саморасширяющейся власти** — discovery не расширяет словарь
   харнессов и не включает шаблоны без подтверждения владельца.
7. **Не egress-поверхность** — агент ходит только на настроенные борд/mesh
   эндпоинты; URL'ы из вывода детей не запрашиваются (нет SSRF-поверхности).
8. **Loopback-listener — не control plane** — только отчётные/intake
   маршруты; спавн-триггеров и проксирования нет.

## Принципы

- **Модель node-exporter**: один бинарник, ноль переконфигурации хоста,
  loopback-бинд `127.0.0.1` с портом от ядра; борд-нога остаётся
  outbound-only; публичный бинд — блокер релиза.
- **Минимум секретов**: секрет executor'а в памяти или 0600 env-файле;
  per-child capability-токены вместо общих кредов; mask-before-truncate.
- **Fail-closed старт и жизнь**: нет CA — нет соединения; непарсимый
  конфиг — отказ всему; честная деградация вместо тихих обходов.
- **Готовые решения**: systemd, journald, node-exporter, vesma-mesh —
  используются, не перестраиваются.

## Метрики успеха

- **M1** — инвентаризация discovery видна в UI (ME-021, live v3 payload).
- **M2** — у каждого ребёнка агента session-fact в карточке задачи
  ≤ 60 с после выхода ребёнка; транскрипт читается read-only (ME-020).
- **M3** — онбординг нового харнесса: со стороны агента ≤ 5 минут,
  end-to-end ≤ 15 минут с действиями владельца.
- **M4** — dead-letter < 10 %/день; `time_to_visible` p95 под трекингом;
  регрессия fail-closed = блокер релиза.
